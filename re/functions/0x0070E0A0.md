## Purpose

Runs one culling walk of one scene graph from one camera, and - only when no visible
array is in play - brackets that walk with the renderer's accumulator so the geometries the
walk registers are drawn by the accumulator's finish before this function returns.

In order (all read, asm.s):

1. SEH frame with the cookie `[0x00B30AAC] ^ ESP` (0x0070E0A0..0x0070E0BF).
2. Guard: camera (arg 1) and scene (arg 2) both non-null, otherwise return with no write
   (0x0070E0CF, 0x0070E0D9).
3. `this+0x0C = camera` (0x0070E0E6), then `0x0070E040(this; camera+0xEC)` (0x0070E0DF..E9):
   the frustum copy to this+0x10..+0x2B and the plane mask this+0x8C = 0x3F (read, 0x0070E040
   export, asm 0x0070E040..76); the six planes at this+0x2C are written by 0x00717A40 (called
   from 0x0070E040 with ECX = this+0x2C), whose instructions are not read here, so their extent
   (+0x2C..+0x8B) is derived from the gap to +0x8C, not read.
4. Visible-array swap: when arg 3 != 0, the old `this+0x08` is saved in a stack local and
   arg 3 stored in `this+0x08` (0x0070E0F2..0x0070E101).
5. Accumulator bracket open: when `this+0x08 == 0` (after step 4), a local `NiPointer` takes
   `[[0x00B3F928]+0x08]` through 0x0075FA90 (AddRef), and when that is non-null its vtable
   +0x4C is called with the camera (0x0070E108..0x0070E139).
6. The walk: `0x007073D0(this = scene; process)` (0x0070E13B..40).
7. Accumulator bracket close: when the local holds an accumulator, its vtable +0x50
   (0x0070E145..50) - this is the call whose return address 0x0070E152 the step probe
   counted.
8. Restore `this+0x08` when arg 3 != 0 (0x0070E152..5A); `this+0x0C = 0` always on this
   path (0x0070E15F).
9. Release the local `NiPointer` (InterlockedDecrement on +0x04, vtable +0x00 with 1 at
   zero) (0x0070E15D..0x0070E186); SEH frame unlinked, `RET 0xC` (0x0070E188..9B).

Subsystems touched, in order: culling process (camera, frustum, planes, mask, visible array),
the camera (frustum +0xEC, world transform +0x64 - both through 0x0070E040), the renderer
global (accumulator +0x08), the accumulator (refcount, +0x4C, +0x50), the scene graph walk
(0x007073D0 -> process vtable +0x04, which is 0x0070DFB0 for NiCullingProcess only ->
object vtable +0x7C; the chain past 0x0070E140 is unverified against this export). No clock
read or write in
this function's instructions (read: no data reference besides the four above); transitive
callees are not checked for the clock (unverified).

## Calling convention and parameters

`__thiscall`, `this` in ECX (copied to ESI at 0x0070E0C5), three stack arguments, callee
cleans with `RET 0xC` (0x0070E19B). Frame: nine pushes (0x24 bytes) before the first
argument read, so `[ESP+0x28]` = entry ESP+4 = arg 1.

Callee stack discipline this function relies on (derived): no `ADD ESP` follows the calls at
0x0070E124 (0x0075FA90) or 0x0070E139 (accumulator +0x4C), and both paths into 0x0070E13B
read the scene from the same `[ESP+0x2C]`, so both callees pop their one argument (callee
cleans). 0x007073D0 ends in `RET 4` per OBVR's quoted bytes (GameAddresses.h:1111-1116).

Returns nothing the callers use: EAX on exit is whatever the last call left (read: no EAX
write after 0x0070E17A on the release path); 0x0070C0B0 does not read EAX after the slot
call (re/functions/0x0070C0B0.md B5 path, read there).

Flows a rebuild test has to cover (derived from B1..B9):

1. camera null -> no write, no call (scene and array anything).
2. camera set, scene null -> no write, no call.
3. camera, scene set; visibleSet = A; this+0x08 anything -> planes built, this+0x08 = A during
   the walk, no renderer read, no accumulator call, this+0x08 restored to its entry value,
   this+0x0C = 0 at return.
4. camera, scene set; visibleSet = 0; this+0x08 = B != 0 -> planes, walk with B, no
   accumulator, this+0x08 stays B, this+0x0C = 0.
5. camera, scene set; visibleSet = 0; this+0x08 = 0; [renderer+0x08] = 0 -> planes, walk, no
   +0x4C/+0x50, this+0x0C = 0. (NiPointer assign with null: no AddRef.)
6. As 5 with [renderer+0x08] = C, C's refcount stays above zero -> AddRef(C), C->+0x4C(camera),
   walk, C->+0x50(), Release(C) without delete. Order: +0x4C before the walk, +0x50 after.
7. As 6 with C's refcount reaching zero at the release (the renderer dropped C during the
   walk) -> C->vtable[0](1) after +0x50.
8. Order check: this+0x0C is written before 0x0070E040 runs (0x0070E0E6 before 0x0070E0E9),
   because 0x0070E040 reads it and skips everything when it is 0 (0x0070E040 export 0x0070E043..48).
9. Precondition, not a flow: [0x00B3F928] is not null-checked (0x0070E116..1C); in flow 5..7
   a null renderer global faults.
