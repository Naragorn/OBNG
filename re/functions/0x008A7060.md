## Purpose

Base-class constructor of the 0x2C-byte object that 0x0088B070 allocates at
0x0088B0A4/0x0088B0BA (`PUSH 0x2C; CALL 0x00401F00`). It writes the base vtable 0x00A95C00
and fills all eleven dwords of the object with constants: a count of 1 at +0x0C, the
value 0x7FFFFFFF at +0x08 and zero everywhere else. It touches no global, no
thread-local slot, no clock, no heap and no Havok world. The caller then overwrites the
vtable with the derived one, 0x00A95C70 (0x0088B0DB).

## Control flow

Straight-line; no branches, no loops, no computed jumps (asm.s, data.json `jump_tables`

dwords holds the value in the table above and the return value equals `this`.

## Claims

- C1 (read, 0x008A7060-0x008A7090): the function has no branch, no call and no data
  access outside `[this+0x00..+0x2B]`; the `RET` at 0x008A7090 still reads the return
  address from `[ESP]`.
- C2 (read, 0x008A7064): it writes the base vtable 0x00A95C00; the caller replaces it with
  0x00A95C70 at 0x0088B0DB.
- C3 (read, 0x008A706A..0x008A7089): it writes all eleven dwords of the 0x2C-byte object;
  no byte of the object is left uninitialised by caller-plus-constructor.
- C4 (read): no clock is read or written; no global, TLS slot or the stack area 0x00B47900
  is touched.
- C5 (derived from 0x0088B0FF-0x0088B10E): +0x0C is a reference count starting at 1.
  The caller decrements `[ESI+0xC]` after 0x008BBA80 (0x0088B0FF `ADD [ESI+0xC],-1`;
  0x0088B103 `JNZ`) and, when it reaches zero, calls vtable slot +0x34 with argument 1.
  That slot of 0x00A95C70 is 0x00889450 (read, 0x0088B070's data.json entry 0x00A95CA4,
  bytes `50 94 88 00`).
- C5a (unverified, pseudocode only): 0x00889450 resets the vtable to 0x00A95C00 and frees
  the block through 0x00401F20 when bit 0 of its argument is set. Only rea-all
  0x889450.c (Ghidra pseudocode, a reading aid) shows this; no asm.s of 0x00889450 is in
  this slice's export. Settled by the disassembly of 0x00889450-0x0088946E (expected:
  `MOV [ECX],0x00A95C00`; `TEST byte [ESP+4],1`; `JZ`; `CALL 0x00401F20`; `RET 4`).
- C6 (derived, from rea-all 0x8a70f0.c pseudocode only): 0x008A70F0 increments +0x0C of
  its argument, releases the object previously in 0x00BA7D98 the same way (slot +0x34,
  argument 1) and stores the new one there. That this object type is the one stored in
  0x00BA7D98 is unverified.
- C7 (derived from C5): when 0x008BBA80 does not take its own reference to the object,
  the caller's release at 0x0088B10E destroys it; when it does, the object outlives
  0x0088B070. Which holds is unverified (answered by 0x008BBA80's map).
- C8 (derived from the base vtable bytes and C2): the base class at 0x00A95C00 is abstract
  in slots 0-5 (purecall); the derived class 0x00A95C70 supplies them.
- C9 (unverified): +0x08 = 0x7FFFFFFF is a "no limit" sentinel (a maximum size or
  threshold); only the value is read.
- C10 (unverified): the class is Havok's memory or thread-memory base (`hkMemory` per
  RTTI 0x00B2E33C). Not checked against the RTTI locator at 0x00A95BFC.
