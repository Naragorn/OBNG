## Purpose

Hands a camera's view to the renderer. `this` is the renderer at the hop's call site 0x0070C0DE (read: ECX = [0x00B3F928] loaded at 0x0070C0B0, OBVR kRendererPointer / xOBSE g_renderer); for the three other callers 0x0057F170, 0x0049A200, 0x0049BEF0, which are not in this export, `this = [0x00B3F928]` is unverified. The function copies the camera's world rotation (nine floats at camera+0x64..+0x84) onto the stack as three column vectors, and, when the renderer's state gate passes, calls the renderer's own virtual slot +0x140 (index 80) with six pointers: the camera's world translation (camera+0x88), the three columns (column 0, column 1, column 2 of the world rotation), the camera's frustum (camera+0xEC) and the camera+0x110 block (the viewport, proposed). Its own instructions write only stack memory: the FSTP locals at 0x00701985..0x007019C2 and the pushes (read). On the call path it hands control to the renderer's vtable +0x140 (CALL EAX 0x00701A04), whose writes to the renderer or camera are not covered by this export (unverified). The whole effect of the function is 'reads camera, then whatever slot 80 does'.

In the scene-draw hop (0x0070C0B0) the call at 0x0070C0DE precedes both slot +0x08 calls on EDI: 0x0070C0F8 (ESI != 0) and 0x0070C112 (ESI == 0, args 0, EBP, EBX), so the ordering holds on every path (read, hop asm.s). That EDI is the culling process and its slot +0x08 is NiCullingProcess::Process 0x0070E0A0 rests on OBVR's comment (GameAddresses.h at kCullingProcessProcess: "the renderer took its view before the cull (00701970 at 0070C0DE)"), not on this export (unverified).

- Arg 1 ([ESP+0x28] after SUB ESP,0x24, read at 0x00701973) = the camera (NiCamera*, proposed). At the hop it is the hop's first argument (EBX).

## Control flow

The nine float copies (0x00701977..0x007019C2) run unconditionally, before any branch. The flags tested at 0x007019C6 come from the CMP at 0x0070197F; the FLD/FSTP between do not write EFLAGS (derived from the x87 instruction set; no integer flag-setting instruction lies between 0x0070197F and 0x007019C6, read).

| # | at | condition | taken | not taken |
|---|---|---|---|---|
| B1 | 0x007019C6 JZ 0x007019D0 | dword [this+0x200] == 1 (CMP at 0x0070197F) | go to B3 | fall to B2 |
| B2 | 0x007019CE JNZ 0x00701A07 | dword [this+0x204] != 1 (CMP at 0x007019C8) | skip the call, return | fall to B3 |
| B3 | 0x007019D6 JNZ 0x00701A07 | byte [this+0x20C] != 1 (CMP at 0x007019D0) | skip the call, return | call slot 80 |

The call happens exactly when `([this+0x200] == 1 || [this+0x204] == 1) && (byte)[this+0x20C] == 1` (derived from B1..B3). Test flows for a rebuild:

1. +0x200 == 1, +0x20C == 1 -> slot 80 called (B1 taken, B3 not taken).
2. +0x200 == 1, +0x20C != 1 -> no call.
3. +0x200 != 1, +0x204 == 1, +0x20C == 1 -> slot 80 called.
4. +0x200 != 1, +0x204 == 1, +0x20C != 1 -> no call.
5. +0x200 != 1, +0x204 != 1 -> no call (+0x20C not read).
6. In flow 1, +0x204 is not read (short circuit, read: B1 jumps over 0x007019C8).
7. Every flow: the nine camera floats are read, RET 0x4.
8. Byte compare: only the low byte of +0x20C is compared (CMP byte at 0x007019D0), so e.g. 0x101 in the dword still passes.

## Claims

- C1 (read, 0x00701A0A): returns with `RET 0x4`; callee cleans its one stack argument.
- C2 (read at the hop's call site, 0x0070C0B0/0x0070C0DE in the hop's asm.s; derived for this function's slot call; unverified for the other callers): `this` (ECX) is the renderer [0x00B3F928] at the hop's call site; the body does not change ECX, so the slot-80 call runs on the same renderer. The callers 0x0057F170, 0x0049A200, 0x0049BEF0 are not in this export, so `this = [0x00B3F928]` there is unverified.
- C3 (read, 0x00701973): the only argument is read once from [ESP+0x28] (= the first stack argument after the 0x24-byte frame) into EAX; at the hop it is the hop's first argument (EBX), which OBVR and re/functions/0x0040C830.md (in progress) name the camera.
- C4 (read, 0x00701977..0x007019C2): nine floats camera+0x64..+0x84 are copied into nine stack locals with FLD/FSTP single precision, in the order +0x6C, +0x78, +0x84, +0x68, +0x74, +0x80, +0x64, +0x70, +0x7C.
- C5 (derived from C4 and the push/LEA offsets): the slot-80 arguments are (camera+0x88, column 0, column 1, column 2, camera+0xEC, camera+0x110), with column k = (m0k, m1k, m2k) of the 3x3 at +0x64 if that matrix is stored row-major (row-major storage unverified).
- C6 (derived from C4): the copy goes through the x87 stack (FLD m32 / FSTP m32). For ordinary values that is bit-exact. For a signalling NaN the FLD raises invalid and the stored value is the quieted NaN, so a rebuild that copies with memcpy differs from the original only on SNaN inputs (x87 semantics; the OBNG emulator's documented limit "FLD does not quiet an SNaN" means an emulator-based differential test would not see this difference).
- C7 (read for the own instructions; unverified for the callee): the function's own instructions write only stack memory, the FSTP locals at 0x00701985..0x007019C2 and the pushes; their camera and renderer accesses are reads or address computations. On the call path control passes to the renderer's vtable +0x140 (CALL EAX 0x00701A04), whose writes to the renderer or camera are not covered by this export (unverified).
- C8 (derived from B1..B3): slot 80 is called exactly when `([this+0x200]==1 || [this+0x204]==1) && byte[this+0x20C]==1`; otherwise the function only reads the camera and returns.
- C9 (derived from the six pushes at 0x007019E1..0x007019FD, no ESP fix-up after 0x00701A04, POP ESI at 0x00701A06): slot 80 cleans its six arguments (RET 0x18). The callee's body is not in this export - its RET is unverified.
- C10 (unverified): name `NiRenderer::SetCameraData` 0x00701970, alias `SetCameraViewProj`. OBVR's comment exists (../OBVR/src/game/GameAddresses.h:1291, "at 0057F3A0 it calls 0x00701970, the SetCameraViewProj OBGEv2 names"), and that is a different name from SetCameraData. xobse.csv and obvr.csv have no entry for 0x00701970.
