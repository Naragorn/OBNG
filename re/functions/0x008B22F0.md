# 0x008B22F0 - sort a ray-hit collector's hits by hit fraction

Slice: havok-thread-conditions. Map only; not rebuilt.

## Identity

- Address: 0x008B22F0 (body 0x008B22F0..0x008B2312, 35 bytes, meta.json)
- Seed name: "Under the cast wrapper (proposal: the world's ray cast entry)"
- Proposed name: `RayHitCollector::SortHitsByFraction` (proposal; the seed name is refuted, see Claims C1)
- Caller: 0x0088B850 (one call site, 0x0088B9F9). Callee: 0x008B21F0 (in-place quicksort, see below).

## Purpose

When the collector object in ECX holds more than one hit, it sorts its hit
array (pointer at +0x10, count at +0x14) in place by the float at +0x14 of
each 0x30-byte element, by calling the recursive quicksort 0x008B21F0 on the
index range [0, count-1]; the result is ascending when no fraction is NaN (see
C4). It is not a ray cast entry: it touches no world, body, phantom, broad
phase, global or thread-local slot, and it runs after the cast (0x008987E0, or
0x008BA1B0 when [ESI+0x70] is set). The caller then copies element 0 (the
nearest hit when no fraction is NaN) into its cast output.

## Calling convention and parameters

- `this` in ECX (read at 0x008B22F1 `MOV EAX,[ECX+0x14]` and 0x008B2303 `MOV EAX,[ECX+0x10]`; the caller loads ECX at 0x0088B9F7 `MOV ECX,EBX`). Thiscall-shaped. (read)
- No stack arguments: it ends with plain `RET` at 0x008B2312 (no `RET N`), and nothing above the return address is read. (read)
- Return value: none used. EAX holds count-1 or a pointer on exit; the caller does not read EAX after 0x0088B9F9 (next instruction 0x0088B9FE overwrites EBX from [EBX+0x10], EAX next written at 0x0088BA14). (read)
- `PUSH ECX` at 0x008B22F0 only reserves a 4-byte stack slot; `POP ECX` at 0x008B2311 restores it. (read)
- Callee 0x008B21F0 is cdecl with 4 dwords: (array, lo, hi, comparator); the caller cleans with `ADD ESP,0x10` at 0x008B230E. (read)

## Claims

- C1 It is not the world's ray cast entry. It runs after the cast (0x008987E0, or 0x008BA1B0 when [ESI+0x70] is set): 0x0088B850 reaches the sort call at 0x0088B9F9 on two paths. When [ESI+0x70] == 0 (0x0088B9AA `JZ 0x0088B9E4` taken) it calls 0x008987E0 (named `hkWorld::castRay` in this slice's meta.json of 0x0088B850) at 0x0088B9E8. When [ESI+0x70] != 0 it calls 0x008BA1B0 at 0x0088B9D2 on a stack object (ECX = ESP+0x38 at 0x0088B9C7), with the collector EBX passed as an argument (`PUSH EBX` at 0x0088B9BF), and joins via 0x0088B9E2 `JMP 0x0088B9ED`. Either way this function is then called at 0x0088B9F9 on the collector in EBX = [ESI+0x78]. - read (0x0088B996..0x0088B9F9)
- C2 It reads only this+0x10 and this+0x14 and writes only its own stack slot (0x008B22F7). - read (the 35-byte body)
- C3 Through its callee it writes only the hit array's elements: fields +0x00 (16 bytes), +0x10, +0x14, +0x20 of elements in [0, count-1] (writes at 0x008B2291, 0x008B2297, 0x008B229D, 0x008B22A3, 0x008B22A6, 0x008B22B0, 0x008B22B6, 0x008B22B9); these are the only non-stack writes. Its other writes are thread-private stack: [ESP+0x24] at 0x008B2216, [ESP+0x60] at 0x008B2281, and its own lo-argument slot [EBP+0xC] at 0x008B22E0 (`MOV [EBP+0xC],EDI`), which lies in the argument area pushed by its caller (0x008B22F0 or its own recursion). - read (0x008B21F0 body)
- C4 When no fraction is NaN, the sort order is ascending by the float at element +0x14, nearest hit first; the caller takes element 0 as the result (0x0088B9FE..0x0088BA17). With a NaN fraction the compare is unordered (`TEST AH,5` / `JP` at 0x008B223B and 0x008B225B), both scans stop, the order is not guaranteed ascending and element 0 need not be the minimum. - derived from C3, the compare loops in 0x008B21F0 and the caller's copy of element 0; whether a NaN fraction ever reaches the array is unverified (settled by the code that fills the array, Q3)
- C5 Element stride is 0x30 bytes. - read (`LEA x,[i+i*2]; SHL x,4` at 0x008B2220/0x008B2223 and `ADD/SUB ECX,0x30` at 0x008B223E/0x008B225E)
- C6 The sort is not stable and is not bit-for-bit order-defined for equal keys or NaN keys (a quicksort with Hoare-style partition). - derived from the callee's control flow; which of two equal-fraction hits ends at index 0 depends on input order
- C7 Five groups:
  - (a) the object it is called on (the collector): reads +0x10, +0x14 (read); writes nothing on the object header; rewrites the element memory its +0x10 points to through 0x008B21F0 (read, C3).
  - (b) other objects of the same kind: none touched. - read (no other base is addressed)
  - (c) Havok world, bodies, phantoms, broad phase, pending-operation queue: none read or written. - read (no access beyond the collector and its array). Whether the +0x20 field is a pointer to a world collidable is unverified; it is only copied, never dereferenced.
  - (d) globals, singletons, TLS slots: none. data_refs is empty in meta.json for both 0x008B22F0 and 0x008B21F0; no `FS:` access. - read
  - (e) heap and Havok's stack area 0x00B47900: no allocation, no reference to 0x00B47900. The hit array's storage (heap, inline buffer, or 0x00B47900) is not shown by this function. - read (no reference); storage location unverified
- C8 No clock read or write anywhere in this function or its callee. - read
- C9 Thread safety: this function is safe to run on several threads at once when each thread owns its own collector and hit array; it shares no state. - derived from C2, C3, C7(d)
