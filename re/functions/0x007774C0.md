# 0x007774C0 - the fixed-function (FVF) partition packer with conditional chip reallocation

Slice: packing-lifetime (map only, not rebuilt in this run). Evidence:
`re/export/packing-lifetime/0x007774C0/` (meta.json, asm.s, data.json,
pseudo.c). Marks: **read** (seen in the instructions, with the address),
**derived** (follows from read facts, named), **unverified** (not checked at
instruction level; this includes everything taken from the pseudocode of
other functions in `re/export/rea-all/functions/`).

Export completeness: meta.json's body is four ranges 0x007774C0..0x00777A3C
(1405 bytes in bytes.bin); asm.s carries 409 instructions ending with
`RET 0x18` at 0x00777A3A (read). The gaps 0x0077774A..0x0077774F,
0x00777838..0x0077783F and 0x0077789C..0x0077789F are alignment padding
skipped by the `JMP`s at 0x00777748, 0x00777836 and 0x0077789A (read).
data.json has five entries (cookie 0x00B30AAC, the float 1.0E-5 at
0x00A3C778, the format string 0x00A8A524, the double 255.0 at 0x00A3DDD8,
the LeaveCriticalSection import 0x00A28074) and no jump tables (read).

Frame convention used below: offsets `[ESP+x]` are given in the **final
frame** (after `SUB ESP,0x168` and the four pushes EBX, EBP, ESI, EDI, i.e.
the frame used from 0x00777517 on). In that frame the arguments are arg1
+0x17C, arg2 +0x180, arg3 +0x184, arg4 +0x188, arg5 +0x18C, arg6 +0x190,
the cookie +0x174 (derived from the instruction offsets at
0x007774D4..0x007774EC, where loads happen after 0, 1 and 3 pushes).

## Purpose

Packs one skin partition's vertices into stream 0 of the partition's
record as an FVF vertex buffer. In order (all read, addresses in Control
flow):

1. Reads the geometry's source arrays (positions +0x1C, normals +0x20,
   colors +0x24, texture-set count +0x2C) and clamps the set count to 8.
2. Calls 0x00776DD0 to compute the FVF code, the vertex stride and the
   byte offset of each component (seven out-pointers).
3. Calls 0x007780A0 on the record with the FVF, then writes the stride to
   `record+0x20[0]` when the record has at least one stream.
4. Chooses the destination:
   - **caller-locked**: arg6 != 0 - packs straight into arg6, no lock, no
     unlock;
   - **reuse** (only when arg6 == 0): the passed chip (arg5) has a buffer whose GetDesc reports
     Format 100, the same FVF and a Size of at least `count * stride`, and
     the geometry's word +0x2E nibble is not 0x8000 - locks the chip;
   - **reallocate** (only when arg6 == 0): otherwise - 0x00776C40(record, 0), chip =
     `record+0x24[0]`, dirty mask forced to 0xFFF, then locks the chip.
   The lock is 0x00776C90 on the manager (ECX) with the chip's own
   `(vb [+0x08], offset [+0x0C], size [+0x14], flags [+0x10])`.
5. Under the dirty mask (arg4) fills the components through the partition's
   vertex map: bit 1 positions and (inside the same block) blend weights
   with an "ILLEGAL WEIGHTS" sum check, bit 2 normals, bit 4 colors packed
   to 32-bit ARGB, bit 8 texture coordinates.
6. When it locked, runs an inlined copy of the manager's Unlock 0x00776D80:
   staging -> mapped memcpy, clears the manager's lock state, leaves the
   critical section, calls the vb's vt+0x30.
7. Returns the chip it packed into, or 0.

The function's own body does not reference the frame clock or any timer:
its only global data references are the five data.json entries (read),
none of them a clock. The callees 0x00776DD0, 0x007780A0, 0x00776C40 (with
the owner vtable slots behind it), 0x007282F0 and 0x006C5D40 were not
examined for clock access (**unverified**; settled by reading their
bodies' data references) - see C13.

## Claims

C1. **read** - The chip's buffer, offset, size and flags are only **read**
here (0x007775C0, 0x0077764E..0x00777657) and passed unchanged to the lock
0x00776C90 as `(vb, offset, size, flags)` (pushed ECX=flags, EDX=size,
ESI=offset, EAX=vb at 0x0077765A..0x00777661). No instruction of this
function writes `chip+0x08..+0x14` (derived: every store in asm.s targets
the stack, the destination buffer, `record+0x20[0]`, or `this+0x48/+0x4C/
+0xF8/+0xFC`). So the range and the lock flags of a chip are not
assigned in this function (**read**, by the absence above). Which function
writes `chip+0x0C..+0x14` is not shown in this export and stays
**unverified** until 0x00776C40 and the owner's vt+0x18 are read at
instruction level (the pseudocode of 0x00776C40 and
re/functions/0x0076FE20.md, in progress, point at the owner's slot +0x18,
also unverified). This function locks the chip's **own** range; it does not
pick a ring slice per lock and does not choose lock flags.

C2. **read** - A geometry whose word +0x2E has `& 0xF000 == 0x8000`
always takes the reallocation path when arg6 == 0 (B6, 0x007775D5 jumps to
0x0077760F, before GetDesc). **derived** (C2 + B10/B11): on the lock path
every call for such a geometry runs `0x00776C40(record, 0)` and then reads
`record+0x24[0]` afresh. Per the pseudocode of 0x00776C40 (**unverified**)
that call is `owner->vt[+0x1C](record, 0)` (release) followed by
`owner->vt[+0x18](record, 0)` (allocate) and stores a non-zero result into
`record+0x24[0]`. Whether the owner hands back a new range, a pooled chip
or the same chip every time is **unverified** - this is the question for
the owner's slot bodies or a runtime compare of `record+0x24[0]` and
`chip+0x0C` across frames.

C3. **read** - For other nibbles the passed chip is reused only when its
buffer exists, `desc.Format == 100`, `desc.FVF == fvf` and `desc.Size >=
vertexCount * stride` (B5, B7..B9). **derived** (B3..B9): with arg6 == 0,
a non-0x8000 stream is released and reallocated only when the chip is
missing, its buffer is missing, `desc.Format != 100` (0x007775E9), the FVF
changed, or the vertex data grew past the buffer's size - not on a dirty
mask alone. With arg6 != 0 every check and reallocation is skipped and the
caller's destination is filled without an unlock (0x0077759A..0x007775B3,
C12). All these "only when" conditions also assume that GetDesc (vt+0x34,
0x007775E2) succeeds: its HRESULT is never tested (**read**), so on failure
the comparisons read uninitialised stack at final +0x5C..+0x73
(**derived**). When it is reused, the dirty mask from the
caller selects the components written (C7).

C4. **read** - After a reallocation the dirty mask is forced to 0xFFF
(0x00777643), so every component group is written (positions + weights,
normals, colors, texcoords, as far as their sources exist).

C5. **read** - Per-stream state written here: `record+0x20[0] = stride`
when `record+0x1C != 0` (0x0077758B..0x00777598, every call, before the
destination choice); 0x007780A0 is called with ECX = record and the FVF
(0x00777580..0x00777586, every call). **unverified** (pseudocode of
0x007780A0): it stores the FVF to `record+0x08` and, when `record+0x0C` is
non-null, calls its vt+0x08 (Release on a COM object) and clears it.
**derived**: only stream 0 is touched (index 0 at 0x00777613,
`[[EDI+0x20]]` and `[[EDI+0x24]]` without an index). The 0x28-byte
descriptors mentioned in the slice questions are not accessed by this
function (derived: no other record or descriptor offset appears in
asm.s).

C6. **read** - The lock result (0x00777667) is not null-tested before it
is used as the destination base (0x0077766F..0x00777677). **derived** (with
0x00776C90 returning 0 on a negative Lock HRESULT, this slice, 0x00776CC4):
a failed D3D Lock on the reuse or reallocation path makes the fill write
near address 0 only when at least one dirty-mask bit whose source array is
non-null is set (B12..B29). Otherwise nothing faults, and the inlined
unlock runs unbalanced, because needUnlock = 1 was set at 0x0077759F: it
decrements lockDepth `[this+0xFC]` that was never incremented (0x007779FE),
calls LeaveCriticalSection without a matching Enter (0x00777A08; 0x00776C90
enters the critical section only after a successful Lock,
0x00776CC0..0x00776CD3), and calls `vb->Unlock` (vt+0x30) on an unlocked
buffer (0x00777A14). B11: with `record+0x1C == 0` after a successful
0x00776C40, chip = 0 (0x00777637) and 0x0077764E dereferences `[0+0x10]`.
Whether either is reachable is **unverified** (0x00763130 calls this
function only when streamCount == 1, re/functions/0x00763130.md C18, in
progress).

C7. **derived** (C1 + 0x00776C90's `TEST EBP,0x3000` at 0x00776D0E in this
slice + the mask gates B13/B23/B26/B28) - The fill writes into the
manager's shared staging block, and the unlock copies `[this+0x4C]` (= the
chip's whole size) staging bytes to the mapped buffer (0x007779D5..0x007779E8).
When the chip's flags have neither 0x1000 nor 0x2000, the lock reads the
mapped bytes back into staging first, so the components a partial mask
skips keep their buffer contents. When the flags do carry 0x1000 or 0x2000
and the mask is partial (reuse path), the skipped components receive
whatever the staging block held from an earlier lock of **any** chip
through the same manager, or uninitialised FormHeap memory when the staging
block was just regrown because capacity `[this+0x44]` < size
(0x00776CEA..0x00776D0B in 0x00776C90; re/functions/0x00776C90.md C8 states
the same). Which flags the chips carry in play is **unverified**.

C8. **read** - Blend weights are written only inside the positions block
(B12/B13 jump past both to 0x0077780F). For each vertex the function sums
`1 - w0 - ... - w(n-1)` over `n = partition[+0x20]` floats (0x007776F0..
0x00777761), and when `|residual| > 1.0E-5` (constant 0x00A3C778, f32
1.0E-5 in data.json) formats "ILLEGAL WEIGHTS! Vertex %4d - Weight Sum
%8.5f  (%8.5f)\n" with `(vertexIndex, 1 - residual, residual)` via
0x006C5D40 into a 256-byte stack buffer at final +0x74 (0x00777780..
0x007777AA). **derived**: the buffer is never read afterwards (no
reference to final +0x74 elsewhere), so the message is formatted and
discarded - pure cost per bad vertex. Weights copied per vertex:
`max(n - 1, 0)` (0x007777C0..0x007777CE; the signed `JLE` at 0x007777B8
skips the copy for n = 0) plus one more when `n` is 3 or 1 (B20). **derived**:
n=1 -> 1, n=2 -> 1, n=3 -> 3, n=4 -> 3, n>=5 -> n-1 floats; with n=0 the
residual is 1.0, the message is formatted for every vertex and nothing is
copied.

C9. **read** - Colors: each float channel is multiplied by the double
255.0 (0x00A3DDD8, f64 255.0 in data.json), rounded to float
(`FSTP float`), then converted with `FISTP dword` (current x87 rounding
mode) and packed as `(a << 24) | (r << 16) | (g << 8) | b` with a from
+0x0C, r from +0x00, g from +0x04, b from +0x08 (0x007778A4..0x0077793C).
There is no clamp. **derived** (from the shift/OR packing
0x0077792F..0x0077793C): spill is upward only. A b, g or r value above 255
carries into the next higher channel; alpha's excess bits are shifted out
(wrap mod 256). A negative channel sets every higher bit through two's
complement and overwrites all higher channels, not just one neighbour. A
product outside int32 or NaN gives 0x80000000 (FISTP integer indefinite).

C10. **read** - Texture coordinates: for set j < min(textureSetCount, 8)
(B1) the source is `0x007282F0(j)` on ECX = geometry (0x00777980..
0x00777985) and 8 bytes per vertex are copied to `texOffset + j*8`
(0x0077798C..0x007779B9). The returned pointer is not null-tested.
**unverified** (pseudocode of 0x007282F0): it returns 0 when
`geometry+0x28` is null or `j >= textureSetCount`, else
`geometry+0x28 + geometry[+0x08](u16) * j * 8`. **unverified** (pseudocode
of 0x00776DD0): the stride reserves `max(textureSetCount clamped to
DAT_00B28CB0, 1)` sets; data.json has no entry for 0x00B28CB0, so whether
the clamp to 8 here and that clamp agree is unverified, and with
textureSetCount = 0 the reserved set is not written here.

C11. **read** - The tail is an inlined copy of the manager's Unlock
0x00776D80 (compare 0x007779D1..0x00777A14 with 0x00776D80..0x00776DC0 in
this slice's export: same memcpy argument order, same clears of +0x48/+0x4C,
same depth decrement at `[this+0x80+0x7C]` and owner clear at
`[this+0x80+0x78]`, same LeaveCriticalSection import, same vt+0x30 call).
Three things differ: the vb is taken from `chip+0x08` (0x007779DF) instead
of a stack argument; a success returns the chip pointer (0x00777A1E)
instead of AL=1; and a failure jumps to the common return-0 path
(0x00777A18 -> 0x0077761F) instead of SETGE.

C12. **read** - On the caller-locked path (arg6 != 0) there is no GetDesc
check, no reallocation, no lock and no unlock, the mask is the caller's,
and the return value is arg5 unchanged (0x007775A6..0x007775B3,
0x00777A1E). The FVF/stride writes to the record (C5) still happen.

C13. **read** - No clock: the data references are the cookie, two
constants, a string and an import (meta.json `data_refs`, data.json); no
direct reference of the body is a timer. **derived**: the body itself
neither reads nor writes the frame clock. Clock access in the callees
0x00776DD0, 0x007780A0, 0x00776C40 (with the owner vtable slots behind it),
0x007282F0 and 0x006C5D40 is **unverified** - settled by reading those
bodies' data references.

C14. **read** - Pseudocode disagreements (instructions win): pseudo.c
declares `void` but EAX carries the chip or 0 (C19 of 0x00763130.md, in
progress, and 0x00777A1E/0x0077761F here); it drops ECX (`local_138` is
used uninitialised, it is the manager); it shows `FUN_007780a0()` and
`FUN_007282f0()` without their ECX and stack arguments (0x00777583,
0x00777984); it shows the GetDesc call without the `&desc` argument
(0x007775D9..0x007775DE).

## Open questions

1. What the owner `[record+0x04]` is and what its slots +0x18 (allocate)
   and +0x1C (release) do: new range from the ring manager 0x007829A0, a
   pooled chip, or the same chip back. This decides whether a 0x8000
   stream keeps its buffer range across frames (C2) - the core question
   for a cross-frame pack cache.
2. Which lock flags `chip+0x10` carries for 0x8000 and for other streams
   (set by the allocation, C1); with 0x1000/0x2000 and a partial mask the
   skipped components are stale staging bytes (C7).
3. What `record+0x0C` is (released by 0x007780A0 on every call, C5) and
   whether the fixed-function path recreating it each call costs a
   declaration rebuild per draw.
4. The value of DAT_00B28CB0 (texture-set clamp in 0x00776DD0, C10).
5. Whether the second caller 0x00769030 passes arg6 != 0 (the
   caller-locked path) and with which mask.
6. Whether C6's null dereferences are reachable in play.

Callees worth their own slice (smallest first): 0x007780A0 (36 bytes,
record FVF set + release), 0x007282F0 (48 bytes, texcoord set getter),
0x00776C40 (67 bytes, ReallocateChip), 0x00776DD0 (180 bytes, FVF /
stride / offset layout - a pure function over two structs, the best
rebuild candidate here), and the owner's slots +0x18/+0x1C (the actual
range assignment; reached only through the vtable, so they need the
owner's class first).
