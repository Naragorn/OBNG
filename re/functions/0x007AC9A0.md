## Purpose

Draws one render pass of the shader accumulator. The accumulator keeps one list per pass
id at `this + 0x104 + 0x14 * passId` (the same lists 0x007AD270 appends to with
`this + (passId + 0xD) * 0x14`, C5); this function, given a pass id:

1. returns at once when that pass's list is empty (count at list+0x10);
2. looks at the shader of the first item's geometry (`geometry+0xBC`) and, when its
   type (shader slot +0x1C) is 1..5, begins the pass's shader state through 0x007D1320
   and two sub-object slot +0x48 calls (and the same two on the shader at
   `[0x007B4290(1)+4]` when it is a different object); when the type is 0x1B, the
   same through 0x007FD260;
3. when the byte 0x00B2BB7C is set and the pass id is one of five fixed id sets, sorts
   the list by geometry data with 0x007AA550 and the comparator 0x007AA390 and hands
   the whole list to one of five batch renderers on the object at `this+0x2264`, then
   returns (C9, C10);
4. otherwise walks the list: for every item - unless 0x00B42E97 is set and the item's
   geometry is on the exclusion list at `this+0x21F0` - either appends the geometry to
   the list at `this+0x2200` (pass ids 0x156..0x158, 0x160..0x162) or, after an
   optional append to the list at `this+0x2214`, draws it through 0x007A9820(item,
   pass), and counts it in two global statistics (0x00B42CBC += 1, 0x00B42CB4 += the
   16-bit result of the geometry data's slot +0x5C);
5. after the first item it ends the shader state begun in step 2 (0x007D1800 for types
   1..5, the empty stub 0x0060D0A0 for 0x1B), then draws the rest;
6. unless 0x00B42CDA is set, retires the list: 0x007A9C30 on it, then its nodes become
   its free-node chain (+0x0C) and head, tail and count are cleared.

The per-geometry engine step is 0x007A9820 (pass id and item into globals, per-light
setup, the geometry's render slot +0x84). On the fixed Walkers scene that call carries
90.0 % of the samples on which this function is running or on the stack (4468 of 4963;
94.8 % of the 4713 samples under a callee) (C14).

Subsystems touched, in order: the shader cache 0x007B4290 (once), the first geometry's
shader (virtual), the per-pass shader-state begin (0x007D1320 / 0x007FD260), the
batch path (0x007AA550 + the `this+0x2264` renderers) or the item walk (exclusion
list, 0x007ABDE0 list appends, 0x007A9820 per item, two statistics globals, one virtual
call on the geometry data per item), the state end (0x007D1800 / 0x0060D0A0), the list
retire (0x007A9C30). No frame-clock read or write in this body (C16).

## Calling convention and parameters

- `__thiscall`: ECX = `this` (the accumulator), saved to [ESP+0x10] at 0x007AC9B2 and
  reloaded from there (0x007AC9DE, 0x007ACC44, 0x007ACD66, 0x007ACE2F ...) (read).
- Two stack arguments, callee cleans: `RET 0x8` on all six exits (0x007ACC70,
  0x007ACCB2, 0x007ACCE4, 0x007ACD16, 0x007ACD48, 0x007ACF32) (read).
  - arg1 = pass id, a dword: loaded to EDI at 0x007AC9AE ([ESP+0x20] after `SUB ESP,0xC`
    and four pushes). Its low 16 bits (`MOVZX ESI,DI` at 0x007AC9B6, before the remap)
    index the list; EDI, after the remap of B1-B3, is what every comparison uses (read).
    Only the pass-taking callees receive it: 0x007D1320, 0x007FD260, 0x007A9820,
    0x007D1800, 0x0060D0A0 and the batch renderers A-C; batch D / E push the immediates
    0xE / 0x17B (equal to EDI on those paths); 0x007B4290, 0x007AA550, 0x007ABDE0 and
    0x007A9C30 do not receive it (read). Its stack slot is reused at 0x007AC9E8 for the
    16-bit index.
  - arg2 = a dword forwarded unchanged as the second argument of 0x007D1320
    (0x007ACA41) and 0x007FD260 (0x007ACA88); its stack slot is reused from 0x007ACD60
    as the "next node" iterator (read). The only caller found, 0x007AE070, passes 0 for
    pass ids 4..0x197 (EBX = 0 from `XOR EBX,EBX` at 0x007AE099 / 0x007AE645, pushed at
    0x007AE0E9 / 0x007AE66A) and 1 for pass ids 0x198..0x19F (`MOV EBP,1` 0x007AEA5D,
    `PUSH EBP` / `PUSH EDI` 0x007AEA67 / 0x007AEA68, call 0x007AEA6B), read (objdump).
    So it is a state or mode value handed to the shader-state begin, not a constant 0
    (derived from these call sites); its meaning is unverified.
- Locals: [ESP+0x14] = the first shader when its type is 1..5 (written 0x007ACA47),
  [ESP+0x18] = the first shader when its type is 0x1B (written 0x007ACA8E), both
  zeroed at 0x007ACA17/0x007ACA1B (read).
- Callee conventions seen at the call sites (read): 0x007B4290, 0x007D1320,
  0x007FD260, 0x007D1800, 0x0060D0A0 are cdecl (caller `ADD ESP` after them);
  0x007AA550 (ECX = list, one pushed function pointer), 0x007ABDE0 (ECX = list, one
  pushed pointer), 0x007A9820 (ECX = this, (item, pass)), 0x007A9C30 (ECX = list) and
  the five batch renderers (ECX = `[this+0x2264]`, (list, pass)) are called without a
  caller cleanup - callee-cleaned (thiscall-shaped; for 0x007ABDE0 `RET 0x4` read
  (objdump) at 0x007ABE1F, for 0x007A9820 `RET 0x8` read in its export).
- Returns nothing used: no caller reads EAX after the slot call (0x007AE670 `ADD EDI,1`,
  read (objdump)).

- pseudo.c's `iVar4 + 4` after 0x007B4290 (the `ADD EAX,4` at 0x007AC9E2) is dead in the

- 0x007ABDE0 is called with the item pointer itself (`PUSH ESI` 0x007ACDAB, `PUSH EBP`
