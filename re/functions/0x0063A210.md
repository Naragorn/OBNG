## Purpose

Once a frame for a high-process actor, this function runs the actor's current
AI package: it counts down a set of the process's own timers by the frame
time, handles early "the package must change" cases (the actor is dead
or unconscious, a dialogue menu closed, a combat or alarm state), lets the
process re-evaluate its package (process slot +0x18), and then dispatches
the package's current **procedure**: it looks up a procedure id in the table
`0x00B152B0[package type][procedure index]` and switches over it (45 cases,
ids 0..0x2C, jump table 0x0063B978). Most cases call one process vtable
slot (+0x508..+0x58C, the procedure handlers) or a free function
(0x006384B0, 0x0062A0E0, 0x00654F10, 0x00628330, 0x0062B5C0, 0x00633DF0,
0x00630100). Case 0x0D handles the package's target (distance tests
against settings, then "stop moving" through 0x005E05F0(0x30)); case 0x2C
is "procedure done": it fires the script event, writes the "%s is done with
%s" debug line for the selected reference, and when the package has no
next step clears the process's package state and frees its lists. At the
end it calls the attack update `kAttackUpdate` 0x005FCAB0(1.0, 1.0) on the
actor, hands the actor to the background pathing object [0x00B3BF80] when
`bUseBackgroundPathing` [0x00B15800] is set, and calls the actor's process
slot +0x20. (**derived** from the claims below; the procedure meaning of
each id is **unverified**.)

Subsystems touched, in order: the process's timers (frame seconds) -> combat
style/pathing helpers (0x005EB400, 0x00635E20, 0x0063A020, 0x00693210) ->
the actor's life state (0x005E0DC0) -> dialogue menu (0x00589B70(0x3F1)) ->
the package's location test (0x005E06C0) and its timers -> the actor's
movement (0x00603320) -> the mount-like object behind actor slot +0x380 ->
game time (g_TimeGlobals 0x00B332E0) and the script event list (0x004FBF90)
-> package re-evaluation (process +0x18, +0x3C0) -> process state machine
(process +0x36C) -> the procedure switch -> attack update -> background
pathing -> process slot +0x20.

## Calling convention and parameters

- `__thiscall`: ECX = this (the HighProcess), moved to ESI at 0x0063A22F
  (**read**). One stack argument, the actor, loaded at 0x0063A225 from
  `[ESP+0x15C]` = the first argument after `SUB ESP,0x154` and `PUSH EBX`
  (**read**), kept in EBX and in the local `[ESP+0x1C]` (0x0063A231), and
  as the actor in EDI after 0x0063A2E3 (**read**).
- Callee cleans: `RET 0x4` at 0x0063ADC8 (**read**), the only return.
- /GS frame: cookie `[0x00B30AAC] ^ ESP` stored at `[ESP+0x150]`
  (0x0063A216-0x0063A21D), checked by `__security_check_cookie` 0x009811E2
  at 0x0063ADBD (**read**). 0x154 bytes of locals including a 300-byte
  sprintf buffer (pseudo `auStack_130`; at `[ESP+0x34]` after the pushes,
  0x0063B707) (**read**).
- Saved registers: EBX, ESI always (0x0063A224, 0x0063A22E); EDI and EBP
  only after the entry gates pass (0x0063A2D8, 0x0063A2F9). The early gates
  jump to 0x0063ADB2 (pops ESI/EBX only); later exits go to 0x0063ADB0
  (pops EBP/EDI first) (**read**). Pseudo merges the two labels.
- Returns nothing (EAX is not set before the exit; the callee's value in
  EAX is whatever the last call left) (**read**: 0x0063ADB0-0x0063ADC8).
- Caller condition (**read** in 0x00605770's asm.s, 0x006059DC-0x00605A09):
  slot 4 is called when the caller's float at `[ESP+0x4C]` compares equal
  to 0.0 (`FUCOM`, `TEST AH,0x44`, `JNP`) or when the actor is the player
  [0x00B333C4]; otherwise slot 3 (+0x0C) is called with (actor, float).
