## Purpose

Loads a culling process's frustum state for one camera: copies the 28-byte
frustum the caller hands in to `this+0x10`, builds the six world-space culling
planes at `this+0x2C` from that copy and the camera's world transform
(`[this+0x0C]+0x64`) through 0x00717A40, and arms all six planes
(`this+0x8C = 0x3F`). With no camera at `this+0x0C` it does nothing. These are
the planes and the mask the cull walk `NiCullingProcess::Cull` 0x0070DFB0 tests
every object's bound against (knowledge/culling-and-draw-setup.md).

Subsystems touched, in order: the culling process's own fields only (camera
pointer read, frustum copy written), then the math helper 0x00717A40 (which
calls the plane constructor 0x00716E00 and the CRT square root 0x00982C30),
then the process's mask. No renderer, device, accumulator or clock access.

## Calling convention and parameters

`__thiscall`, one stack argument, callee cleans: `RET 0x4` at 0x0070E076 (read).
No return value (C16). What EAX holds on return is a by-product, read:

- F2 (camera present): EAX is set to `this+0x10` at 0x0070E050 and pushed at
  0x0070E060, but the `CALL 0x00717A40` at 0x0070E064 overwrites it, and
  0x0070E069..0x0070E076 never write EAX again. 0x00717A40 ends with
  0x007181E8 `MOV EAX,[EAX+0xC]` (EAX = the plane 0x00716E00 just built,
  0x00716E00 returns `this` via 0x00716E00 `MOV EAX,ECX`), 0x007181EC
  `MOV [ESI+0x5C],EAX`, 0x007181F3 `RET 0x8`. So EAX is the constant of plane
  5, the same dword stored at process+0x88 (read (objdump)). It is **not**
  `this+0x10`; an earlier version of this file said so and was wrong.
- F1 (no camera): EAX is not written; it is the caller's EAX (read: no EAX
  write between 0x0070E040 and 0x0070E076 on the JZ path).
