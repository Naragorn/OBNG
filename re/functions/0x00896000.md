## Purpose

Advances one actor's character controller by one time step taken from a caller-owned movement-input record
(`param`): decides whether the actor counts as still, splits the step into at most two substeps, turns the
displacement asked for into a Havok velocity, rotates the controller's attached body, and per substep runs the
support probes 0x00891780, the proxy's support check 0x008AE890, the current character state's update (vtable
+0x18) and - unless the still-actor shortcut skips it - the integrate wrapper 0x008902B0 under the iteration cap
`[0x00B2EFB8]`. After the substeps it keeps a copy of the proxy's manifold (at most five entries), runs 0x008939B0,
hands a debug colour to a list hung on the phantom's world object and to a material property of a scene node, and
counts two timers down. Returns 0 or 2. (D from the control flow below.)

## Calling convention and parameters

- `__thiscall`: ECX = this, copied to ESI at 0x00896022 (R). One stack argument at [EBP+8], kept in EDI at
  0x0089601F (R): a pointer to the caller's movement-input record whose +0x00 is read as a float (0x0089602E) (R).
- Frame: EBP frame with ESP aligned to 16 (0x00896003 `AND ESP,0xfffffff0`), 0x134 bytes of locals, stack cookie
  from `[0x00B30AAC]` (0x0089600C) checked by 0x009811E2 at both exits (R).
- Callee cleans: `RET 0x4` at 0x0089701A and 0x00897033 (R).
- Returns EAX: 0 from the early exit (0x00897029 `XOR EAX,EAX`) and from the normal exit when flags bits 5-7 are
  clear; 2 when `[this+0x1F4] & 0xE0` is non-zero after 0x008939B0 (0x00896DFE-0x00896E02, returned at 0x00897002)
  (R). Bits 5-7 are cleared on entry (0x00896024), so a 2 means a callee between entry and 0x00896DF8 set one (D).

## Claims

1. R - the clock: dt comes only from `*param` (0x00896056); no global game clock is read. RDTSC is read at six
   profiler sites (0x00896170, 0x008967B3, 0x008967F9, 0x00896A36/0x00896A7C, 0x00896F85) into the thread's TLS
   buffer only.
2. R - when the step is split (B15), `*param` and param+0x10 are overwritten with the divided values: the caller's
   record changes (0x0089626E-0x00896270, 0x00896265).
3. R - n = 1 - 0x009828C0(dt / -0.05) with the double `[0x00A96910]` (0x00896215-0x00896227); n <= 1, still
   (0x00896232) or smallStep (0x00896240) gives n = 1; n > 2 is capped to 2 (0x00896245-0x00896247). D (from that and
   0x009828C0 truncating toward zero, which is U: its rea-all pseudocode is the MSVC `_ftol2` shape, an SSE3 `fisttp`
   path and otherwise a rounding with a correction to truncation, plausible but not proven) - n = 2 once
   dt / 0.05 >= 1, i.e. dt >= 0.05 (the float 0.05 widens to exactly the double 0.05000000074505806, so dt == 0.05f
   gives -1.0 and n = 2), unless still or smallStep. The flags bit-19 path (B24, 0x00896769) ignores n and never
   enters the substep loop.
4. R - `[0x00B2EFB8]` is 1 around the integrate when flags bit 20 is set, else 4, and 4 after (0x00896BC2-0x00896BE3);
   agrees with knowledge/character-controller-contacts.md.
5. D (from claim 4 and 0x008AD7D0 reading it) - two updates running at once race on `[0x00B2EFB8]`: one's integrate
   can run with the other's cap (1 instead of 4 or the reverse). Making the cap a per-call value is required before
   this can run on several threads.
6. R - `[0x00BA7A5C]` is cleared by this function each substep (0x00896849) and tested after the integrate
   (0x00896C0C); D (with 0x00893B90's pseudocode) - it is a global result channel between a callee and this
   function: two concurrent updates would clear or read each other's pick.
7. R - 0x008AC080 (phantom set position, pseudocode U) is called only at 0x00896C9D, inside the picked-body branch
