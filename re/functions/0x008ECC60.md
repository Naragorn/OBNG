## Purpose

Moves the phantom to a new position, grows its AABB along the cast path and pushes that AABB into the world's broad
phase (0x008DE950), builds a linear-cast input on the stack, then for every collidable in the phantom's overlap list
(+0x120 array, +0x124 count, walked from the last to the first) picks a cast function from the world's collision
dispatcher by the pair of shape types and calls it with the two collectors the caller passed. The function itself
returns nothing (no EAX set before `RET 0x10`).

**Answer to the slice question:** a cast is not read-only. It writes the phantom's own transform (+0xA0) and, through
0x008DE950, the world: the counter at world+0x88 is incremented and decremented without a lock prefix, the broad phase
gets the phantom's new AABB, and pair changes are applied (see Claims C10-C14). The hits go into the caller's
collectors through the dispatcher's functions (not followed here).

No clock or time global is read or written by this function's own instructions (derived: data.json has one data
reference, 0x00A3D65C = 0.5f, and no other absolute address appears in asm.s). Its callees - the shape vcalls,
0x008DE950 (and its 0x00899210), 0x008D9870 and the dispatcher's cast functions - were not checked for that
(unverified; settled by exporting those callees from the reference binary).

## Calling convention and parameters

`__thiscall`, `this` in ECX (moved to ESI at 0x008ECC75), four stack arguments, callee cleans: `RET 0x10` at
0x008ECDCC (read). The frame is aligned to 16 bytes (`AND ESP,0xFFFFFFF0` at 0x008ECC63) because the vectors are
moved with MOVAPS (read).

## Control flow

| # | Branch | Condition | Address | Test flow |
|---|---|---|---|---|
| B1 | skip loop | overlap count - 1 < 0 as a signed int32 (DEC then JS), i.e. count <= 0 as int32, which includes any count >= 0x80000000; in practice count == 0 (derived) | 0x008ECD3E / 0x008ECD4A | empty overlap list: only the position write, the AABB and the broad-phase update happen; no cast function is called |
| B2 | type override | other shape's type == 0x18 (JNZ skips when not) | 0x008ECD67 / 0x008ECD6E | other type != 0x18: type used as is |
| B3 | type override, second test | type == 0x18 and bit 0x2000 of other collidable +0x1C set (JZ skips when clear) | 0x008ECD79 / 0x008ECD7C | 0x18 with the bit clear: stays 0x18; with the bit set: replaced by 3 (0x008ECD7E) |
| B4 | loop back | index after DEC >= 0 (JNS) | 0x008ECDC3 / 0x008ECDC4 | count n: n calls, indices n-1 down to 0 |

No branch tests the result of 0x008DE950 (void) or of the cast functions (ADD ESP,0x14 drops it; read). Inside
0x008DE950 (pseudocode only): when world+0x88 + world+0x8C != 0 it reports error 0x11 through 0x00898820 and returns
without touching the broad phase; this function carries on and casts anyway (derived from B1-B4 having no test).

## Read-and-write map (the manifest's five groups)

- **(a) Own object (the phantom)**: writes +0xA0..+0xAF; reads +0x08, +0x14 (shape), +0x70 (transform), +0x120,
  +0x124; through 0x008DE950 reads +0x28 (unverified).
- **(b) Other actors / references**: reads every overlapping collidable's +0x00 (shape, then its type) and +0x1C;
  overlaps include other characters' phantoms (knowledge/threading.md: 14 % of Gsk tests are type 2). Writes to
  them only inside 0x008DE950's pair handling (unverified) and the cast functions (not followed).
- **(c) Havok world**: reads world+0x74 (input +0x00..+0x0C, +0x08, +0x20) and world+0x7C (dispatcher table +0x190,
  function entries). Through 0x008DE950 writes world+0x88 and the broad phase, reads +0x8C, +0x84, +0x90, +0x2A8,
  +0x64, +0x78, +0x08 (all unverified, pseudocode).
- **(d) Globals with addresses**: 0x00A3D65C (0.5f, read-only constant). Through 0x008DE950: 0x00BA7D9C, the
  fallback stack allocator (read, and its +0x20 cursor written when used; unverified).
- **(e) Heap**: none in this function. 0x008DE950 uses the thread's stack allocator (cursor bump, a vcall +0x0C when
  the block is full, +0x10 on release) and calls 0x008A75D0 to free (unverified, pseudocode).

## Open questions

- Does 0x008DE950's increment of world+0x88 use a plain ADD, and is world+0x8C a second counter of the same kind?
  Read its instructions (not only the pseudocode).
- What does 0x008DE950's broad-phase call change when the phantom only moves a little: the AABB only, or also pair
  add/remove (overlap list of this and other phantoms)? Needed to decide if a cast can run beside another actor's.
- Which class owns the vtable at 0x00A9AFFC (no RTTI)? hkSimpleShapePhantom and hkCachingShapePhantom strings are in
  the image; the per-entry dispatch without a cached agent fits a simple shape phantom (unverified).
- Shape type 0x18, the replacement type 3 and filter bit 0x2000: meaning unknown.
- Which dispatcher entries are reached in the crowd (the cast functions' addresses), and do they write anything besides
  the collectors?
