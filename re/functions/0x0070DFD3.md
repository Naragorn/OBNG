# 0x0070DFD3 - the plane-loop half of 0x0070DFB0 (slice draw-setup, map only)

**This is not a function.** 0x0070DFD3 is a branch target inside 0x0070DFB0 that
Ghidra split off as `FUN_0070dfd3`. The function's mapping, as one function, belongs
in `re/functions/0x0070DFB0.md` (in progress in this phase). This file is a pointer;
it keeps only what the loop half's own export shows, so the 0x0070DFB0 entry can
cite it.

The one read fact that matters: this half has **no callers** (meta.json
`"callers": []`) and is reached by exactly one instruction in the whole EXE, the
`JNZ 0x0070DFD3` at **0x0070DFC0** (bytes `75 11`) in the entry half, taken when the
plane mask `[this+0x8C]` is non-zero. It leaves through the entry half's
`POP EBP; POP ECX; RET 0x4` epilogue pattern (0x0070E039..0x0070E03B), so the
two halves share one `__thiscall`, one stack argument, `RET 4` contract.

## Purpose

When the entry half finds a non-zero plane mask, this half tests the argument
object's bound against each active plane and either culls the object or hands it
on with a narrowed mask:

1. For i = 0..5, when bit i of `[this+0x8C]` is set, it calls 0x0047DA70 with
   ECX = arg+0x20 (the object's bound) and the plane at `this+0x2C+0x10*i`.
2. Result 2 (sphere wholly on the plane's negative side) leaves the loop early;
   the object is then **not** passed on.
3. Result 1 (wholly on the positive side) clears bit i in `[this+0x8C]` while
   the loop continues, so later work skips that plane.
4. When all six iterations ran (no result 2), it calls the argument's virtual
   slot +0x7C with `this` pushed, under the narrowed mask.
5. On both paths it then writes the mask saved on entry back to `[this+0x8C]`
   and returns with `RET 4`.

Read this way (derived from steps 3-5, see C8), the narrowed mask lasts until the
restore at 0x0070E033; only the +0x7C call and what it calls can read it (B6'
path only), and the caller's next object sees the original mask again. That matches a hierarchical cull where children inherit the parent's
"already fully inside" planes. The Gamebryo reading (the +0x7C slot as a
visit/OnVisible that recurses into children) is **unverified**.

Subsystems touched: the culling process object (`this`: planes and mask), the
culled object (its bound at +0x20 and one virtual call), and the bound/plane test
0x0047DA70. No clock reads or writes, no globals.

## Calling convention and parameters

The half has no convention of its own. It inherits the entry half's frame
(read, 0x0070DFB0 asm.s):

- `this` in ECX on entry to 0x0070DFB0, copied to **EBP** at 0x0070DFB2
  (`MOV EBP,ECX`). This half uses EBP as `this` throughout and never loads it.
- Frame on arrival (ESP0 = ESP at the entry of 0x0070DFB0): `[ESP0-4]` = saved
  mask (pushed ECX slot overwritten at 0x0070DFBC), `[ESP0-8]` = caller's EBP,
  `[ESP0+4]` = the one stack argument (an object pointer).
- It pushes EBX, ESI, EDI (0x0070DFD3..0x0070DFD5) and pops them at
  0x0070E01E..0x0070E020, so the argument is `[ESP+0x18]` inside the loop
  (0x0070DFF1) and `[ESP+0xC]` after the pops (0x0070E023), and the saved mask
  is `[ESP+4]` at 0x0070E02F. All three offsets resolve to the same slots the
  entry half uses (derived from the push/pop counts).
- Exit: `POP EBP` (0x0070E039), `POP ECX` (0x0070E03A, discards the mask slot),
  `RET 0x4` (0x0070E03B): callee cleans its one argument, the same `RET 4` as
  the entry half's 0x0070DFD0 (read).
- EAX on return from this half = the saved mask (`MOV EAX,[ESP+4]` 0x0070E02F),
  on the entry half's mask==0 path = whatever the virtual call left. Callers
  therefore see no consistent return value (derived; treat as `void`).
- The virtual call at 0x0070E02D must pop its one pushed argument itself:
  otherwise `[ESP+4]` at 0x0070E02F would read the pushed EBP instead of the
  saved mask (derived from the stack offsets; consistent with `__thiscall`).

## Control flow

Every branch, with its condition (read from asm.s unless marked):

| # | at | instruction | condition | target / effect |
|---|---|---|---|---|
| B0 | 0x0070DFC0 (entry half) | `JNZ 0x0070DFD3` | `[this+0x8C] != 0` | enters this half; otherwise the entry half calls slot +0x7C and returns without writing the mask back |
| B1 | 0x0070DFDB | `JMP 0x0070DFE0` | unconditional | skips the 3 filler bytes `8D 49 00` (`LEA ECX,[ECX+0]`, never executed) at 0x0070DFDD to the aligned loop head |
| B2 | 0x0070DFEF | `JZ 0x0070E010` | bit i of the mask clear | plane i skipped, no call |
| B3 | 0x0070E001 | `JZ 0x0070E01B` | WhichSide result == 2 | loop left with EDI = i < 6 (culled) |
| B4 | 0x0070E006 | `JNZ 0x0070E010` | result != 1 (so result 0, or any value other than 1/2) | mask unchanged, next plane |
| B4' | 0x0070E008 | fall-through | result == 1 | bit i cleared in `[this+0x8C]` |
| B5 | 0x0070E019 | `JC 0x0070DFE0` | i+1 < 6 (unsigned) | next iteration |
| B6 | 0x0070E021 | `JNZ 0x0070E02F` | EDI != 6 (flags from `CMP EDI,6` at 0x0070E01B; the three POPs do not touch flags) | culled: skip the virtual call |
| B6' | 0x0070E023 | fall-through | EDI == 6 (all six iterations ran) | `CALL [[arg]+0x7C](this)` |

Test flows the rebuild needs (derived from B0-B6): mask 0 (entry half only);
mask with no bit 0..5 set but non-zero (bits 6..31 only: the loop calls nothing,
the virtual call runs, the mask is restored); each plane i giving 2 (cull at i,
earlier 1-results' cleared bits restored anyway); 1 on some planes then a pass
(narrowed mask visible to the virtual call, restored after); all zeros (mask
unchanged during the call).

## Claims

- **C1** 0x0070DFD3 is reached only from the `JNZ` at 0x0070DFC0.
  **read**: meta.json `callers: []`; a byte scan of the md5-matching EXE
  (`cdd2f0c5eff198d4f26b7b5b54ce4930`, ImageBase 0x00400000) for every
  `E8`/`E9` rel32, `0F 80..8F` rel32 and `EB`/`70..7F` rel8 whose target is
  0x0070DFD3, and for the absolute dword `0x0070DFD3` in every section, finds
  exactly one hit: rel8 `75` at 0x0070DFC0. A register-computed target that
  never stores the address as a dword is not excluded by this scan (none is
  plausible, since no table holds it).
- **C2** It returns through the same `RET 4` contract as the entry half: `POP EBP`,
  `POP ECX`, `RET 0x4` at 0x0070E039..0x0070E03B against `POP EBP`, `POP ECX`,
  `RET 0x4` at 0x0070DFCE..0x0070DFD0. **read**. Its stack offsets for the argument
  and the saved mask resolve to the entry half's slots. **derived** (push/pop
  counts, see Calling convention).
- **C3** The loop runs at most six iterations over bits 0..5 and planes
  `this+0x2C+16*i`. **read** (0x0070DFE0..0x0070E019).
- **C4** On result 2 the object is culled: the virtual call is skipped (B3, B6).
  **read**.
- **C5** On result 1 bit i is cleared in `[this+0x8C]`; on any other non-2
  result the mask is left as it was. **read** (0x0070E003..0x0070E00A).
- **C6** The mask saved on entry is written back to `[this+0x8C]` on both exits of
  this half, after the virtual call or after the cull. **read** (0x0070E02F,
  0x0070E033 are reached by both B6 and B6').
- **C7** The entry half's mask==0 path does not write the mask back after its
  virtual call. **read** (0x0070DFC2..0x0070DFD0 contain no store to +0x8C).
- **C8** The narrowed mask lasts until the restore at 0x0070E033. Only the +0x7C
  call (0x0070E02D) and anything it calls in turn can read it, and only on the B6'
  path. On the cull path (B3, B6) nothing reads it before the restore: between
  0x0070E01B and 0x0070E033 there are only the `CMP`, the three `POP`s, the `JNZ`
  and the load of the saved mask. (The loop's own `TEST` at 0x0070DFE9 reads the
  mask after a clear, but only bits j > i, which the clear of bit i does not
  change.) **derived** from C5, C6 and the instructions 0x0070E01B..0x0070E033.
  C6 on the B6' path rests on the +0x7C callee cleaning its one argument (see
  Calling convention): otherwise `[ESP+4]` at 0x0070E02F reads the pushed EBP,
  not the saved mask. That callee contract is **derived** from the stack offsets,
  not read in any +0x7C target.
- **C9** pseudo.c agrees with the instructions on the loop, the break on 2, the
  bit clear on 1 and the restore. It names the saved mask `param_1` and the
  argument `param_3` because the half has no frame of its own; the instructions
  show both are slots of the entry half's frame (`[ESP+4]` and `[ESP+0xC]`
  after the pops). It also drops the pushed `this` of the virtual call and the
  `ECX = arg+0x20` of the 0x0047DA70 call. **read** (pseudo.c vs asm.s).
- **C10** Slot +0x7C of the argument's vtable is a per-object visit method
  (OnVisible-like) that recurses into children. **unverified**: this export has
  no vtables, so the behaviour cannot be read here. What would settle it: the
  per-class slot +0x7C targets, which re/functions/0x0070DFB0.md C11 reads via
  objdump (NiNode 0x0070AB40 walks its children through 0x007073D0). The name
  `OnVisible` has no settled source (recalled Gamebryo naming; no xOBSE or OBVR
  header names the slot).
- **C11** `this` is the NiCullingProcess and 0x0070DFB0 is its vtable slot 1,
  dispatched from NiAVObject::Cull 0x007073D0. **unverified here** (OBVR
  GameAddresses.h, the comment before the NiCullingProcess::Process hook;
  0x007073D0's pseudocode in re/export/rea-all calls `[[param_1]+4]`).

## Open questions

- Which class's slot +0x7C is called (0x0070E02D), and does it recurse with the
  same culling process? Needs the vtables of the objects 0x007073D0 and 0x0049CBF0
  pass. Belongs to the 0x0070DFB0 entry.
- 0x0049CBF0 calls 0x0070DFB0 directly (pseudocode, rea-all 0x49cbf0.c line 83)
  after its own single-plane test at +0x90: is that the same culling process type,
  and does it rely on EAX (C9's inconsistent return)? Belongs to the 0x0070DFB0 entry.
- Who sets bits 6..31 of `[this+0x8C]`, if anyone? A mask with only those bits set
  enters this half, tests nothing, and calls the visit (B2 on every i).

Smaller callees worth their own slice: none here. 0x0047DA70 is already mapped
(perf-levers). The virtual +0x7C target is the next step for the cull walk.

## Layout requests

For a shared `NiCullingProcess` header (offsets from this half; the rest belongs
to the 0x0070DFB0 entry):

- `+0x2C` `NiPlane planes[6]` (16 bytes each: `NiPoint3 normal; float constant`),
  ending at 0x8B.
- `+0x8C` `uint32_t activePlaneMask` (bits 0..5 used here).

For `NiAVObject`: `+0x20` world bound (`NiBound`: centre, radius; 16 bytes) and
vtable slot `+0x7C` (one argument, the culling process; callee cleans).
