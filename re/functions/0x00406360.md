## Purpose

The start-up sequence that builds the game world's singletons and loads the
plugins, and - last of all - sets the global clock's fixed step from an
integer setting. That it runs once at start-up is **unverified**: meta.json
`callers` is []; a search for 0x00406360 as an indirect call target or as a
pointer in .rdata/.data would settle it. In order (**read**, addresses below):

1. Log "Initializing Sky..." (0x00406390), take the Sky singleton
   (`Sky_GetSingleton` 0x00542EA0, xOBSE) and store it in 0x00B333B0
   (0x004063AD). Initialise it with 0x005411D0 (0x004063B2), wire it into the
   scene roots 0x00B333D8 / 0x00B333DC (0x004063D4 vtable +0x84 on
   0x00B333DC; 0x004063EA / 0x00406406 attach-like calls), update both roots
   (0x00707610, 0x00707980, 0x00707370(0.0f, 1)) and call 0x007B8940(root,
   10, 0, 1) on each.
2. Tag the sky's shader properties: for five sky sub-objects it takes the
   property of type 4 (0x00707530(4)) and, when it is a
   `NiRTTI_SkyShaderProperty` (0x00B4335C, xOBSE), writes a kind code to
   property+0x88: 2, 4, 0, 1, and 3 with the index at +0x84 for the two
   entries of the array at [sky+0x2C]+0x08.
3. Attach 0x00B333A8 (when set) and take its first child's vfunc +0x08
   result as an argument for TES.
4. Log "Initializing TES...", allocate 0xAC bytes (`FormHeap_Allocate`
   0x00401F00), construct with 0x00441970("Data\\", [0x00B333AC], child,
   sky) and store `g_TES` 0x00B333A0 (0x0040663F); call 0x0043F560 on it.
5. Log "Initializing TreeManager...", call 0x0055F750(0).
6. Log "Initializing Menus...", update the node passed as the stack argument
   (0x00707610, 0x00707980, 0x00707370(0.0f, 1)).
7. Plugins: for ten string settings 0x00B02C90..0x00B02CD8 (stride 8), when
   the string is non-empty, look the file up through `g_dataHandler`
   (0x00447C50) and when found mark it with 0x0044FAD0(1). Then
   `this`->0x00404B00(0x00B3F178, [0x00B02C88]) - the runtime value of the
   string setting at 0x00B02C88, loaded at 0x0040673A, whose image value is
   0x00A2FB94 ".\\Plugins.txt"; when that returns 0 and
   none of the ten was found, look up and mark "Oblivion.esm" the same way.
8. Allocate 0x804 bytes, construct with 0x0066A740 and store `g_thePlayer`
   0x00B333C4 (0x004067A6); call 0x0046C300(0x14, 1) on it.
9. Log "Loading Files...", `g_dataHandler`->0x0044F3D0(0, 0), then
   `g_TES`->0x00443550().
10. Log "Initializing Player...", `LookupFormByID(7)` cast to TESNPC
    (`Oblivion_DynamicCast` 0x009832E6), hand it to the player (0x006C5420),
    set a vector (2048.0, 2048.0, 0.0) through player vtable +0x1CC, pass the
    12 bytes at 0x00B3F9A8 by value to 0x004D89A0, call vtable +0x6C, and
    check two values through vtable +0x284 with 10 and 8: a zero logs the
    Fatigue / Health error (0x00404EC0) with the NPC's editor name.
11. Log "Initializing Scripts...", `g_dataHandler`->0x00447D80().
12. Log "Initializing Sound System...", 0x006AF850(0).
13. **The clock** (0x004068FA..0x0040692B): read the dword at 0x00B02D10;
    when it is in 1..199, write `1000.0 / value` as a float to
    `g_timeInfo.fixedStepMs` 0x00B33E94; otherwise leave it alone.

This is the only place in the function that touches the clock: no read of
0x00B33E90..0x00B33EA7 and no call of the TimeInfo methods
(0x0047D0F0/0x0047D120/0x0047D150/0x0047D170) appear in asm.s (**read**, by
the full listing).

## Claims

1. **read**: the only write to the clock is `FSTP float ptr [0x00B33E94]` at
   0x0040692B, the last block before the epilogue (0x00406931).
2. **read**: the value is `1000.0 / v` where v = dword [0x00B02D10] (0x004068FA)
   loaded by `FILD` (0x00406915) and divided into the double 1000.0 at
   0x00A2FC70 by `FDIVR` (0x00406921); data.json gives 0x00A2FC70 as f64
   1000.0 and 0x00A2FC78 as f32 4294967296.0.
3. **read**: the write happens only when v - 1 <= 0xC6 unsigned (CMP/JA at
   0x00406905/0x0040690B), i.e. when 1 <= v <= 199; otherwise fixedStepMs keeps
   whatever value it had.
4. **derived** (from claim 3 and the image value 0 at 0x00B02D10): when the
   setting is left at its image default 0, this function does not write
   fixedStepMs, and variable-step mode stays as the TimeInfo builder left it
   (the builder's initial value is in knowledge/frame-clock.md, not in this
   export).
5. **derived** (from #33 to #35): the FLDZ at 0x00406929 and the 2^32 fix-up
   at 0x0040691B are both unreachable for v in 1..199, but they are two
   different things. Only `JGE 0x00406919` + `FADD float ptr [0x00A2FC78]`
   (0x0040691B) is the UInt32-to-float fix-up. The FLDZ path (`JZ` at
   0x0040690F -> 0x00406929 -> `FSTP` at 0x0040692B) skips the FDIVR at
   0x00406921, so it is the zero arm of `v ? 1000.0 / v : 0.0f`, not part of
   the conversion; 0x0040D4D0 shows the same separate zero arm (0x0040D789 ->
   FLDZ at 0x0040D7AB). That v is treated as unsigned rests on the fix-up
   alone (derived; the declaration itself is not in the binary).
6. **derived** (exact rational arithmetic in Python over v = 1..199): the
   stored float is the same whether the x87 precision control is 24-, 53- or
   64-bit, so the measured 24-bit control (knowledge/frame-clock.md) does
   not change this result.
7. **unverified**: that 0x00B02D10 is `iFPSClamp` (OBVR's
   `FrameClockLogic.h:37` says "+0x04: 1000 / iFPSClamp" without naming the
   writer). The setting's name pointer 0x00A3141C is in data.json's bytes but
   the string at 0x00A3141C is not in the export. Settled by exporting the
   bytes at 0x00A3141C.
8. **derived** (claims 1 to 3, the unit of +0x04 in knowledge/frame-clock.md):

9. **read**: no other export of this slice references 0x00B02D10 (grep over

### Where pseudo.c and asm.s disagree (the instructions win)

- pseudo.c line "LookupFormByID(7,0,&RTTI_TESForm,&RTTI_TESNPC,0);
  Oblivion_DynamicCast(uVar13)" puts the four cast arguments on the lookup.
  The instructions push them before the lookup but clean only one dword
  after it (`ADD ESP,4` at 0x004067F9) and five after the cast (0x00406808):
  the lookup takes one argument, the cast five.
- pseudo.c shows `FUN_005411c0(DAT_00b333ac); FUN_00708e40(uVar7)`: the
  `PUSH EBP` at 0x004063E2 precedes both calls, 0x005411C0 is called with
  ECX = sky, and its result becomes ECX for 0x00708E40. Which of the two
  consumes the pushed dword depends on their `RET N`, which is not in this
  export; the same shape repeats at 0x004065C7..0x004065CF. Open question 3.
- pseudo.c computes the fixed step through intermediate stores to
  `_DAT_00b33e94` and `(float)_kMillisecondsPerSecond`. The instructions keep
  the value in ST(0) and divide the double 1000.0 by it (`FDIVR double ptr`),
  storing once (0x0040692B). The results agree for 1..199 (claim 6), but the
  rebuild follows the instructions.
- pseudo.c renders the sky array loop as a `do { ... if (1 < uVar6) {rest of
  the function} } while(true)`; the instructions are a plain loop that exits
  at 0x004065B3 when EDI reaches 2.
- pseudo.c ends with `*unaff_FS_OFFSET = (int)appuStack_3c[7]`: this is the
  SEH restore `MOV ECX,[ESP+0x50]; MOV FS:[0],ECX` at 0x00406931, not an
  array element.
