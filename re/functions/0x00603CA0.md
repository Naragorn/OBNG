## Purpose

The per-frame body of one actor's update. In order (D, from the control flow below):

1. Fetch the 3D root (vtbl+0x154), the head-tracking object (process vtbl+0xE8), the controller-like object
   0x0065A2C0 and the animation data (vtbl+0x164). Leave unless the actor has 3D, a parent cell whose byte +0x26 is 6,
   and the argument is below 900.0.
2. Controller pre-step 0x005E14E0 (on controller+0x1F0) with a byte from the animation groups 3 and 1.
3. Process calls +0x2F4, +0x440, (+0x60), head-tracking nudge, an actor-value-8 restore for this+0xB0 == 6.
4. NPC-only flags (0x400) and 0x005F4AE0.
5. Mount handling (0x005E1030 / vtbl+0x380, proposal "is riding / the mount"): heading and position copied from the
   mount; else the global flag [0x00B3CBD0] = 1 when vtbl+0x388 answers non-null.
6. **Writes the 3D root's local transform** (translate +0x54..+0x5C from the reference position, rotation +0x30..+0x50
   from the heading, the controller's +0x32C and 0x004D7C50) - a first-person-player variant and an everyone-else
   variant.
7. Rescans the carried light (0x007B4280(0) -> 0x007C6FF0).
8. With animation data: 0x00471C00, a spine twist for a mounted actor (Bip01 Spine / Spine1 rotations), the animation
   step 0x00603500(frameSeconds), the skeleton update ApplyAnimData 0x00471F20, a root-motion scale correction.
9. Clears [0x00B3CBD0].
10. Unless the first-person player: swimming / breath / drowning / splash / water damage (controller state 5, the
    controller's +0x2A0 / +0x338), the NPC's greeting/detection of the player (0x005F6540 -> process +0x484 / +0x1A4 /
    +0x158), the process timer +0x360 counted down by frameSeconds, an animation reset, process +0x318.
11. Process +0x424 -> +0x42C; process +0x08 == 0 -> 0x00633250; 0x005F12D0; an NPC's camera-distance fade value
    handed to the shader accumulator 0x007ABD00 and to an object from process +0x18C (0x005EA2F0 / 0x005EA320).

It does **not** call the character controller's update 0x00896000 (see Claims C5).

## Calling convention and parameters

- `__thiscall`: ECX = the actor, moved to EBP at 0x00603CCD and kept there to the end (R).
- One stack argument, a 32-bit float: read at `[ESP+0xEC]` (12 bytes SEH + 0xC8 locals + 4 saved registers + cookie =
  0xE8 to the return address) at 0x00603D4A and 0x006054FC, with no pushes outstanding at either (R).
- `RET 0x4` at 0x00605759, the only return (R). Callee cleans the stack.
- No meaningful return value: EAX is not set before the epilogue at 0x00605740 (R); `void` (D).
- Frame: SEH record (handler 0x009C2C60, R 0x00603CA2), `SUB ESP,0xC8`, saves EBX/EBP/ESI/EDI, pushes
  `[0x00B30AAC] XOR ESP` (the /GS cookie, data.json u32 0xBB40E64E) at 0x00603CBF; the epilogue pops it into ECX at
  0x0060574E without a check call - the check sits in the SEH handler stub (its bytes in data.json `8b 54 24 08 ...
  33 c8 e8 ...`) (R).
- The argument's uses (R): `arg >= 900.0` (f64 at 0x00A6C820, data.json 900.0) -> early exit (B4); for the player,
  `arg != 0.0` skips 0x00633250 (B85). **Nothing else reads it**; the per-frame time is the global [0x00B33E9C].
- pseudo.c names the second use `unaff_retaddr`; it is the same argument (R vs. 0x006054FC).
