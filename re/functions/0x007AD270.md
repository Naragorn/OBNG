## Purpose

Called once per visible geometry `P` while the scene is culled, it decides where `P`'s
render work goes and files it - it does not draw, except on three paths (C3):

1. Debug/filter gates on the bytes 0x00B42CDA / 0x00B42CDB (only NiLines-derived
   geometry passes when both are set, 0x007AD2B0) and the per-geometry call
   0x007AB6F0 when only 0x00B42CDB is set.
2. Gets `P`'s property state (0x00405760) and its shader property `prop =
   [state+0x18]`; with no state, `P` goes to a default list (0x007ABC40 / 0x007ABDE0).
3. Classifies by the shader object's id (`[P+0xBC]` slot +0x1C) and the property's
   shader type (`prop` slot +0x54): sky (0x16/0xB), water (0x18/0xC), particles
   (0x19/0xE), bolt (0x1A/0xD) take their own short paths; other lit shaders
   (type >= 1) take the main path; everything else (no shader object, id <= -1,
   type < 1) takes the fixed-function path.
4. Fixed-function path: with the accumulator byte +0x21E0 clear it renders `P` at
   once through `P`'s slot +0x84 with `g_renderer`; otherwise it files `P` by alpha:
   opaque (or blended with the "no sorter" bit while +0x34 is set) into the default
   list, blended into +0x0C, +0x2244 or +0x2254 (split by an exact compare of the
   integer 0x00B42CE4 with `P`'s bound-centre z when 0x00B42CE1 is set, C6).
5. Main path: relights `P` against the shadow scene node (0x007B4280 / 0x007C7050,
   once until `P`'s flag 0x80 is cleared again), asks the property for `P`'s render
   pass list (`prop` slot +0x5C), allocates a 0x18-byte group per call for a
   multi-pass geometry with a NiGeomMorpherController, and then files every pass
   record (C4, C5, C21): opaque records into the per-pass list array at
   `this+0x104+key*0x14`, or into the morpher group via 0x007AD1C0 when one was made
   this call; blended records into the record list +0x21C0 plus one geometry list
   (+0x0C / +0x2244 / +0x2254), or only into the +0x60 group via 0x007AD1C0; with
   +0x21E0 clear, every record into the lists +0x90 / +0x7C / *[+0x78] (or dropped
   in render mode 6). Pass ids 0x34..0x47 (only when the pass list has exactly one
   record) are re-keyed to 0x19..0x2E, and pass ids 0x190 / 0x192 (any count) are
   dropped, when the geometry has no fog property (`state+0x0C`, derived
   BSFogProperty) or its bound does not reach past fogStart; otherwise they keep
   their key and the fog constants 0x00B46638..0x00B46654 are written (C9, C10).
6. Bumps three counters (0x00B42CD0 geometries, 0x00B42CC4 by a word from the
   geometry data, 0x00B42CB0 by 0x10 per non-blended main-path record handled,
   including the mode-6 fall-back records it drops) and returns `AL = 1`.

The pass lists it fills are drained later: 0x007AC9A0 indexes the same array
(`this + pass*0x14`, fields +0x108 / +0x114) - derived, C15.

## Calling convention and parameters

- `__thiscall`: `this` (the accumulator) in ECX, copied to EBX at 0x007AD283 and used
  as the base of every +0x0C..+0x2268 access. **read**
- One stack argument `P` (a geometry, NiAVObject-derived): `MOV ESI,[ESP+0x88]` at
  0x007AD27C after `SUB ESP,0x7C` and two pushes = `[ESP+4]` at entry; later read as
  `[ESP+0x8C]` / `[ESP+0x90]` after the EDI / EBP pushes. **read**
- Callee cleans: every exit is `RET 0x4` (0x007AD2C5, 0x007AD351, 0x007AD423,
  0x007AD525, 0x007AD70F, 0x007ADF62, 0x007ADF7E, 0x007ADFAA, 0x007ADFCD). **read**
- Return: `MOV AL,0x1` on every exit (0x007AD2BF, 0x007AD34B, 0x007AD41D, 0x007AD51F,
  0x007AD709, 0x007ADF5C, 0x007ADF78, 0x007ADFA4, 0x007ADFC7); the upper 24 bits of
  EAX are whatever the last call left. A bool, always true. **read**
- Saved registers: EBX, ESI always; EDI from 0x007AD2FA; EBP from 0x007AD368. The
  early exits pop only what they pushed (0x007AD2BE: ESI, EBX; 0x007AD349: EDI, ESI,
  EBX). **read**
- Frame: 0x7C bytes of locals; the locals named below are relative to ESP after all
  four pushes: `[ESP+0x13]` byte "morpher group made", `[ESP+0x14]` next list node,
  `[ESP+0x18]` current record, `[ESP+0x1C]` `prop`, `[ESP+0x20]` the pass list,
  `[ESP+0x34]` `[state+0x08]`, `[ESP+0x2C..0x88]` float scratch of the distance test.
  **read**
- Ghidra's signature `undefined4 __thiscall FUN_007ad270(int param_1,int *param_2)`
  matches the shape; meta.json says `calling_convention: unknown`. **read**

Note on the two list types (correction: the first version gave every list 0x14 bytes,
which is wrong):

- **0x005B1E20 lists** at +0x0C, +0x21C0, +0x2244, +0x2254. All four are passed as
  `this` (ECX) to the same 0x005B1E20 (OBVR `GameAddresses.h:1814` `kListAddTail`),
  so they are one type (derived). +0x2244 and +0x2254 are both such lists and lie
  0x10 apart (0x007ADDC1, 0x007ADDAC), so the type is at most 0x10 bytes (derived).
  The rea-all pseudocode of 0x005B1E20 (`re/export/rea-all/functions/0x5b1e20.c`,
  a reading aid only) touches +0x00 (vtable, slot +0x04 allocates a node), +0x04
  head, +0x08 tail, +0x0C count, which fits exactly 0x10 bytes; the 0x10 size is
  therefore derived from the spacing, with the field list from the pseudocode
  (unverified against 0x005B1E20's instructions, which this slice did not export).
- **0x007ABDE0 lists** at +0x7C, +0x90 and the array `+0x104 + key*0x14`. The array
  stride is 0x14 (index arithmetic, read); 0x7C + 0x14 = 0x90 and 0x90 + 0x14 = 0xA4
  (the next field used) fit a 0x14-byte type (derived), as does
  re/functions/0x007AC9A0.md (lists +0x7C / +0x90 of 0x14 bytes). 0x007ABDE0 is
  also called on the 0x18-byte object at `*[this+0x78]` (0x007ADEE3), so the
  receiver of 0x007ABDE0 is not one fixed size; whether the 0x18-byte object
  derives from the 0x14-byte list is unverified.
- +0x3C (0x006AA320) and +0xA4 (0x007AD1C0) are not sized here (unverified).
