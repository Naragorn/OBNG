## Purpose

Builds a 0x40-byte, 16-aligned stack object whose first dword is the vtable 0x00A96AD4 (a
ray cast collector, proposal), zeroes its +0x30 and +0x34, and calls 0x008D95A0 on that
object with (`[this+0x64]`, input, `[this+0x78]`, 0, output). 0x008D95A0 fills the collector
from those arguments and calls vfunc +0x38 of `[this+0x64]` (read 0x008D9667). Knowledge
names `[world+0x64]` the broad phase (knowledge/actor-frame-map.md line 363 and 406, from
re/functions/0x008DE950.md). `this` is the hkWorld (derived: the caller passes the same EDI,
set at 0x0088B976 and not rewritten up to 0x0088BAA7, as ECX to 0x008987E0 at 0x0088B9E6/0x0088B9E8
and 0x0088BA82/0x0088BA84, which xobse.csv:472 names `hkWorld::castRay`), so the ray goes to
the broad phase's vfunc +0x38 (derived). The function itself writes nothing outside its own stack frame
(read: the only memory writes are 0x00898EE3, 0x00898EE7, 0x00898EF8, all into the frame).
Nothing here reads or writes the clock; the callee appends up to two 12-byte records to the
per-thread timer ring when the ring has room (see group (d)).

  restored by `MOV ESP,EBP; POP EBP` (0x00898F05-0x00898F07) (read). No callee-saved register

  EAX after 0x0088BAA9, read 0x0088BAAE onward) (derived).
- Call to 0x008D95A0 (read 0x00898EDE-0x00898F00): ECX = the stack collector `S`;

  `RET 0x14` (read 0x008D96A5), so it pops its five args; the frame is restored by `MOV ESP,EBP`

Let S be the 16-aligned ESP after `SUB ESP,0x40`. Push trace (derived from the instructions):
0x00898EDE ESP=S-4, 0x00898EE2 ESP=S-8, so `[ESP+0x38]` = S+0x30 and `[ESP+0x3C]` = S+0x34;
0x00898EF3 ESP=S-20, so `LEA ECX,[ESP+0x14]` = S and `[ESP+0x14]` = S+0x00.

## Control flow

Straight line, no branch in this function (read: no Jcc or JMP between 0x00898ED0 and 0x00898F08).
One test flow: given `this` with +0x64 and +0x78, arg1 and arg2, the callee receives
ECX = a fresh collector with vtable 0x00A96AD4, +0x30 = 0, +0x34 = 0, and args
(`[this+0x64]`, arg1, `[this+0x78]`, 0, arg2); the function returns with 8 bytes popped.

The branches that decide whether this function runs are in the caller 0x0088B850 (read):
- 0x0088B97A: vfunc +0x58 of the caller's ECX returned 0 -> skip (EDI = the result becomes this
  function's `this`, 0x0088B976, 0x0088BAA7).
- 0x0088B99D: `[ESI+0x78] == 0` -> 0x0088BA24, else the 0x008BA1B0 / 0x008987E0 path.
- 0x0088BA2B: `[ESI+0x74] == 0` -> 0x0088BAA3, the call to this function.
So this function runs when the request's +0x78 and +0x74 are both 0 (derived from those three
branches).
