## Purpose

A leaf predicate on a geometry buffer-data record. It answers "does the record have at
least one stream, and does every stream slot hold a chip whose vertex buffer pointer is
set?" with AL = 1, and AL = 0 otherwise. It writes nothing.

Order inside one call (read): load `record[+0x1C]` (stream count, 0x00777F11); zero ->
AL = 0 (0x00777F16); then walk `record[+0x24]` (array of chip pointers, 0x00777F22) from
slot 0 upward, for each slot test the chip pointer (0x00777F25) and the chip's `+0x08`
(0x00777F2C), leave with AL = 0 at the first null; after the last slot, AL = 1
(0x00777F3C).

Subsystems touched: only the render-side buffer-data record and its stream chips
(memory reads). No D3D call, no heap, no lock, no critical section, no clock.

What the AL means for the packer 0x00763130 (from re/functions/0x00763130.md, slice
scene-pass, B3/B4/B5 and B12): with `force == 0` and AL = 1 and the geometry's
consistency nibble `geom[+0x2E] & 0xF000 == 0x4000` (static), the packer returns AL = 1
at 0x0076317C without packing; with AL = 0 the packer takes the fresh path (release every
slot through `[[record+0x04]]+0x1C(record, i)`, resize through 0x00777F70, zero
`record[+0x34]`, dirty = 0xFFF).

## Claims

C1. **read** - `this` is ECX: the first instruction after the prologue reads `[ECX+0x1C]`
(0x00777F11); every call site loads ECX right before the call (objdump: `MOV ECX,ESI`
0x00763151, `MOV ECX,EDI` 0x00767B64, `MOV ECX,EDI` 0x0076847C, `MOV ECX,EDI` 0x007685B4,
`MOV ECX,ESI` 0x00769B74, `MOV ECX,ESI` 0x0076D21A).

C2. **read** - No stack arguments, callee pops nothing: both exits are `RET` with no
immediate (0x00777F1B, 0x00777F3F), and no instruction reads `[ESP+n]`.

C3. **read** - AL = 0 when `record[+0x1C] == 0` (0x00777F14-0x00777F1B).

C4. **read** - With `record[+0x1C] = n > 0`, the function returns AL = 1 only when for
every i in 0..n-1 the dword `[record[+0x24] + 4*i]` is non-zero (0x00777F25) and that
chip's dword `+0x08` is non-zero (0x00777F2C); it returns AL = 0 at the first slot that
fails either test (0x00777F28, 0x00777F30 -> 0x00777F18).

C5. **read** - The walk stops at the first failing slot: slots after it are not read
(0x00777F28 and 0x00777F30 jump straight to the AL = 0 exit). When n > 0, `record[+0x24]`
itself is dereferenced without a null test (0x00777F22-0x00777F25).

C6. **derived** (from 0x00777F14/0x00777F16 and the flag semantics of TEST) - The `JBE` at
0x00777F20 is never taken: it is reached only when `JNZ` at 0x00777F16 was taken
(ESI != 0), ESI is unchanged between them, and `TEST ESI,ESI` at 0x00777F1E clears CF and
sets ZF = 0 for a non-zero ESI, so `CF | ZF` is 0. It is a compiler-emitted loop guard
(MSVC `for` precheck), not a separate flow.

C7. **read** - The function writes no memory and calls nothing (no store and no CALL in
asm.s; meta.json callees `[]`).

C8. **read** - No clock, no global: data.json and meta.json `data_refs` are empty and every
memory operand is register-based.

C9. **derived** (C3, C4, C7) - "AL = 1" says only that the record has at least one stream
and each stream has a chip with a non-null buffer pointer at `+0x08`. It does not compare
`streamCount` with the declaration's stream count (the packer does that itself at
0x00763250, re/functions/0x00763130.md B13), and it does not read the chip's offset
(`+0x0C`), flags (`+0x10`) or size (`+0x14`), nor any lock or content state.

C10. **derived** (C9; packer facts from re/functions/0x00763130.md B3/B4/B5, slice
scene-pass) - For lever L3 (cross-frame pack cache): the packer's static early-out rests on
"buffers exist" plus the static consistency nibble, not on a content check. Whether the
bytes in those buffers are still the last packed ones (e.g. after a DISCARD lock of a
shared buffer) is not answered by this function; that belongs to the lock 0x00776C90 and
the allocation 0x007774C0 of this slice (in progress).

C11. **read** (objdump) - How each caller uses AL:
- 0x00763130 (packer): stores AL to `[ESP+0x28]` (0x0076315D); when `force` byte
  `[ESP+0x3C]` is 0 (0x00763158/0x00763161) and AL != 0 (0x00763163/0x00763165), tests
  `geom[+0x2E] & 0xF000` (0x00763167-) for the early-out.
- 0x00767B40: the same pattern - null-tests the record EDI first (`CMP EDI,EBX` with
  EBX = 0 at 0x00767B4C, `JE` at 0x00767B52), stores AL to `[ESP+0x38]` (0x00767B6F), skips
  the early-out when the byte `[ESP+0x48]` is non-zero (`CMP [ESP+0x48],BL`,
  0x00767B6B/0x00767B73) or AL == 0 (0x00767B75), else tests `[ESI+0x2E]` (0x00767B79-).
  BL is 0 at 0x00767B6B: `XOR EBX,EBX` at 0x00767B4A and no write to EBX before 0x00767B6B
  (objdump), so the check is `CMP byte [ESP+0x48],0`, a force-style byte like the packer's
  `[ESP+0x3C]`.
- 0x00768470: ECX = `[arg+0x38]` (0x00768477, 0x0076847C); AL != 0 -> returns AL = 1 with
  `RET 0x20` at once (0x00768483-0x0076848C); AL == 0 -> continues at 0x0076848F.
- 0x00768580: ECX = `[ESI+0x0C]` (0x007685B1); AL != 0 -> jumps to 0x007686D0
  (0x007685BD); AL == 0 -> continues at 0x007685C3.
- 0x00769B60: ECX = ESI = `[EDI+0x1C]` (0x00769B71, 0x00769B74), not null-tested (only EDI
  is tested, at 0x00769B66); keeps AL in BL (0x00769B7F), then
  unconditionally writes `record[+0x00] = 0x01400000` (0x00769B81, no null test of ESI before it) and calls
  `0x00777F70(1)` (0x00769B7B-0x00769B87); BL == 0 -> calls `[[record+0x04]]+0x1C`
  (0x00769B97-0x00769B99 visible; the rest of the call was not disassembled in this run).
- 0x0076D200: when arg1 `[ESP+0x8]` is null and arg `[ESP+0x18]` (ESI) is non-null
  (0x0076D205/0x0076D216), calls it on ESI; AL == 0 -> returns EAX = -1 with `RET 0x1C`
  (0x0076D223 -> 0x0076D229-0x0076D230). The -1 is not specific to AL == 0: the same exit
  0x0076D229 is also reached when ESI is null (0x0076D218) and when AL == 1 but EBP
  (`[ESP+0x18]` loaded at 0x0076D208) is 0 (0x0076D225/0x0076D227).
None of the callers null-tests ECX in the instructions shown for 0x00768470,
0x00768580 and 0x00769B60 (0x00768477-0x0076847E, 0x007685B1-0x007685B6,
0x00769B71-0x00769B76; 0x00769B60 tests only EDI at 0x00769B66); 0x00763130 null-tests the
record at 0x0076313F (re/functions/0x00763130.md B1), 0x00767B40 at 0x00767B4C/0x00767B52
and 0x0076D200 at 0x0076D216.

C12. **unverified** - That 0x00768470 / 0x00768580 / 0x00769B60 / 0x0076D200 are further
buffer-data packers or binders (non-skinned geometry, particles, the record's first
allocation): only the call-site instructions above were read, not their bodies.

## Open questions

1. Can `record[+0x24]` be null while `record[+0x1C] > 0` (C5)? The resize 0x00777F70 is the
   writer of both fields (re/functions/0x00763130.md C10, pseudocode only); reading it at
   instruction level would settle it.
2. Is a chip's `+0x08` ever cleared while the chip stays in its slot (e.g. on device
   loss/reset, or when the ring manager 0x007829A0 frees and recreates a buffer)? If so,
   this check is what sends a static record back through a full re-pack. The release
   path `[[record+0x04]]+0x1C` and 0x007829A0 (in progress) would answer it.
3. What the callers 0x00767B40, 0x00768470, 0x00768580, 0x00769B60 and 0x0076D200 are
   (C12), and whether any of them runs per frame.
4. Settled (objdump, C11): BL is 0 at 0x00767B6B in 0x00767B40 (`XOR EBX,EBX` at
   0x00767B4A, EBX not written before 0x00767B6B), so `[ESP+0x48]` is a force-style byte
   like the packer's `[ESP+0x3C]`.

## Layout requests

For the shared header `GeometryBufferData` (proposal, same as re/functions/0x00763130.md):
- `+0x1C std::uint32_t streamCount` (unsigned; static_assert offset 0x1C).
- `+0x24` stream chip array: in a 64-bit clean header an explicit 32-bit handle
  (`std::uint32_t streamChipsHandle`) pointing at `streamCount` 32-bit chip handles,
  stride 4 (static_assert).

For `VBChip` (proposal):
- `+0x08` the vertex buffer as a 32-bit handle (`std::uint32_t vertexBufferHandle`),
  non-zero meaning "allocated" for this check.

Smaller callees worth their own slice: none (leaf). The neighbours worth one: 0x00777F70
(the stream-array resize that writes `+0x1C`/`+0x24`) and the release slot
`[[record+0x04]]+0x1C`, which decide when this check flips from 1 to 0.
