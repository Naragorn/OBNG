## Purpose

One call moves the character's phantom through the world for the time
`[arg1+8]` (read, 0x008AD82F). Order of one iteration (read, the addresses in
Control flow):

1. **Initial cast** (0x008AD8DD-0x008AD932): both collectors reset
   (count +0x14 = 0, early-out +0x04 = FLT_MAX 0x7F7FFFFF), then the phantom's
   virtual +0x30 with (&position, &castInput, castCollector, startCollector).
   `castInput.to` = position + `this+0x20`; `+0x10` = 0.01 (0x3C23D70A);
   `+0x14` = `this+0x5C` + `this+0x58`. When the cast collector holds hits:
   sort 0x008AF890, then 0x008ABD40 over its hits with `this+0x20`.
2. **Update manifold** (0x008AD987): `this` vtable +0x08 (startCollector,
   castCollector).
3. **Planes** (0x008AD990-0x008ADAB4): a plane array of 0x40-byte entries on
   the thread's Havok stack, capacity `this+0x64` + manifold size + 10; per
   manifold entry the virtual +0x0C (entry, &plane[i], elapsed time) and
   0x008AC3C0 (may append a further plane); a reserve for `this+0x64` more
   planes, through 0x008A6E40 (heap) when the stack capacity is short.
4. **Simplex solve** (0x008ADAB7-0x008ADD35): a status array of 0x10-byte
   entries on the thread's stack, the solver input filled (position 0,
   velocity `this+0x10`, `this+0x68` splatted, up `this+0x40`, remaining
   time, a minimum time step, planes, count), every listener's virtual +0x04
   (&manifold, &input) from last to first, then 0x008EC790 (input, output).
5. **Apply surface** (0x008ADD8D): 0x008AC6A0 (arg1, arg2) on `this`.
6. **Cast move** (0x008ADDD9-0x008ADF99): when the solved displacement
   differs from `this+0x20` by more than 0.001 in x, y or z: a second cast
   into the cast collector alone (start collector NULL); new contacts are
   announced to the listeners (virtual +0x08) and appended to the manifold;
   hits already in the manifold are dropped from the collector's front;
   with a hit left, 0x008AC530 moves the position towards the target by the
   first hit's fraction and returns the time used. Otherwise the whole
   displacement is taken (0x008AE0E2).
7. **End of iteration** (0x008ADFAA-0x008AE04E): `this+0x20` = the solved
   displacement, the remaining time reduced, both stack arrays released.

After the loop (0x008AE071-0x008AE08A): `this+0x10` = the solver's output
velocity, and the phantom's 0x008ABAC0 (&position, tolerance), called on
every path (read, 0x008AE08A). Per its rea-all pseudocode (not
instruction-checked) it always writes the phantom's position +0xA0..+0xAC,
and updates the AABB and the broad phase (shape vt+0x0C on `[phantom+0x14]`,
then 0x008DE950) only when `[phantom+0x08]` != 0 (derived, see the map,
group c).

**Clock:** this body reads no game clock and writes none (read). The solver
0x008EC790, 0x008AC6A0 and the virtual targets (this vt+0x08/+0x0C,
listener +0x04/+0x08, phantom vt+0x30) were not followed: **unverified** for
them. The body's only time input is
`[arg1+8]` (read, 0x008AD82F, 0x008ADA23). RDTSC runs at 0x008AD816,
0x008AD8BC, 0x008AD96D, 0x008ADAE4, 0x008ADD6D, 0x008ADDBD and 0x008AE0BB,
each only when the TLS monitor stream has room (TLS block +0x1A4 < +0x1A8),
and its low dword goes into that stream entry at +4 (read) - Havok's own
per-thread profiling stream, not the engine's time.

- The two collectors (arguments 3 and 4, owned by the caller 0x008902B0):

### (b) Other actors or references

- None addressed directly in this body (read: no access outside `this`, the
  phantom, the arguments, the TLS block, the thread memory and the stack).
- **Other bodies are written by the callee 0x008AC6A0 ("StApplySurf")**
  (derived from rea-all pseudocode of 0x008AC6A0, not instruction-checked):
  for each manifold entry whose root collidable has type byte +0x18 == 1 and
  whose entity byte +0x92 == 0, it computes an impulse from the relative
  velocity, the character's velocity (`this+0x10..+0x18`), `this+0x6C` and
  `this+0x70`, calls the listeners' +0x14 and calls the body's motion virtual
  +0x60 (&impulse, &point) - a point impulse on the touched rigid body, i.e.
  the character pushes what it touches. Its listener +0x10 call runs when a
  property key 0x1300 is found on the body. Which game objects those bodies
  belong to (other actors' controllers are phantoms, not entities) is
  **unverified**.
- Listener callbacks: +0x04 (before the solve, with &manifold and &solver
  input, which a listener may modify) and +0x08 (contact added) - **not
  followed**; their targets depend on the listener objects at `this+0x80`.

### (e) Heap and the thread's stack

- Two blocks per iteration: planes `(this+0x64 + count + 10) * 0x40` + 0x10
  rounded down to 16 (0x008AD9D2-0x008AD9DA), status array sized by the
  extracted plane count `[ESP+0x20]` plus `this+0x64`, plus 1, times 0x10,
  rounded (0x008ADAFA-0x008ADB7B; not by the manifold size) (read). Each
  comes from the thread's Havok stack unless it would pass the stack end
  (+0x2C, 0x008AD9E3, 0x008ADB84); then the memory object's vtable +0x0C is
  called instead (0x008AD9EF, 0x008ADB92) (read). What that call allocates
  from is not in this export: **unverified**, it may be heap. Released in
  reverse at 0x008ADFCD/0x008AE01B (stack top reset), with vtable +0x10 when
  the block equals `memory+0x28` (read).
- Heap is therefore not limited to the growth calls. Known paths: the
  stack-overflow call above (target unknown), the frees through 0x008A75D0
  (0x008ADFFF, 0x008AE04E) (read), and callees such as 0x008AC3C0 (grows
  via 0x008A6EE0, pseudocode) and the unfollowed virtuals may allocate as
  well (**unverified**).
- Growth: 0x008A6E40 (grow the plane array; rea-all pseudocode: 0x008A7560
  allocate, 0x008B1890 copy, 0x008A75D0 free the old block when owned) and
  0x008A6EE0 (grow the manifold by doubling, same calls). 0x008A75D0 frees
  to the thread memory's free lists, or - when the size > 0x2000 or
  `[mem+0x30]` == 0 - through `[mem+0x10]`'s vtable +0x14 (rea-all
  pseudocode), a shared allocator: **unverified** whether it locks.
- The plane array is freed by 0x008A75D0 at 0x008AE04E only when its flag
  word lost bit 31, which only the grow 0x008A6E40 does (its pseudocode
  keeps bit 30 and writes the capacity) (derived).
- The status array's free (0x008ADFFF) runs when `[ESP+0x138]` has bit 31
  clear; this body sets the bit at 0x008ADBF7 and never clears it, and that
  slot lies at solver input +0x68, so whether 0x008EC790 writes it is
  **unverified**.
