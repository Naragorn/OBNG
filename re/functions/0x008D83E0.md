## Purpose

For each of `count` pairs in an array of 8-byte pairs, it reads a signed type byte at `+0x04` of both pair
members, picks a 4-byte pointer from a table of the `this` object at index `typeA * 8 + typeB`, and calls that
object's vtable slot `+0x0C` with a pointer to the pair (read, 0x008D83F3-0x008D8409). Its own code writes no
memory other than its stack pushes (read: the only memory operands are loads and PUSH). All effects of "removing
a pair" lie in the per-pair callee, which this map does not follow.

From the call site in 0x008DE950 (export/actor-movement/0x008DE950/asm.s): ECX = `[world+0x68]` (0x008DEAD3),
arguments are two values from the caller's stack (0x008DEAD1/0x008DEAD2) (read). So when called from the
phantom's broad-phase update, `this` is the world's broad-phase dispatcher (derived from 0x008DEAD3 and the
0x008DE950 map).

## Calling convention and parameters

- `__thiscall`: `this` in ECX, copied to EBX at 0x008D83E6 (read). Ghidra also says `__thiscall` (pseudo.c).
- Stack args: `[ESP+4]` at entry = `pairs` (loaded into ESI at 0x008D83EB as `[ESP+0xC]` after two pushes);
  `[ESP+8]` at entry = `count` (loaded at 0x008D83E0) (read).
- Callee cleans: `RET 0x8` at 0x008D8415 (read) - two 4-byte arguments.
- Saves EBX (0x008D83E5), ESI (0x008D83EA), EDI (0x008D83EF); restores them at 0x008D8412-0x008D8414 (read).
  EBP is not used. No locals, no frame.
- Return value: none set. EAX holds whatever the last callee left, or `count - 1` when the loop is skipped
  (read: EAX last written at 0x008D83E4 on the skip path). Callers using EAX was not checked (unverified).
- The per-pair callee is called with ECX = table entry and one pushed argument (the pair pointer, 0x008D8408);
  the caller does not adjust ESP after the call (read), so the callee pops its own argument
  (thiscall, `RET 4`) (derived from the balanced POPs at 0x008D8412-0x008D8414 and RET 0x8).

## Control flow

|---|---|---|---|---|
| 1 | Skip the loop | `count - 1 < 0` (signed, SF after DEC): `count <= 0`, except `count == INT_MIN` where DEC wraps to 0x7FFFFFFF and the loop runs | JS 0x008D83E8 -> 0x008D8414 | count = 0, count < 0: no callee call, RET 8 |

## Claims

1. 0x008D83E0 is `__thiscall (this=ECX, pairs, count)` and returns with `RET 0x8` - read (0x008D83E6, 0x008D83EB, 0x008D83E0, 0x008D8415).
2. Each pair is 8 bytes holding two pointers; the loop walks them in increasing order - read (0x008D83F3, 0x008D83F5, 0x008D840C).
3. The callee for a pair is the object at `this + (typeA*8 + typeB)*4`, where typeX is the signed byte at `+0x04` of the pair's X pointer - read (0x008D83F8-0x008D8403).
4. The callee is called through its vtable slot +0x0C with ECX = the object and the pair pointer as the only argument - read (0x008D8406-0x008D8409).
5. When `count <= 0` (and count != INT_MIN) no callee is called - read (0x008D83E4, 0x008D83E8).
6. The function's own instructions write no memory but its own stack - read (whole body).
7. No globals, TLS, heap or clock are touched by its own instructions - read (whole body; meta.json data_refs empty).
8. There is no bounds check on the type bytes - read (no compare between 0x008D83F8 and 0x008D8403).
9. When called from 0x008DE950, `this` is `[world+0x68]` - read (0x008DEAD3 in export/actor-movement/0x008DE950/asm.s).
10. The callee pops its own one argument - derived (no ESP adjustment after 0x008D8409; balanced POPs and RET 0x8).
11. The dispatcher's table starts at offset 0, so the dispatcher has no vtable at +0 - derived (claim 3, no displacement at 0x008D8403).
12. The sibling 0x008D8370 is the add-side: same table index, slot +0x08, behind a vt+0x00 filter call on its third argument whose result byte must be non-zero - read (0x008D83AC, 0x008D83AE, 0x008D83C9 in export/controller-narrowphase/0x008D8370/asm.s).
13. Pseudo.c and asm.s agree (parameter order, loop, index); pseudo's `param_3 + -1 > -1` test equals DEC/JS, and it keeps the counter in the parameter where the asm uses EDI - read.
14. The vt+0x0C targets remove collision agents / overlap entries in shared tables - unverified (only the 0x008DE950 map's "Up" note and the seed name).

## Could two threads run this at once for two different phantoms?

Its own code: yes - it only reads the dispatcher table and the pairs and writes only its stack (claims 6, 7).
The call as a whole: **not established, and not safe as the code stands**. What stands against it:
- The per-pair callee vt+0x0C (0x008D8409) is unfollowed; it is where pairs are removed from shared state
  (unverified what and how, claim 14).
- Two different phantoms can share a pair partner (both overlap the same body, or they overlap each other, in
  which case the same pair can appear in both threads' lists) - derived from the pair structure; that the
  callee then writes the partner's data is unverified.
- Its caller 0x008DE950 increments `[world+0x88]` without LOCK and updates the shared broad phase before calling
  this (re/functions/0x008DE950.md, in progress; knowledge/actor-frame-map.md, second slice) - so the path that
  reaches it already serialises on unguarded shared state.
