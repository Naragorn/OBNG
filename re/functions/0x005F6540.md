## Purpose

`this` (the detector) computes how well it detects `target` (arg2) and returns that level as an int. In order:

1. **Cache** (0x005F6574-0x005F65C2): asks its own process `this->process(+0x58)->vt+0x3B0(target)` for a stored
   entry; if one exists, `*arg3 = entry+0x08` (byte) and the cached level = `entry+0x0C`. `target->vt+0x154()` is
   checked first: when it returns 0, the function returns -1 (R 0x005F65AE -> 0x005F70BF). Only when it is non-zero,
   arg1 == 0 and an entry exists with level != 0x7FFFFFFF does it return the cached level without computing
   (R 0x005F65B4-0x005F65C2).
2. **Inputs** gathered from both actors (0x005F65C8-0x005F6883): distance (0x004D7E90 GetDistance), the target's light
   amount (`target->process->vt+0x3AC(target,0)`), scaled when the detector's AV 0x29 > 0, line of sight
   (0x005F2820), the target's boot weight (0x005F3B50), moving / running flags (target process vt+0x2C0 bits 0xF and
   0x200), sneaking (0x005E0550), the detector's underwater test (0x005E06C0), the detector's sleep state
   (`process->vt+0x36C() == 9`), the target's cell flag bit 0 (0x004C97F0), both actors' luck-modified Sneak skill
   (AV 0x1F with AV 7, 0x00547B90), the detector's AV 0x2D, the target's AV 0x2F and 0x2E.
3. **Formula**: target AV 0x2F > 0 or target AV 0x2E >= 100 give -100 (R 0x005F6854, 0x005F6879); otherwise the cdecl
   16-argument function 0x005463F0 computes it (R 0x005F6883-0x005F68E3). Both -100 stores jump to the close-bonus
   block at 0x005F68E7 (R 0x005F685C, 0x005F6881), so step 4 applies to -100 as well.
4. **Close bonus**: when distance <= 900.0, `level = ftol(target->process->vt+0x35C() + level)` (R 0x005F68E7-0x005F690E).
5. **Store**: when arg1 == 0 or arg5 != 0, and `this` is not the player, the result goes back into the detector's
   process with `vt+0xA8(target, level>0 ? 3 : 0, lineOfSight, level)` (R 0x005F6912-0x005F6950).
6. **Debug overlay** (0x005F6952-0x005F70BD): when the byte 0x00B3BD9A is set and the target filter matches and the
   selected reference 0x00B333B4 is `this`, 17 text lines with every input are drawn (0x0057B8E0).

It reads no clock and no frame time (R: data.json's 15 data addresses contain no time global; the callees' bodies
are not followed for this, U for them).

## Claims

- C1 (R, 0x005F6540-0x005F70E3): `__thiscall`, six stack args, `RET 0x18`, return value in EAX.
- C2 (R, strings at 0x005F6A19, 0x005F706E): the function computes the detection level of `this` against arg2; the
  final debug line names `this` first (0x005F7068) and the target second (0x005F7060).
- C3 (R, 0x005F65AE, 0x005F65B4-0x005F65C2): when target->vt+0x154() is non-zero (checked first, else -1), arg1 == 0
  and the process holds an entry with level != 0x7FFFFFFF, the stored level is returned with no computation.
- C4 (R, 0x005F65D6): every computation (past the cache) increments the global 0x00B333C0 with a plain `ADD`; two
  threads running this function would lose counts (D). For the parallel map this is a shared write.
- C5 (R, 0x005F6912-0x005F6950): the result is stored back into `this->process` only when arg1 == 0 or arg5 != 0 and
  `this` != g_thePlayer.
- C6 (R call, D field): when X = `this->vt+0x330()` is non-null (R 0x005F665C) and 0x006135F0(X) == target (R
  `CMP EAX,EBP` 0x005F6673), 0x00612810 is called on X with the int at B+0x20 (R 0x005F6660-0x005F668A; set to 3 at
  0x005F663F and passed by pointer to 0x005F2820). That this stores to X+0x180, and that 0x006135F0 returns the data of
  X+0x40's first non-empty node (possibly unlinking empty nodes), is D from rea-all pseudocode of 0x00612810 and
  0x006135F0 only: a write into another object hanging on `this`, and possibly a write on its list.
- C7 (D from C4-C6 and group (b)): the target is only read; the writes are the global counter, the detector's own
  process entry and the +0x180 field. A per-detector parallel run would need the counter made per-thread or atomic,
  and is U until 0x005F2820 and the process virtuals are read.
- C8 (R, 0x005F6604-0x005F6629): the detector's AV 0x29 is only tested for > 0; its value is not used; the light is
  then multiplied by [0x00B37A50] and clamped to 100. That AV 0x29 is Night Eye is U (actor-value numbering not
  checked against a source).
- C9 (D, rea-all 0x9828c0.c and every use here: called right after an FPU result, EAX used as int,
  0x005F661B-0x005F6620): 0x009828C0 is the CRT float-to-int conversion (_ftol), not a random generator.
  `knowledge/render-thread-outside-the-pass.md` (line 222, 371) and `docs/performance-backlog.md` (line 599) call it
  "a random draw"; that reading is wrong if C9 holds - the "draw against 50 and 10" there should be re-read as an
  ftol of a float compared against 50 and 10. Flagged for that file's owner.
- C10 (R, 0x005F66EB): the target's process is dereferenced without a null test after the test at 0x005F66CA;
  0x005F65DD and 0x005F68F8 do the same. A target without a process would fault (D).
- C11 (R 0x005F675E-0x005F6760 vs. 0x005F6F7D): the underwater flag is computed on `this` (ECX = EBX) but the debug
  line prints it with the target's name (ECX = EBP). The instructions win: the input to the formula is the detector's.
- C12 (R, data.json): the constants are 0.0f (0x00A2FAA8), 0.875f (0x00A6E688), 900.0 (0x00A6C820, f64), 3.0
  (0x00A30E48, f64); 0x00B37A50's image bytes are 0, but the 32 zero bytes look like uninitialised .data/.bss, so its
  run-time value (and whether the light becomes 0 when AV 0x29 > 0) is U; settled by a writer xref or a memory read in
  game.
- C13 (R, call sites): both slice callers (0x00603CA0 at 0x00604F68, 0x00603500 at 0x00603B01) pass arg1 = 0 and
  target = g_thePlayer: in the high update an actor computes its detection of the player.
- C14 (R, data.json data refs): no time or clock global is read or written by this body.
