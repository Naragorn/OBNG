## Purpose

Decides whether one scene object (arg1: a geometry or a node) is within the reach of
one ShadowSceneLight (`this`) whose source light is arg2, and returns that as a bool
in AL. Three outcomes, in this order:

1. arg2 is null: false (0x007D2EAD-0x007D2EB6).
2. arg2's RTTI (its virtual slot +4) is `NiRTTI_NiDirectionalLight` 0x00B3FCFC: true,
   without touching anything else (0x007D2EC2-0x007D2ED0).
3. Otherwise the object's bound sphere (arg1 +0x20..+0x2C, copied to the stack at
   0x007D2EDE-0x007D2EFB) is tested in one of two ways, chosen by `this+0x14C`:
   - `this+0x14C != 0` (the plane path): for every plane i in 0..5 whose bit
     `1 << i` is set in `this+0x1B0`, `WhichSide(bound, this+0x150+16*i)`; a 2 (wholly on
     the negative side) makes the result false but the loop goes on; a 1 (wholly on
     the positive side) clears bit i in `this+0x1B0`; a 0 changes nothing. Returns true
     when no tested plane answered 2.
   - `this+0x14C == 0` (the distance path): `dist = sqrt(|arg2.pos(+0x88..+0x90) -
     centre|^2)`, returns `arg2+0xF8 > dist - radius` (false on equality and on NaN).
     The plane mask is not touched.

The plane path does not look at arg2's position or +0xF8 at all, and the distance
path does not look at the planes.

Subsystems touched, in order: NiRTTI (one virtual call on arg2), the bound/plane math
(0x0047DA70, up to six calls) or the CRT square root (0x00982C30, one call). No clock
reads or writes, no globals besides the RTTI address compare, no locks, no allocation.

Mask meaning, from the callers' instructions: the six planes and the mask form one
block (+0x150..+0x1AF planes, +0x1B0 mask), constructed together in the
ShadowSceneLight constructor (six calls of the plane constructor 0x00716DB0 from
0x007D6112, then `MOV [ESI+0x1B0],0x3F` at 0x007D6137). 0x007D59E0, the recursive
scene walk, saves the mask before calling this function (0x007D59F4/0x007D59FF) and
writes it back on every exit after the call (0x007D5A7F, 0x007D5AD6, 0x007D5B07)
around the recursion (0x007D5A74, 0x007D5ABD) (read). Derived from that save/restore
shape, not read: a cleared bit means "the current subtree's bound is wholly on the
positive side of plane i, its children need not test plane i" and the clearing is
undone when the walk leaves that subtree - the shape of a hierarchical frustum cull
(an active-plane mask over six culling planes). That Gamebryo calls it
`NiFrustumPlanes::m_uiActivePlanes` is **unverified** (memory of the Gamebryo API, no
retrieved source). 0x007C6100 calls it without any save or restore of +0x1B0 (see C18
and Open questions).

## Calling convention and parameters

- `__thiscall`: ECX = `this`, moved to EBX at 0x007D2EAB and used only through EBX
  (read). Both callers load ECX with the ShadowSceneLight: 0x007C61B8 `MOV ECX,ESI`
  with ESI = the list node's data `[EBP+0x8]` (0x007C6197) from the ShadowSceneNode's
  light list `[EDI+0xE8]`, where EDI is arg2 of 0x007C6100 or a fallback node from
  0x00707530/0x007B4280 (0x007C6124-0x007C6167); 0x007D59E9 `MOV EBP,ECX` keeps the caller's own `this`
  (read; that these objects are ShadowSceneLights is derived from
  knowledge/shadow-light-list-remove.md, which reads the list element type).
- Two stack arguments, callee cleans: `RET 0x8` on all four exits (0x007D2EB6,
  0x007D2ED0, 0x007D2F5A, 0x007D2FE6) (read).
  - arg1 at entry [ESP+4] (read as [ESP+0x28] at 0x007D2EDA after SUB ESP,0x1C and two
    PUSHes): the object whose bound is tested. 0x007C6100 passes P, its first cdecl
    argument (0x007C61B3 `MOV EAX,[ESP+0x28]` = the caller's [ESP+0x24] after one push);
    0x007D59E0 passes its own stack argument EDI (0x007D59FB, 0x007D5A0A).
  - arg2 at entry [ESP+8] (read as [ESP+0x2C] at 0x007D2EA5 into ESI): the source
    light. 0x007C6100 passes `*FUN_00405AD0(&tmp)` (0x007C61AB-0x007C61B2, the
    NiPointer copy of the light's +0x100 per knowledge/shadow-light-list-remove.md);
    0x007D59E0 passes `[EBP+0x100]` (0x007D5A03-0x007D5A09) (read).
- Return: AL, a bool (0 or 1): `XOR AL,AL` 0x007D2EB0, `MOV AL,1` 0x007D2ECA,
  `MOV AL,[ESP+0x34]` 0x007D2F4F, `MOV AL,[ESP+0x2C]` 0x007D2FDD. The upper 24 bits of
  EAX are not defined by the function on the last three exits (EAX holds the RTTI
  pointer's upper bytes, WhichSide's return or the FNSTSW word) - callers test AL only
  (0x007C61C7 `MOV BL,AL`/0x007C61F7 `TEST BL,BL`; 0x007D5A10 `TEST AL,AL`) (read).
- Registers: EBX, ESI, EDI, EBP saved and restored where used (PUSH/POP pairs at
  0x007D2EA3/0x007D2EA4, 0x007D2F01/0x007D2F02); ECX, EDX, EAX clobbered (read).
- Stack frame (ESP0 = ESP at entry):
  - ESP0-0x1C..-0x14: dx, dy, dz (distance path, FSTP at 0x007D2F67/75/83).
  - ESP0-0x10..-0x04: the bound copy {centre x, y, z, radius} (MOVs 0x007D2EE4-0x007D2EFB);
    its address is `this` for 0x0047DA70 (`LEA ECX,[ESP+0x20]` at 0x007D2F22 with
    ESP = ESP0-0x30 after PUSH EBX/ESI/EBP/EDI and the argument push).
  - ESP0+4 (arg1's slot): float scratch on the distance path (0x007D2FA3, 0x007D2FB0,
    0x007D2FC1).
  - ESP0+8 (arg2's slot): its low byte is the result byte (written 0x007D2EF2,
    0x007D2F30, 0x007D2FB8, 0x007D2FD8; read 0x007D2F4F, 0x007D2FDD). arg2 itself
    stays in ESI on the distance path (ESI is overwritten only in the plane loop,
    0x007D2F10).
- x87: the plane path does no x87 work itself; the distance path leaves the x87 stack
  balanced (3 FLD/3 FSTP, then 3 FLD + 2 duplicate-FLD, 2 FMULP + FMUL, 2 FADDP leave
  one value, FSTP/FLD pairs, FCOMPP pops the last two) (derived from the instruction
  stack effects).

## Control flow

Each row is a flow a rebuild test must exercise.

| id | address | instruction | condition | effect |
|---|---|---|---|---|
| B1 | 0x007D2EAD | `JNZ 0x007D2EB9` (after `TEST ESI,ESI` 0x007D2EA9) | arg2 == 0 | return false (0x007D2EB0 `XOR AL,AL`, `RET 8` 0x007D2EB6); no virtual call, no write |
| B2 | 0x007D2EC7 | `JNZ 0x007D2ED3` (after `CMP EAX,0xB3FCFC`) | arg2->GetRTTI() == 0x00B3FCFC | return true (0x007D2ECA `MOV AL,1`, `RET 8` 0x007D2ED0); arg1 not read, mask untouched |
| B3 | 0x007D2EFF | `JZ 0x007D2F5D` (flags from `CMP [EBX+0x14C],0` at 0x007D2ED3; only MOVs in between) | this+0x14C == 0 | distance path (B8); else plane loop (B4-B7) |
| B4 | 0x007D2F1F | `JZ 0x007D2F44` (after `TEST [EBX+0x1B0],ESI`) | bit i of the mask is clear | skip plane i (no WhichSide call) |
| B5 | 0x007D2F2E | `JNZ 0x007D2F37` (after `CMP EAX,2`) | WhichSide == 2 | result byte = 0 (0x007D2F30), `JMP 0x007D2F44` (0x007D2F35): next plane, mask bit i kept |
| B6 | 0x007D2F3A | `JNZ 0x007D2F44` (after `CMP EAX,1`) | WhichSide == 1 | `NOT ESI; AND [EBX+0x1B0],ESI` (0x007D2F3C/0x007D2F3E): clear bit i; any other value (0) falls to the increment unchanged |
| B7 | 0x007D2F4D | `JC 0x007D2F10` (after `CMP EDI,6`) | i < 6 (unsigned) | next plane; at i == 6 return the result byte (0x007D2F4F, `RET 8` 0x007D2F5A) |
| B8 | 0x007D2FD6 | `JZ 0x007D2FDD` (after `FCOMPP` ST0 = [arg2+0xF8], ST1 = dist - radius; `FNSTSW AX`; `TEST AH,0x41`) | C0 and C3 both clear, i.e. range > dist - radius | keep true; otherwise (range < d, range == d, or unordered/NaN, all set C0 or C3) result byte = 0 (0x007D2FD8); return at 0x007D2FE6 |

Test flows the rebuild needs from these: null arg2; directional arg2 (with a null
`this+0x14C` and with a non-null one, to prove neither is read); the plane path with
mask 0 (returns true, nothing called); each plane's 0, 1, 2; a 2 on an early plane
followed by a 1 on a later plane (result false, the later bit cleared - the
non-early-exit flow); mask with gaps (only set bits tested); the distance path with
range above, equal to and below dist - radius, and a NaN position or range.

## Claims

C1. **read** - Null arg2 returns false before any other read (0x007D2EA5-0x007D2EB6).

C2. **read** - When arg2's virtual slot +4 returns 0x00B3FCFC the function returns
true without reading arg1, `this+0x14C`, the planes or the mask
(0x007D2EB9-0x007D2ED0). That 0x00B3FCFC is `NiRTTI_NiDirectionalLight` comes from
re/symbols/xobse.csv (obse/obse/NiRTTI_1_2_416.inl:145) and meta.json's name; derived:
a directional source light reaches every object.

C3. **read** - arg1's four dwords +0x20, +0x24, +0x28, +0x2C are copied to
ESP0-0x10..-0x04 before the branch on `this+0x14C` (0x007D2EDA-0x007D2EFB), and the
copy, not arg1, is what 0x0047DA70 receives as `this` (`LEA ECX,[ESP+0x20]` 0x007D2F22,
ESP = ESP0-0x30). Derived: writes to `this+0x1B0` cannot alter the bound during the
loop.

C4. **read** - The plane path visits i = 0..5 in ascending order (EDI from 0,
`ADD EDI,1`, `CMP EDI,6`, `JC`), plane address `this+0x150+16*i` (EBP), bit `1 << i`
(`MOV ESI,1; MOV ECX,EDI; SHL ESI,CL` 0x007D2F10-0x007D2F17).

C5. **read** - The mask is re-read from memory for every plane (`TEST dword
[EBX+0x1B0],ESI` at 0x007D2F19 inside the loop), and each iteration writes at most
bit i (0x007D2F3E with ESI = ~(1 << i)).

C6. **read** - On WhichSide == 2 the result byte becomes 0 and the loop continues with
the next plane (0x007D2F30, 0x007D2F35 `JMP 0x007D2F44`); later planes are still
tested and still have their bits cleared on 1.

C7. **derived** (from C4, C5, the "no globals, no callees" contract of 0x0047DA70 in
re/functions/0x0047DA70.md, and C3) - The six plane tests are independent: plane i's
outcome depends only on the bound copy, plane i and bit i, and iteration i writes
only bit i. So a batched rebuild that evaluates WhichSide for every set bit (any
order, or all at once) and then applies `mask &= ~ones` and `result = (twos == 0)`
yields the same mask and the same return value as the loop, provided WhichSide's
arithmetic is reproduced bit for bit (the precision conditions in
knowledge/bone-palettes.md "Sphere against plane"). An early-exit rebuild (stop at
the first 2) would **not** be equal in general: it would leave bits of later planes
set that the original clears (C6).

C8. **read** (0x007D59E0 instructions, objdump) - 0x007D59E0 reads `[EBP+0x1B0]` into a
stack slot before the call (0x007D59F4, 0x007D59FF) and stores that slot back to
`[EBP+0x1B0]` on all three exits after the call (0x007D5A7F, 0x007D5AD6, 0x007D5B07),
including the exit taken when this function returns false (0x007D5A12 `JE 0x007D5B02`
-> 0x007D5B07). 0x007D59E0 reaches the save and the call only when
`DAT_00B42F48 != 0` (0x007D59E1 `CMP [0x00B42F48],0` / `JNE`; otherwise `XOR AL,AL` /
`RET 4` at 0x007D59F1) (read, as reported by the refutation round; 0x007D59E0's body is
not in this slice's export). Derived: on that path the bits this function clears live only while
0x007D59E0 recurses into the children of the object that passed (0x007D5A74,
0x007D5ABD); on a false return they are discarded, so the non-early-exit of C6 has no
lasting effect through 0x007D59E0. That the mask therefore means "planes still to test
in this subtree" (a hierarchical-cull active-plane set) is **derived** from this
save/restore pattern, not read.

C9. **read** (0x007C6100 instructions, objdump 0x007C6100-0x007C6220) - 0x007C6100
never reads or writes `+0x1B0` of the light in its own body. It calls this function
only when 0x007C5750(P) returns AL != 0 (0x007C6170-0x007C6177; otherwise it returns
at 0x007C618C without any call) and `[EDI+0xE8]` is non-null (0x007C6195), where EDI is
arg2 or a fallback node from 0x00707530/0x007B4280 (0x007C6124-0x007C6167); then once
per entry of that light list whose data `[listnode+8]` is non-null
(0x007C618D-0x007C6209), and calls `0x007D5790` (AddGeometry) with P when AL != 0
(0x007C61F7-0x007C6202). Derived: within 0x007C6100's own body a bit cleared by one
geometry's test stays cleared for the next geometries tested against the same light;
whether 0x007C5750 or 0x007D5790 resets `+0x1B0` is **unverified** (their bodies were
not read; see C18 and Open questions).

C10. **read** - The distance path computes, with arg2 = L and the bound copy {c, r}:
`dx = L.x - c.x`, `dy = L.y - c.y`, `dz = L.z - c.z`, each stored to single
(0x007D2F5D-0x007D2F83); `s = (dy*dy + dx*dx) + dz*dz` (FMULP ST2 = dx*dx at
0x007D2F95, FMULP ST3 = dy*dy at 0x007D2F99, FADDP ST2 at 0x007D2F9D, FMUL ST0 = dz*dz
at 0x007D2F9F, FADDP at 0x007D2FA1); only the final sum `s` is stored as a single
(0x007D2FA3) - the products and the partial sum are rounded according to the x87
precision control, not by a store (exact single roundings only under the 24-bit
control word, C12); `q = sqrt(s)` via
0x00982C30 (argument and result in ST0), stored to single at 0x007D2FB0;
`d = q - r` stored to single at 0x007D2FC1; result = `!(C0 || C3)` of
`FCOMPP` with ST0 = L+0xF8, ST1 = d, i.e. true exactly when `L+0xF8 > d`.

C11. **derived** (from C10 and the Intel x87 FCOM condition-code table as quoted for
FCOMPP in re/functions/0x0047DA70.md) - Equality returns false; an unordered compare
(NaN in d or in L+0xF8) sets C3, C2 and C0 and returns false.

C12. **derived** (from C10, and from the precision-control quote in
knowledge/bone-palettes.md "Sphere against plane") - Under the game's 24-bit precision
control the three single stores after FMUL/FADDP/FSUB change nothing in range;
whether 0x00982C30's square root rounds the same way as a C++ `sqrtf` is
**unverified** (its callee 0x00991B88 was not read).

C13. **read** - The distance path does not touch `this` beyond the `+0x14C` compare,
and the plane path does not read arg2 beyond its RTTI (no access through ESI after
0x007D2EC0 on the plane path; ESI is reused as the bit at 0x007D2F10).

C14. **read** (objdump 0x00982C30-0x00982C43) - 0x00982C30 is `SUB ESP,0xC; FST qword
[ESP]; CALL 0x00991B88; CALL 0x00982C4D; ADD ESP,0xC; RET`: it takes its argument in
ST0 and returns in ST0 (consistent with the FLD before and the FSTP after the call
here). It is called from 230 sites in .text (objdump sweep, `call 0x982c30`). That it
is the CRT's x87 `sqrt` intrinsic helper (`_CIsqrt`) is **unverified** - the name

C15. **read** - The function reads no global besides comparing against the address

## Addendum 2026-10-30 (rounding control an input)

**The control word at the call site.** The shadow walk 0x007D59E0 calls this
function with FCW **0x0C7F** - precision 24 bits, rounding control = truncate
(measured: FXSAVE at the walk's entry, artifacts/shadow/obng-range-walk-routed/
20261030-131826/OBNG.log). Neither function loads a control word (read: no
FLDCW/FNINIT/FLDENV/FXRSTOR in either asm.s), so the distance path's FSUB,
FMUL, FADDP and every FSTP float round under the caller's mode, and the plane
path's WhichSide calls run under it too. On the garbage-sized scene-root bound
of that run the sum of squares stores as +inf at nearest (AL 0) and as FLT_MAX
under truncate (AL 1, the 108 geometries the original added).

**The square root (C12, C14 settled).** Read with objdump in the reference
Oblivion.exe (md5 cdd2f0c5eff198d4f26b7b5b54ce4930): 0x00982C30 stores its
argument and calls 0x00991B88 and 0x00982C4D; 0x00982C4D saves the control word
(FSTCW 0x00982C4E) and, unless it is 0x027F, calls 0x00991B15, which loads
`(word & 0x300) | 0x7F` (0x00991B19..0x00991B27): the caller's precision,
**round to nearest**, every exception masked. FSQRT runs at 0x00982C6C; the
saved word is loaded back at 0x00991BA6 (flag [0x00BA9DDC] non-zero) or
0x00991BD0 (flag zero and the saved word's precision mask set, as in 0x..7F).
So the root is FSQRT at 24 bits, round to nearest, under every caller mode;
only the store at 0x007D2FB0 rounds under the caller's mode (exactly, for a
24-bit root). The emulator cases of 0x007D2EA0.json model it with a plain
FSQRT stub at fpcw 0x007F, which is the same there (derived) and would not be
under another mode.

**The mode is an input of the rebuild.** `DifferencePc24`, `SumOfSquaresPc24`
and `Distance` take `which_side::X87Rounding`; the engine shape
`IsInRange(self, object, source, mode, testPlane, squareRoot)` and
`WhichSidePort{mode}` carry it to the plane path; no default
(src/engine/render/ShadowSceneLight_IsInRange{Logic,}.h). The walk takes it
once per walk in `LightValues::rounding` (ShadowLightRangeWalkLogic.h); the
plugin's shadow and route read it with FNSTCW at the walk's entry.

**Emulator cases per mode** (tools/difftest/cases/0x007D2EA0-rounding.json from
tools/difftest/generators/0x007D2EA0-rounding.py, which replaces the two
hand-made cases of the first reproduction; results
tools/difftest/expected/0x007D2EA0-rounding.json, measured in Unicorn
2026-10-30): G1 (the garbage bound of the game run), D1..D15 but D6, M1..M4
(a tie and a negative tie in the differences, an exact zero difference - -0
under down -, a rounded sum of squares) and P1 (the plane path with
WhichSide's own bytes, planes whose answers depend on the mode), each at fpcw
0x007F, 0x047F, 0x087F and 0x0C7F - 80 runs, 20 per control word. The square
root is the game's own: the stub at 0x00982C30 jumps to a logging wrapper that
calls the CRT bodies 0x00982C4D..0x00982CE9 and 0x00991B15..0x00991BD4, taken
from the reference executable by emulate.py's new "image" ranges (no CRT bytes
in the repository; the run needs OBNG_ORACLE_EXE or --image); WhichSide is an
"image" stub of its 92 bytes, traced. D6 is left out: its NaN sum takes the
CRT's error path 0x00991AB7, which calls further into the CRT than the image
ranges cover. The rebuild equals the original in all 80 runs - AL, GetRTTI
calls, WhichSide's plane addresses, every mask write, the mask afterwards, dx,
dy, dz, s and q bit for bit (tests/ShadowSceneLight_IsInRangeTest.cpp,
DifferentialRounding); 28 of the 60 directed-mode runs differ from the same
inputs at nearest. State: verified (emulator) under the four rounding controls
at precision 24, with the CRT's square root; in the game, the rebuild-first
shadow run under 0x0C7F is the next check (not run).
