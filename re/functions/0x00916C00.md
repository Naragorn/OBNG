## Purpose

A convex shape's support-point query: given a direction `d` (3 floats), it
walks the shape's vertices stored as blocks of four in structure-of-arrays
form (per block 0x30 bytes: four x, four y, four z), computes `dot(d, v)` for
four vertices at a time with SSE, keeps the running maximum, and writes the
vertex with the largest dot product plus its vertex index (packed into the w
word with `| 0x3F000000`) to the output vector. It is a leaf: no calls, no
globals, no heap. It is a shape query used by the convex-convex (GSK)
narrow phase, not an agent and not a MOPP walk (derived from the
instructions below plus the sampler context in knowledge/threading.md
line 178 and knowledge/render-thread-outside-the-pass.md line 126-127,
where 0x0093C690 / 0x0093F250 are the GSK feature walk; the caller edge is
**unverified** - meta.json lists no callers, consistent with an indirect
call).

  - `[EBP+0xC]` = `float* out` (16 bytes written at 0x00916D75, 0x00916D7B,
    0x00916D82, 0x00916D8B) (read).
- Returns void in effect; EAX at return holds `index | 0x3F000000`
  (0x00916D85) - whether a caller uses EAX is **unverified**.
- Frame: `PUSH EBP; MOV EBP,ESP; AND ESP,0xFFFFFFF0; SUB ESP,0x14`, then
  EBX/ESI/EDI pushed (0x00916C00-0x00916C0E). After the pushes `[ESP+0x10]`
  is 16-byte aligned (derived: aligned base - 0x14 - 0x0C = base - 0x20), which
  the `MOVAPS [ESP+0x10],XMM0` at 0x00916CA2 needs.
- Locals: `[ESP+0xC]` 4-byte scratch for moving a float between integer,
  x87 and SSE registers; `[ESP+0x10..0x1F]` the four dot products of the

## Control flow

Index arithmetic: ECX starts at 3 (0x00916C68) and grows by 4 per block
(0x00916D4C); a winner in lane L sets EAX = ECX - 3 + L, i.e.
`index = 4*block + L` (0x00916CF1, 0x00916D18, 0x00916D30, 0x00916D39)
(read). The running maximum XMM4 starts as splat(0xFF7FFFFF = -FLT_MAX)
(immediate at 0x00916C12, read) and becomes splat(winner) at 0x00916D3B-0x00916D49.

Tie rule: every compare jumps on `<=`, so on equal dot products within a
block the higher lane wins; across blocks a later block wins only when
strictly greater (CMPLTPS `max < dot`) (derived from F3, F6-F11).

Edge flow worth a test: in the full-compare path the four lanes are compared
regardless of the mask. With finite values the result equals the maximum of
the masked lanes (unmasked lanes are `<=` old max `<` masked lanes). When an
unmasked lane is NaN, F7/F9/F11 treat it as "less or equal" and can pick lane
3 or a NaN lane, e.g. mask 3, d2 = NaN: F6 (d0>d1) -> F7 unordered -> F11
unordered -> lane 3 wins although lane 3 did not beat the maximum (derived
from F5-F11). Mask 13 and 14 skip the compare against the one lane that is
known not to win (derived).

Pseudocode disagreement: pseudo.c computes the loop condition as
`fVar7 = (float)(uVar9 + 1); ... (int)fVar7 < iVar11`. The instructions do an
integer `LEA EDX,[ECX-3]` (0x00916D4F) and `CMP EDX,EDI` (0x00916D55); there is
no float conversion - Ghidra reused one variable for EDX across the
`MOVMSKPS` result and the loop counter. The instructions win. pseudo.c's
switch restructuring otherwise matches the tables.
