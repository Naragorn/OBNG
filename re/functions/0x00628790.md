# 0x00628790 - PointAlongRefLine (proposal)

Slice: actor-movement. Map only (not rebuilt in this run).

## Identity

- Address: 0x00628790 - 0x00628931 (418 bytes, 131 instructions; meta.json `body`, `bytes_bin`).
- Seed name: "(name unknown; above 0x00643340)" (manifest); Ghidra `FUN_00628790`.
- Proposed name: `PointAlongRefLine` - "the point `dist` units from reference A on the line through
  reference B, toward or away from B, snapped by the cell when the cell's flag bit 0 is set".
  A proposal until the refutation round.
- Only static caller: 0x00633590 (meta.json `callers`), call at 0x00633663.

## Purpose

Free function (no `this`) that returns a 3-float vector by hidden return pointer:

1. out = the vector at 0x00B3F9A8..0x00B3F9B0 (zero in the image).
2. When both reference arguments are non-null: read A's and B's position through vtable slot +0x174,
   take the direction B - A (flag set) or A - B (flag clear), normalize it with 0x0043F350, and set
   out = A + (dist + 0.0) * dir (the add is exact except for -0.0 and sNaN, see claim 5).
3. When A's cell (A +0x40 through 0x006ECC80) is non-null and that cell's byte +0x24 bit 0 is set
   (0x004C97F0), out is replaced by the result of 0x005E2E20 called on A with out, the cell and three
   zero arguments.

It touches no clock, no Havok object, no heap, and writes nothing outside its own stack frame and the
caller's out buffer.

## Calling convention and parameters

`__cdecl`, `RET` with no immediate at 0x00628931 (read); ECX is not read before it is overwritten at
0x006287A0 (read), so there is no `this`. The caller cleans: 0x00633590 does `ADD ESP,0x8` at
0x0063367E and reuses the remaining 12 bytes as the by-value argument of 0x006127E0 (seen only in a
second copy of the EXE, md5 66a6c2ef...; **unverified** in the reference binary, see the claims).

## Claims

1. **read** (0x00628931 `RET`, 0x006287A0 overwrites ECX before use): cdecl, no `this`, caller cleans.
2. **read** (0x00628790..0x006287B6): out is first set from 0x00B3F9A8..B0, which data.json gives as
   zero bytes in the image; that the value stays zero at run time is **unverified** (it is not const data
   by evidence here; knowledge/actor-frame-map.md lists it as "vector (zero in the image)").
3. **read** (0x006287B9, 0x006287C5): when refB or refA is null, the function returns that vector and
   calls nothing.
4. **read** (0x0062881C..0x00628860): when towardB != 0, dir = posB - posA; when 0, dir = posA - posB;
   each component rounded to float by FSTP.
5. **read** (0x006287F5..0x0062880C, data.json 0x00A2FC68 = double 0.0): dist is argument 3 + 0.0 in
   x87, stored as float. **derived** (from the FLD float at 0x006287F5, the FADD at 0x006287FE and the
   FSTP float at 0x0062880C): the add is exact; for finite non-zero values, denormals and qNaN the value is
   unchanged (the FLD float / FSTP float round trip is exact); -0.0 becomes +0.0 under round-to-nearest,
   toward +inf and toward zero, and stays -0.0 under round-toward-minus-infinity; an sNaN argument comes
   back as a qNaN (quieted by the FLD at 0x006287F5, raising invalid). The rounding control is not set in
   this body, so the -0.0 case depends on the caller's x87 control word (**unverified** which RC is live
   here). A bit-identical rebuild must follow the caller's RC and not fold the add away.
6. **read** (0x00628881..0x006288D8): out = posA + dist * normalized dir, each product and sum rounded
   to float through stack temporaries.
7. **read** (0x006288DB..0x00628926): when refA +0x40 is non-null and its byte +0x24 bit 0 is set, out
   becomes the vector returned by 0x005E2E20(refA; out by value, cell, 0, 0, 0).
8. **unverified** in the reference binary (seen in a second copy of the EXE, see below;
   0x0063364E..0x00633663; the callee side, the fifth stack byte read at 0x006287F9, is **read**): the caller 0x00633590 passes
   argument 5 = the result of 0x0064ADA0 on its `this` (EDI), argument 4 = 0x006135F0 on the reference
   returned by vt+0x330 of its argument 1, argument 2 = its argument 1, argument 3 = its argument 2.
   Evidence source: `Oblivion - A Painted World/Stock Game/Oblivion.exe`, md5 66a6c2ef97ddea75f43d916aca8d164d
   (not the reference md5 cdd2f0c5...); its 418 bytes at file offset 0x227B90 equal bytes.bin of this
   function exactly. The caller's bytes were read from a second copy whose identity with the
   reference at 0x00633590 is **unverified**; rea-all's caller pseudo (reference binary) agrees on the
   call target and the first four arguments. To settle it: export 0x00633590 (and 0x006135F0 to confirm
   its plain RET at 0x0061360E) from the reference binary (md5 cdd2f0c5...).
9. **derived** (from 7, the callee list and the absence of other calls): this function cannot call
   0x00643340 except through vt+0x174 or inside 0x005E2E20. **read**: there is no direct call to
   0x00643340 in this body. **unverified**: whether the sampler chain "0x00643340 < 0x00628790" is
   reached through 0x005E2E20 (unfollowed, many callees) or vt+0x174, or is a stale stack word (as
   knowledge/actor-frame-map.md warns) is undecided; checking 0x005E2E20's call tree would settle it.
10. **derived** (meta.json callers = 0x00633590 only): the manifest's "0x00628790 < 0x005F1910" does not
    hold as a direct call; 0x005F1910 is not this function's caller.
11. **derived** (claims 1-7): thread-safety of this body alone: it writes only the caller's out buffer
    and its own frame; it reads two references' positions and one cell flag. Any shared-state write
    lives in the virtual +0x174 (unverified, expected a pure getter) or in 0x005E2E20 (which calls
    0x0047DF80 with `% 1000`, possibly the CRT rand, which knowledge/actor-frame-map.md says keeps
    per-thread state - unverified for this path).
12. **unverified**: the meaning of the caller 0x00633590 (it compares a distance against 30.0 and calls
    vt+0x3DC/+0x238/+0x414 of its `this`); it looks like a package or combat step that moves an actor
    toward or away from a target. This is why the proposed name stays neutral.
