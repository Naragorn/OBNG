# 0x009DC2D0 - static initialiser that registers the INI setting at 0x00B06704

Slice: frame-clock. Evidence: `re/export/frame-clock/0x009DC2D0/` (meta.json,
asm.s, pseudo.c). Marks: **read** (seen in the instructions, with the
address), **derived** (follows from read facts, named), **unverified**.

## Purpose

A compiler-generated dynamic initialiser for one global object, the object at
0x00B06704. It does exactly two things:

1. Calls 0x004040E0 with `ECX = 0x00B07BF0` (`g_IniSettingCollection`, xOBSE
   and OBVR agree on that address) and one stack argument `0x00B06704`
   (0x009DC2F0..0x009DC302). Read as: the INI setting collection adds the
   setting object at 0x00B06704 to its list.
2. Registers 0x00A18690 with `_atexit` (0x009DC307..0x009DC311), the
   destructor stub for that same global (proposal).

Answer to the slice question ("is this the initialiser of the multiplier and
the TimeInfo?"): **no**.

- It writes neither 0x00B06704 nor g_timeInfo 0x00B33E90. The only stores in
  the body go to `FS:[0]` (0x009DC2EA, 0x009DC318) and to its own EH state slot
  `[ESP+0x10]` (0x009DC2FA) (read).
- The g_timeInfo write at 0x009DC2B6 lies **before** the entry 0x009DC2D0. This
  function has a complete EH prologue at its entry (0x009DC2D0 `PUSH -1`) and a
  `RET` at 0x009DC323. So Ghidra did not cut this body: 0x009DC2B6 belongs to a
  different, preceding piece of code that Ghidra has no function for (derived
  from meta.json body range and the prologue/epilogue at 0x009DC2D0/0x009DC323).
- What it does show: the "global time multiplier" at 0x00B06704 that
  0x0047D170 reads with `fmul [0x00B06704]` (0x0047D247, knowledge/frame-clock.md)
  is the address of an **INI setting object** handed to the setting collection.
  With OBVR's layout of a list entry's SettingInfo, `{value union, name pointer}`
  (GameAddresses.h:690-709, taken from xOBSE GameAPI.h), the float at
  0x00B06704 is that setting's value at +0x00 (derived). Which INI setting it
  is, and its default, is not in this function (unverified, see Open questions).

## Calling convention and parameters

- No parameters. Nothing above the return address is read: the only stack
  access with an offset, `[ESP+0x10]` at 0x009DC2FA, resolves to entry_ESP-4,
  the EH state slot this function pushed itself (derived from the push
  sequence 0x009DC2D0..0x009DC2E5 and the push at 0x009DC2F0).
- No `this`: ECX is not read before it is loaded with 0x00B07BF0 at 0x009DC2F5
  (read).
- Returns with a plain `RET` at 0x009DC323, no `ret N`; returns nothing (EAX is
  whatever `_atexit` left; read, no EAX load after 0x009DC30C). Fits a
  `void (*)(void)` entry in the CRT initialiser table (derived; the table
  itself is not in the export).
- No callers in meta.json (`"callers": []`, read). Consistent with being reached
  only through a function-pointer table such as `_initterm`'s (unverified).
- Callee 0x004040E0: thiscall, ECX = 0x00B07BF0, one stack argument, cleans it
  itself (`ret 4`). Derived from stack balance: after the call the caller
  pushes 0x00A18690, calls `_atexit` and pops only 4 bytes (0x009DC311); the
  load `MOV ECX,[ESP+4]` at 0x009DC314 then reads the saved previous `FS:[0]`
  at entry_ESP-12 only if 0x004040E0 removed its own argument.
- Callee 0x00981FB4 `_atexit`: cdecl, caller cleans (`ADD ESP,4` at 0x009DC311,
  read).

## Control flow

There are **no branches**: no conditional or unconditional jump between
0x009DC2D0 and 0x009DC323 (read). One straight flow:

| # | Flow | Condition | At |
|---|---|---|---|
| 1 | install EH frame, set state 0, register setting, register atexit destructor, unlink EH frame, return | always | 0x009DC2D0..0x009DC323 |
| 2 | exceptional exit: if 0x004040E0 throws, the handler 0x009AF43A unwinds state 0 (presumably destroying the object at 0x00B06704) | exception inside 0x004040E0 | 0x009DC302 |

Flow 2 is not a branch in this body; it exists only through the EH table at
0x009AF43A, which is not in the export (unverified what it runs). The EH state
is never reset to -1 before the frame is unlinked at 0x009DC318 (read), so
`_atexit` failing is not covered by an unwind action here (derived).

For a rebuild test the observable flow is: after the call, the collection's
list contains 0x00B06704 and 0x00A18690 is registered for exit.

## Open questions

1. Which INI setting is 0x00B06704? Reading the dword at 0x00B06708 (the name
   pointer in OBVR's SettingInfo layout) and the string it points to settles it,
   together with the float at 0x00B06704 (default value). Not in this export.
2. What is the code around 0x009DC2B6 that writes g_timeInfo? It is a separate
   function (probably the neighbouring static initialiser of `TimeInfo`
   0x00B33E90, unverified); it needs its own entry and export, e.g. by
   creating a function at the start of the code ending before 0x009DC2D0.
3. What do 0x004040E0 and 0x00A18690 do exactly (add to list; remove from list
   or destroy)? Export both.
4. Does anything other than the INI loader write 0x00B06704 at run time (a
   console command or script changing the time multiplier)? Needs an xref list
   of writes to 0x00B06704.
5. The EH prologue mixes a cookie (`XOR EAX,ESP` with 0x00B30AAC, 0x009DC2E3).
   That pattern is commonly associated with MSVC 8.0 (2005) and later, not
   2003; I could not verify the compiler version from this export.

## Layout requests

- `SettingInfo` (shared INI header, not TimeInfo.h): `+0x00` value union
  (float for this setting), `+0x04` `const char* name` - from OBVR
  GameAddresses.h:690-709; the +0x04 field is not confirmed by this function.
- `IniSettingCollection` at 0x00B07BF0: a method at 0x004040E0
  (`thiscall`, one `SettingInfo*`, `ret 4`) proposed as `AddSetting`.
- TimeInfo.h: name the multiplier as "the value of the INI setting at
  0x00B06704" rather than a free float global, once open question 1 gives the
  setting's name.
