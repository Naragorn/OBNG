Oblivion.exe 1.2.0.416, md5 `cdd2f0c5eff198d4f26b7b5b54ce4930` (the copy

## Purpose

Ends a lock taken by the lock wrapper 0x00776C90 on the same manager: copies
the staging block the caller filled into the D3D buffer's mapped memory,
clears the manager's per-lock slots, releases the manager's lock object
(depth, owner thread, critical section), then calls the D3D buffer's Unlock
and reports whether it succeeded. It is a leaf apart from memcpy, one import
and one COM call: no clock, no global, no allocation.

Order of subsystems touched (all **read**): CRT memcpy (0x00776D8F) ->
manager fields (0x00776D9F-0x00776DAC) -> Win32 critical section
(0x00776DB0) -> Direct3D buffer Unlock (0x00776DC0). The copy into the D3D
memory runs **inside** the critical section; the D3D Unlock runs **after**
it is left.

## Calling convention and parameters

- `__thiscall`: ECX = the buffer manager, moved to ESI at 0x00776D81
  (ESI saved by `PUSH ESI` 0x00776D80, restored by `POP ESI` 0x00776DA9)
  (**read**).
- One stack argument: `vb` at E+4, read at 0x00776DB6 as `[ESP+4]` after
  `POP ESI` and the LeaveCriticalSection call (**read**). That the offset is
  E+4 there is **derived**: LeaveCriticalSection is `WINAPI` (stdcall,
  `synchapi.h` line 131 of Windows SDK 10.0.26100) and pops its one argument
  pushed at 0x00776DAF, so ESP is back at E.
- Callee cleans: `RET 4` at 0x00776DCB (**read**).
- Return: AL = 1 when the HRESULT of `vb->vt[+0x30](vb)` is >= 0, else 0
  (`TEST EAX,EAX; SETGE CL; MOV AL,CL` 0x00776DC4-0x00776DC9) (**read**).
  Bits 8-31 of EAX keep the HRESULT's upper bits (only AL is written,
  0x00776DC9) (**read**); the traced callers test AL only (`TEST AL,AL` at
  0x007700D5 and 0x0077748E, objdump) (**read**).
- Ghidra's meta.json says `calling_convention: unknown` and signature
  `FUN_00776d80()`; pseudo.c says `__thiscall(int, int*)` returning bool.
  The instructions agree with pseudo.c; meta.json's signature is incomplete,
  not contradictory.

## Control flow

Straight line from 0x00776D80 to 0x00776DCB with one conditional jump and
one data-dependent result (**read**, all of asm.s):

| # | At | Condition | Taken | Not taken |
|---|---|---|---|---|
| B1 | 0x00776DAA `JNZ 0x00776DAF` | flags of `ADD [mgr+0xFC],-1` at 0x00776DA5 (the `POP ESI` at 0x00776DA9 leaves flags alone): depth after the decrement != 0 | skip; +0xF8 keeps its value | `MOV [mgr+0xF8],0` at 0x00776DAC |
| R1 | 0x00776DC4-0x00776DC9 `TEST/SETGE` | HRESULT of `vb->vt[+0x30]` >= 0 | AL = 1 | AL = 0 |

The memcpy (0x00776D8F), the zeroing of +0x48/+0x4C, LeaveCriticalSection
and the D3D Unlock run on every path; no branch precedes or skips them
(**read**).

Test flows a rebuild needs (**derived** from B1 and R1):
1. depth 1 -> 0: owner cleared; HRESULT S_OK -> AL 1.
2. depth 2 -> 1 (nested lock): owner kept.
3. HRESULT negative -> AL 0, everything before it still done.
4. lockedBytes 0: memcpy of 0 bytes, rest unchanged.
5. depth 0 -> 0xFFFFFFFF (unbalanced unlock): JNZ taken, owner kept, and
   LeaveCriticalSection on a section this thread does not own (refusal
   path; the original does not guard it).

## Claims

C1. **read** - Copy: `memcpy(dst = [mgr+0x48], src = [mgr+0x40], n =
[mgr+0x4C])`. Pushes in order count (EAX <- +0x4C, 0x00776D83/0x00776D8C),
src (ECX <- +0x40, 0x00776D86/0x00776D8D), dst (EDX <- +0x48,
0x00776D89/0x00776D8E); `CALL 0x009812C0` 0x00776D8F; caller cleanup `ADD
ESP,0xC` 0x00776D9C. The cdecl (dst, src, n) argument order is **derived**
from Ghidra's library name `_memcpy` (meta.json) and the 3-argument
caller-cleaned call shape.

C2. **read** - ECX at every direct call site is a manager object, never a
chip (objdump): 0x00766D59 `MOV ECX,[EBX+0x8B0]` (EBX = 0x00766880's
`this`, 0x00766884); 0x00769262 `MOV ECX,[EDX+0x8B0]` with EDX = `[ESP+0x14]`,
the slot 0x00769039 filled with 0x00769030's `this`; 0x007666A6 `MOV
ECX,[EBP+0x8B0]` (EBP = `this` of 0x00765990, set at 0x00765997, not
rewritten before 0x007666A6); 0x007700D0 `MOV ECX,[EBP+0x0C]` (EBP = the
declaration `this` of 0x0076FE20, re/functions/0x0076FE20.md); 0x00777489
`MOV ECX,[ESP+0x14]`, the slot 0x00777249 filled with 0x00777240's own
`this`. Each site pushes `[reg+0x08]` of a stream object as `vb`
(0x00766D4F, 0x00769254, 0x0076669C, 0x007700C9, 0x00777481) (**read**);
that the object is a chip is read for 0x0076FE20 (0x0076FE20.md) and
**unverified** for the other four.
**derived**: the manager is not per chip; at three of five sites it is
`[X+0x8B0]` of a renderer-shaped object (0x00769030 is entered with ECX =
`[0x00B3F928]`, which OBVR's GameAddresses.h names the NiDX9Renderer,
per re/functions/0x00763130.md), at one it is the method's own `this`, at
one `[declaration+0x0C]`. That `[declaration+0x0C]` is the same object as
`[renderer+0x8B0]` is **unverified** (no writer of declaration+0x0C was
read). For 0x00769262 and 0x00777489 the stack slot reasoning assumes the
calls in between leave ESP balanced (**derived**, not traced call by call).

C3. **read** - Slots cleared after the copy: `+0x48 = 0` 0x00776D9F, `+0x4C
= 0` 0x00776DA2 (ECX zeroed 0x00776D94). **derived** (with the lock,
objdump 0x00776CE3-0x00776CF0): the manager has one mapped/size slot, not a
stack; a nested lock on the same manager (depth 2) overwrites the outer
lock's +0x48/+0x4C, the inner unlock copies and zeroes them, and the outer
unlock then copies 0 bytes to address 0. Whether nesting ever happens is
**unverified**.

C4. **read** - Lock object at mgr+0x80: depth `[+0xFC]` decremented
(0x00776DA5), owner `[+0xF8]` zeroed only when it reaches 0 (B1), then
`LeaveCriticalSection(mgr+0x80)` (0x00776DAF/0x00776DB0). **read**
(objdump): the identical sequence `ADD [ECX+0x7C],-1; JNZ; MOV
[ECX+0x78],0; PUSH ECX; CALL [0x00A28074]` stands alone at 0x0043F300, and
the renderer-shaped object keeps another such block at +0x180
(0x00763565-0x007635A4). **derived**: +0x80..+0xFF is one generic lock
object (critical section at +0x00, owner thread +0x78, depth +0x7C) whose
Unlock 0x0043F300 is inlined here; the class name (Gamebryo
`NiCriticalSection`?) is **unverified**.

C5. **read** - The memcpy into the D3D memory runs before
LeaveCriticalSection (0x00776D8F < 0x00776DB0); the D3D Unlock runs after it
(0x00776DC0). With the lock (objdump: D3D Lock 0x00776CBC before
EnterCriticalSection 0x00776CD3) **derived**: the critical section guards the
staging block and the manager's slots, not the D3D Lock/Unlock calls
themselves.

C6. **read** - Return: AL = (HRESULT >= 0) (R1); `RET 4` (0x00776DCB).

C7. **derived** (C1, B1/R1 having no branch before the copy) - Within
0x00776D80 there is no path that skips the copy: every call copies exactly
`[mgr+0x4C]` bytes from `[mgr+0x40]`, which is what the probe in
`plugin/src/Probes.cpp` (ProbeUnlock) hashes at entry. So the probe's hash
covers every byte written to the D3D buffer only for unlocks through
0x00776D80 reached while ProbePacker's thread context has depth > 0.
Unlocks outside a packer call are only counted as `outside` and not hashed,
and a null staging pointer hashes as 0 (Probes.cpp ProbeUnlock, at commit
7418151 lines 361-370 and in the working tree).

C8. **derived** (lock objdump 0x00776CEA-0x00776D20 plus C1) - What those
bytes are depends on the lock flags: when `flags & 0x3000 == 0` the lock
first copies the mapped D3D contents into staging, so bytes the caller does
not write are re-written unchanged; when DISCARD (0x2000) or NOOVERWRITE
(0x1000, values from d3d9types.h lines 1696-1697) is set, staging is not
pre-filled, and bytes the caller does not write carry stale contents from
an earlier lock only when the staging capacity `[mgr+0x44]` already covers
the lock size (`JAE 0x00776D0E` at 0x00776CF4 taken). Otherwise the lock
frees and reallocates staging (0x00401F20 / 0x00401F00,
0x00776CF6-0x00776D0B), and those bytes are whatever the allocator hands
back (uninitialised heap). Either way the probe hashes the bytes that land
in the buffer.

C9. **derived** (C2) - The committed probe that made the 20261104-083110
measurement keys its cache on `self` as "chip" (`plugin/src/Probes.cpp` at
commit 7418151, ProbeUnlock line 372: `PackKey{geometry, partition, chip}`
with `chip = self`). The uncommitted working-tree ProbeUnlock already keys
on `{geometry, partition, stream}` and takes the slice from PackStream's
chip, so what follows applies to the committed probe and its measurement.
`self` is the manager, so where the manager is one object (C2), the
third key component is constant and the measured "35 keys" are
(geometry, partition) pairs, not distinct chips. The `vb` argument (the
chip's `+0x08`, C2) is the per-buffer identity the probe already receives as
`d3dBuffer`. **OBNG's probe and docs/subsystems/stream-packing.md should
pick this up**; the measurement itself is not invalidated, its "chip
pointers are stable" reading is.

C10. **read** (objdump) - Two functions inline this body instead of calling
it: 0x00776E90 at 0x00777165-0x007771A4 (memcpy 0x00777178, LeaveCriticalSection
0x00777198, `CALL EDX` = vt+0x30 0x007771A4) and 0x007774C0 at
0x007779D1-0x00777A14 (memcpy 0x007779E8, LeaveCriticalSection 0x00777A08,
vt+0x30 0x00777A14). Both also call the lock 0x00776C90 (0x00777001,
0x00777662) and contain no `CALL 0x00776D80`. **read** (objdump, all `CALL` to
them in 0x00760000-0x00780000): 0x007774C0 is called at 0x0076332D (the
packer 0x00763130's fallback on `[renderer+0x8B0]`,
re/functions/0x00763130.md) and at 0x00769188; 0x00776E90 at 0x00767DEE and
0x0076919A. **derived**: packs made through 0x007774C0 and 0x00776E90 never
pass 0x00776D80, so besides the 0x00763130 fallback, packs from 0x00769030
and from the function containing 0x00767DEE can bypass the probe as well;
the probe does **not** see every packed byte, only the packs that end in
the five call sites of C2. Which share of the measured 4.15 MB a frame
goes through the inlined copies is **unverified** (cheapest step: a
counting detour on 0x007774C0 and 0x00776E90 next to the existing one).

C11. **read** (objdump) - The site 0x007666A6 (and its lock 0x00765C66)
belongs to a function at 0x00765990 that follows 0x007655F0's `RET 0x14`
(0x0076598D) without padding and starts with `SUB ESP,0x108; PUSH EBP; MOV

C12. **read** - No clock and no global data are read or written: the only
data reference is the import slot 0x00A28074 (data.json: pointer value
0x00700A08, Ghidra name `PTR_LeaveCriticalSection_00a28074`); every other

C13. **derived** (re/functions/0x0076FE20.md C13 and the lock objdump
0x00776CC2-0x00776CC8) - If a caller unlocks after a failed lock (the lock
returns 0 before entering the section), +0x48/+0x4C still hold the zeros of
the previous unlock (when no other lock ran since), so the copy is 0 bytes,
but the depth is decremented and a section this thread did not enter is
left (flow 5). Whether any caller does this in play is **unverified**.

C14. **unverified** (C2 with re/functions/0x007655F0.md, struct row
`this +0x8B0`) - **read**: 0x007655F0 passes `[this+0x8B0]` as ECX to
