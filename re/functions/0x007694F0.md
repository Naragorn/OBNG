## Purpose

Draws one geometry with the pipeline its caller left on the device: no shader open/close,
no pass loop, no stream/index binding. In instruction order:

1. **Gate**: returns when byte `this+0x6F0` is non-zero (0x007694F6/0x00769501).
2. **Vertex count**: returns when the data's virtual +0x50 returns 0 in AX
   (0x0076951B-0x00769520). Neither early return clears the data flags.
3. **Decision**: `skinned = 0x00768890(this; geometry, 0)` (0x00769537), result kept in BL.
4. **Shader**: `record = [[geometry+0xB4]+0x38]` (0x0076953C/0x00769548, re-read of
   geometry+0xB4), `shader = 0x00560920(0x00B42858, [geometry+0xBC])` (0x00769553);
   `shader->slot+0x48()` (0x00769566) **with no null test** and its result unused; then
   `[[this+0x8AC]+0xFF0]->slot+0x04()` (0x00769579), result unused.
5. **Skinned arm** (BL != 0): per partition of `[[skin+0x0C]+0x0C]` (count `[skin+0x0C]+0x08`,
   stride 0x2C): with `shader == this+0xA94` and `boneCount > this+0x6D8`, call 0x0060D0A0
   with the string and the bone count and skip the partition; otherwise one
   DrawIndexedPrimitive per entry of the partition's record `[partition+0x28]`.
6. **Whole arm** (BL == 0): `record+0x30 == 0` -> one DrawPrimitive; otherwise one
   DrawIndexedPrimitive per entry of the record's array.
7. **Close**: `word [data+0x2E] &= 0xF000` on every path that passed step 2.

Compared with the siblings (re/functions/0x007672F0.md, 0x00767520.md; earlier slices):
the device draw loops are the same instructions in shape (same argument order, the
`lengths[i] - 2` count and `start += count + 2`), but here there is no shader slot 10-17,
no default-shader fallback (the cast result is used as is), no slot 15 (so the record is
not packed or bound here: whole arm `data+0x38`, skinned arm `partition+0x28`, both
straight from memory), no world-bound copy, and the flags clear runs once at the end
instead of per pass.

## Calling convention and parameters

`__thiscall`: ECX = this, copied to EBP at 0x007694F4 and to ESP0-0x14 at 0x007694FD; EBP
holds `this` until the skinned arm's DIP loop reuses it (0x007695DD), after which it is
reloaded from ESP0-0x14 (0x00769634). One stack argument, callee-cleaned: `RET 0x4` at
0x0076965B, 0x007696C5, 0x007696F7 (read). EBP, ESI, EBX, EDI are saved and restored in
LIFO order on each exit (read: pushes 0x007694F3, 0x00769507, 0x0076952C, 0x0076952D; pops
0x00769654-0x00769657, 0x007696BE-0x007696C1, 0x007696F0-0x007696F3; the two early exits
enter the shared epilogue at 0x007696F3 (only EBP pushed) and 0x007696F2 (ESI, EBP pushed)).

No return value: EAX at the three normal exits is the data pointer (loaded for the flags
clear, 0x0076964A / 0x007696B4 / 0x007696E6), at the gate exit the caller's EAX, at the
zero-count exit the slot +0x50 result (read). The caller found, 0x007176D0, pops and
returns right after the call without reading EAX (objdump 0x00717706-0x0071770A).

## The callee 0x00768890 (question 4)

Read in full with objdump 0x00768890-0x00768952 in this run. **Convention: `__thiscall`**
(ECX = renderer, copied to EBX at 0x007688A0 and used as `[EBX]` vtable and `[EBX+0x6E4]`,
`[EBX+0x5C9]`), two stack arguments `(geometry, shader)`, `RET 0x8`, result in AL (`MOV
AL,1` / `XOR AL,AL`). Ghidra's pseudocode of it (rea-all) shows a two-parameter function
with `in_ECX`, i.e. it did not recognise the thiscall - the instructions win.

## Open questions

1. Which of the seven `+0x88(g_renderer)` callers (0x007F6BF0 and the five batch renderers,
   0x007F9410) produce the measured slot 90 calls, and what each leaves on the device
   (shader pass, streams, indices) - needed for the second eye's draw to see the same state.
   An instruction-level map of 0x007F6BF0 settles the first caller.
2. Callers of +0x168 outside 0x00700000-0x008FFFFF and through non-disp32 forms were not
   scanned (C23 scope).
3. What byte `renderer+0x6F0` is and who sets it; what `renderer+0x200/+0x204/+0x20C` (the
   slot 34 gate) are.
4. What shader slot 18 (+0x48) does when called outside a pass loop (reset of the pass
   cursor? first pass's state apply?) - its body per shader class was not read here.
5. The rebuild cannot reproduce C4/C12 (faults). The port contract has to state them as
   preconditions (cast non-null; whole-arm record non-null) or the rebuild deviates by
   refusing; a choice for the slice, not a finding.
6. Whether D7/D8 (0x00768890 with renderer+0x6E4 / +0x5C9) can return 1 with
   `partition[0]+0x28 == 0` in practice (then C17's null record would fault).

## Layout requests

Fields a shared header (StereoDrawDirect / the rebuild's `<Name>.h`) needs, each as a
`static_assert`ed offset:

- `NiDX9Renderer`: +0x280 device (u32 handle), +0x6D8 maxBonesWithoutShader (u32), +0x6F0
  draw-suppress (u8), +0x8AC render state (u32 handle), +0xA94 defaultShader (u32 handle);
  for 0x00768890: vtable +0x54, +0x5C9 (u8), +0x6E4 (u32). Vtable slot 90 = +0x168.
- render state: +0xFF0 shader constant manager (u32 handle), its vtable +0x04.
- `NiGeometry`: +0xB4 data, +0xB8 skin, +0xBC shader (u32 handles); vtable slot 34 = +0x88.
- `NiGeometryData`: vtable +0x50 (u16 vertex count in AX), +0x2E flags (u16, mask 0xF000
  kept), +0x38 record (u32 handle).
- `NiSkinInstance`: +0x0C skin partition. `NiSkinPartition`: +0x08 count (u32), +0x0C
  array; partition record stride 0x2C with +0x1C vertexCount (u16), +0x20 boneCount (u16),
  +0x22 stripCount (u16, partition 0 only), +0x28 record (u32 handle).
- buffer record: +0x14 vertexCount, +0x30 indexBuffer, +0x34 baseVertexIndex, +0x38
  primitiveType, +0x3C primitiveCount, +0x44 arrayCount, +0x48 lengths (u16 array or 0).
- `NiD3DShaderInterface`: vtable +0x48 (slot 18); for 0x00768890 +0x50, +0x68. RTTI object
  address 0x00B42858.
- Constants: string 0x00A88D90; primType 4 (list) / 5 (strip); D3D9 device slots +0x144 /
  +0x148.
