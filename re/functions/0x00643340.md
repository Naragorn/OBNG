## Purpose

Returns, as an int (via `_ftol` 0x009828C0), the sum of three terms for actor-value code `av` (arg2):

1. `L0` = ActorValues::GetAV 0x0065CB80 on `(arg3 + 0x88)` for `av`, stored as float; 0.0 when arg3 is null.
   +0x88 is xOBSE's `Actor::avModifiers` (GameObjects.h:852), which fits arg3 being an Actor (derived; unverified).
2. `L1` = ActorValues::GetAV 0x0065CB80 on `(this + 0x70)` for `av`, stored as double. this+0x70 is xOBSE's
   `LowProcess::avDamageModifiers` (GameProcess.h:1099).
3. A base term:
   - when `av == 0xB` (Encumbrance) and arg3 != 0: the float returned by 0x004D8FB0 called on arg3;
   - otherwise: `(double)(int) arg1->vtable[0x128/4](av)`.

The caller chain is the process class hierarchy's override of the same virtual slot 0x268: HighProcess
0x00628940 (caches Encumbrance and Paralysis; a negative cache means "not cached") -> MiddleLow/MiddleHigh
0x00658790 (adds `this+0x94`, xOBSE `MiddleLowProcess::maxAVModifiers`) ->
LowProcess 0x00643340 (this function). See Claims C4-C9.

Flows (each a test flow for a rebuild):

- F1 arg3 == 0, any av: `L0 = 0.0`; generic: `(int)arg1->vt[0x128](av) + L0 + L1` -> `_ftol`.
- F2 arg3 != 0, av != 0xB: `L0 = GetAV(arg3+0x88, av)`; generic as F1.
- F3 arg3 != 0, av == 0xB: `L0 = GetAV(arg3+0x88, 0xB)`, `L1 = GetAV(this+0x70, 0xB)`, base = `0x004D8FB0(arg3)`
  (float in ST0), sum `base + L0 + L1` (0x00643387 `FADD float`, 0x0064338B `FADD double`) -> `_ftol`.
- (arg3 == 0, av == 0xB) is F1: the Encumbrance special case needs arg3.

Precision detail for a class-A rebuild: `L0` is rounded to float (0x00643366 `FSTP float`), `L1` kept as double
(0x0064337C / 0x006433A6 `FSTP double`); the generic base is an int loaded by `FILD` (0x006433BD). Sum order is
base + L0, then + L1 - read. The result depends on the x87 precision control in force (unverified which).

## Claims

- C1 (read, asm.s 0x00643340-0x006433D4): `__thiscall`, `RET 0xC`, three stack args, int result via `_ftol`.
- C2 (read, 0x0064336A-0x00643371): the Encumbrance path is taken only when av == 0xB and arg3 != 0.
- C3 (read, exe table g_scriptActorValueNames 0x00B0A1A8 named by xOBSE `GameAPI.cpp:207`, entries at index*4):
  av 0xB is "Encumbrance", 0x30 is "Paralysis", 0x4 is "Speed".
- C4 (read, byte scan of the md5-matching exe's .rdata + RTTI locators): 0x00643340 is slot 0x268 of the
  LowProcess vtable 0x00A720A4 (pointer at 0x00A7230C); it is the only .rdata word equal to 0x00643340.
- C5 (read, same method): slot 0x268 is 0x00658790 in MiddleLowProcess (vtable 0x00A72D64, slot at 0x00A72FCC)
  and MiddleHighProcess (0x00A72684, slot at 0x00A728EC); 0x00628940 in HighProcess (0x00A71814); 0x005E17D0 in
  BaseProcess (0x00A6F464).
- C6 (read, meta.json callers + objdump 0x006587B8): the only direct call to 0x00643340 is 0x00658790 at
  0x006587B8, which passes ECX and its three args through unchanged and adds `GetAV(this+0x94, av)`.
- C7 (read, objdump of 0x00628940-0x006289E2; chain derived from C5, C6): on a HighProcess the chain is
  0x00628940 -> 0x00658790 -> 0x00643340 (CALL 0x00658790 at 0x00628969, 0x006289BA, 0x006289DC).
  For av 0xB, 0x00628940 uses the float cache at +0x294 when it is >= 0.0 or NaN (0x0062894C-0x00628959:
  FLDZ / FCOMP / FNSTSW / TEST AH,0x41 / JNE 0x0062897C) and recomputes only when it is < 0.0 (CALL 0x00658790 at
  0x00628969, FILD 0x00628972, FSTP [ESI+0x294] 0x00628976). A cached 0.0 is a hit. On both paths the returned
  value is not the raw cache: it is `_ftol(0x00985A00((double)[ESI+0x294]))` - FLD 0x0062897C, FSTP double
  0x00628985, CALL 0x00985A00 0x00628988, FSTP float 0x0062898D, FLD 0x00628994, CALL 0x009828C0 0x00628998.
  For av 0x30 it uses the int cache at +0x298 when >= 0 (CMP / JGE 0x006289A6-0x006289AD) and recomputes when < 0.
  Every other av falls through to 0x00658790 uncached (0x006289CF-0x006289E2).
- C7a (read, objdump of 0x00628C50-0x00628C91 and the md5-matching exe's float at 0x00A30634 = 0xBF800000 = -1.0;
  second source xOBSE GameProcess.h:202 "0A3 ... unk294 = -1", slot 0xA3 = offset 0x28C): HighProcess vtable slot
  0x28C (word at 0x00A71814+0x28C = 0x00628C50, read in the exe) calls 0x00658880 (MiddleLowProcess slot 0x28C, word at 0x00A72D64+0x28C, read) and then invalidates the cache: +0x294 = -1.0 for
  av 0xB (0x00628C83-0x00628C89), +0x298 = -1 for av 0x30 (0x00628C75). Both caches use a negative value as "empty".
- C7b (unverified; pseudo.c of rea-all only): 0x00985A00 is a CRT rounding helper (its pseudo returns 0 for
  |x| < 1 and masks mantissa bits below the binary point, a floor/truncate shape); which rounding it applies is not
