## Purpose

Per drawn partition and shader pass, makes the geometry's GPU buffers current and binds them
on the D3D device. In order:

1. **gate** (0x0077A314-0x0077A33D): decide whether to pack at all - on the geometry being
   non-null, the shader's `+0x34` word, the data's consistency nibble and the partition;
2. **pack** (renderer subsystem): either `PackSkinnedGeometryBuffer 0x00763130` for a skin
   partition (record = `[partition+0x28]`) or `0x00767B40` for the whole geometry
   (record = `[data+0x38]`), both with `force = 0`, both through the renderer at
   `[this+0x14]` and the shader declaration at `[this+0x24]`; the pack's result is ignored;
3. **bind** (D3D device at `[this+0x10]`): per stream i of the record,
   `SetStreamSource(i, chip_i->vertexBuffer, 0, stride_i)`, then `SetIndices(record+0x30)`;
4. return the record (null when there is none; the draws abort the partition on null).

It does not draw, does not set constants and does not read or write any clock.

## Control flow

Every branch with its condition. "geometry", "partition", "arg3" are the stack arguments;
"data" is `[geometry+0xB4]`; "record" is EDI from 0x0077A37E on.

| # | At | Condition | Taken -> |
|---|---|---|---|
| B1 | 0x0077A31B `JZ` | `geometry == 0` | 0x0077A37A: no pack, record = arg3 |
| B2 | 0x0077A325 `JZ` | `[this+0x34] == 0` | 0x0077A33F: pack (B5 picks which) |
| B3 | 0x0077A339 `JNZ` | `([data+0x2E] & 0xF000) != 0x8000` | 0x0077A37A: no pack, record = arg3 |
| B4 | 0x0077A33D `JZ` | `partition == 0` (only reached when `+0x34 != 0` and data is volatile) | 0x0077A37A: no pack, record = arg3 |
| B5 | 0x0077A34F `JZ` | `partition == 0` | 0x0077A366: record = `[data+0x38]`, `0x00767B40(record, data, skin, decl, 0)`; else record = `[partition+0x28]`, `0x00763130(record, data, skin, partition, decl, 0)`; both `JMP 0x0077A37E` (0x0077A364, 0x0077A378) without testing the result |
| B6 | 0x0077A380 `JZ` | `record == 0` | 0x0077A3DB: return 0, no device call |
| B7 | 0x0077A389 `JBE` | `record[+0x1C] == 0` | 0x0077A3C9: no SetStreamSource, SetIndices still runs |
| B8 | 0x0077A38E `JNC` | `i >= record[+0x1C]` on loop entry | stride = 0 (0x0077A398). Unreachable: i = 0 and the count is non-zero after B7 (derived) |
| B9 | 0x0077A39C `JNC` | `i >= record[+0x1C]` (EAX still the count) | chip = 0 (0x0077A3A6), then `[0+0x8]` would fault. Unreachable inside the loop (derived from B7/B10: the loop runs only while i < count) |
| B10 | 0x0077A3C6 `JC` | `i + 1 < record[+0x1C]` (count reloaded after each device call, 0x0077A3BE) | next stream at 0x0077A390 (re-entering after the first bounds test at 0x0077A38B) |

B8 and B9 are the two bounds checks of an inlined array accessor (the same pattern as
0x00763130's B18); a rebuild can keep them as dead arms or drop them, but no test flow can
reach them while the count is re-read only between iterations.

Test flows a rebuild needs at least:
- F1 geometry null, arg3 null -> returns 0, no call at all (B1, B6).
- F2 geometry null, arg3 non-null -> binds arg3 without packing (B1).
- F3 `+0x34 == 0`, partition non-null -> 0x00763130 with `(partition[+0x28], data, skin, partition, decl, 0)`, ECX = `[this+0x14]`; returns `partition[+0x28]` (B2, B5).
- F4 `+0x34 == 0`, partition null -> 0x00767B40 with `(data[+0x38], data, skin, decl, 0)`; returns `data[+0x38]` (B2, B5).
- F5 `+0x34 != 0`, data volatile (`0x8xxx`, low 12 bits arbitrary), partition non-null -> as F3 (B3, B4, B5).
- F6 `+0x34 != 0`, data volatile, partition null -> no pack, returns arg3 (B4).
- F7 `+0x34 != 0`, nibble 0x0000 / 0x4000 / 0x9000 / 0xC000 -> no pack, returns arg3 (B3; nibble compared exactly, so 0x9000 is not volatile).
- F8 pack returns AL = 0 -> the record is still bound and returned (B5: no test).
- F9 record non-null with streamCount 0 -> SetIndices only (B7).
- F10 streamCount 1 and 3 -> SetStreamSource(i, chip_i+0x08, 0, stride_i) for i = 0..n-1, then SetIndices(record+0x30) (B10).
- F11 `record[+0x30] == 0` -> SetIndices(0) is still called (no test before 0x0077A3D9).
- F12 a callee that changes `record[+0x1C]` during the loop -> the loop follows the new count (B10 reload) (edge, for fidelity only).
- F13 `+0x34 != 0` with data null -> the read at 0x0077A32D faults (no null test on data; documents the original's precondition).

## Claims

C1. **read** - `__thiscall`, four stack arguments, callee cleans: `RET 0x10` at 0x0077A3E0;
`this` in ECX, held in EBX (0x0077A319). The fourth stack argument is never read (only
0x0077A310, 0x0077A321, 0x0077A37A read the stack).

C2. **read** - The return value is the full EAX = EDI (0x0077A3DB): the record bound, or 0 when
the record is null (B6).

C3. **read** - Pack gate: it packs when `geometry != 0` and either `[this+0x34] == 0`
(0x0077A31D-0x0077A325), or `([data+0x2E] & 0xF000) == 0x8000` and `partition != 0`
(0x0077A327-0x0077A33D). In every other case it binds arg3 without packing (0x0077A37A).

C4. **read** - Both packs get `force = 0` (`PUSH 0x0` at 0x0077A34D, shared by both call
paths) and ECX = `[this+0x14]` (0x0077A359, 0x0077A36D). Partition path: pushes
`decl=[this+0x24], partition, skin=[geom+0xB8], data=[geom+0xB4], record=[partition+0x28]`
(0x0077A351-0x0077A35E) -> `0x00763130(record, data, skin, partition, decl, 0)`.
Whole-geometry path: pushes `decl, skin, data, record=[data+0x38]` (0x0077A366-0x0077A372)
-> `0x00767B40(record, data, skin, decl, 0)`.

C5. **read** + **objdump** - The pack's return value is ignored, and the record bound is the
pointer the function loaded itself, not the callee's result: EDI is set before the call
(0x0077A354, 0x0077A369), both calls are followed by `JMP 0x0077A37E` with no use of EAX
(0x0077A364, 0x0077A378), and both callees preserve EDI (objdump: 0x00763130 pushes EDI at
0x007631AB before its first EDI write at 0x007631AC and pops it at both exits that follow,
0x00763389 and 0x007633B1; its exits 0x0076317C and 0x007633BD-0x007633C4 come before the
push. 0x00767B40 pushes EDI at 0x00767B45 and pops it before each of its four `RET 0x14`,
0x00767B87, 0x00767E52, 0x00767E80, 0x00767E8B). **Correction** for
re/functions/0x00763130.md C22, which says "the return value of either call becomes the
record": the instructions say the record is `[partition+0x28]` / `[data+0x38]` whatever the
pack returned. A failed pack (AL = 0) still has its record bound and handed to the draw
(derived).

C6. **derived** (C3; re/functions/0x0077A1F0.md struct table: `this+0x34` is passed as the
pass index to the NiD3DPass and constant-map calls and compared with 0;
re/functions/0x007C9230.md: `this+0x34 != 0` skips the bone palette) - `[this+0x34]` is the
shader's current pass index. **read** (C3, B1 at 0x0077A31B): when `geometry != 0` and
`[this+0x34] == 0` a packer is called; when `[this+0x34] != 0` only volatile (0x8000)

C7. **derived** (C3, C4; re/functions/0x00763130.md C4, C9) - What a call from here repacks,
by the data's consistency nibble (force is always 0 from here):
- static (nibble exactly 0x4000) with all stream slots allocated: a packer is reached only
  when `+0x34 == 0`, and 0x00763130 then returns at its early-out (force 0, allocated)
  without touching a buffer; with `+0x34 != 0` no packer is called at all (B3, `JNZ`
  0x0077A339). So: in pass 0 (under C6's unverified reading); not called in later passes;
- volatile (0x8000), partitioned: 0x00763130 is entered with force 0 and dirty 0xFFF on every
  call, whether `+0x34` is 0 or not (C3, read). That each such call copies every element and
  refills the index buffer is **unverified** (0x00763130.md C25), and a failed stream pack
  with streamCount != 1 returns before the index refill. "Every shader pass of every draw"
  holds only under C6's unverified pass-index reading;
- any other nibble ("mutable"): packed only when `+0x34 == 0` and only per the low 12 dirty
  bits. On the partition path the skinned draw clears those bits (`AND word [a2+0x2E],0xF000`
  at 0x007677B7, re/functions/0x00767520.md C9); on the unpartitioned path 0x00767B40 clears
  them itself and (**unverified**, C14) ORs dirty 0x3 on a `skin[+0x18]` stamp mismatch.
Whether skinned bodies carry 0x8000 is **unverified** (a log of `[data+0x2E]` at this function
in the game would settle it).

C8. **derived** (C5, C7) - For volatile partitioned data and a shader with N passes, one draw
enters 0x00763130 for the same partition N times with dirty 0xFFF (whether each entry copies
everything is unverified, C7): nothing in this body or in 0x00763130 (which reads no
global, 0x00763130.md C28) remembers that the partition was packed earlier in the draw or
the frame. Every draw of the body (each eye, each shadow pass that draws it) starts again
at pass 0 - **unverified** (rests on C6's pass-index reading). **For OBVR's StreamReuse**
(derived from C7/C8, measured numbers not re-checked here): the only work a reuse can skip
at this level is the volatile repack (and a mutable repack whose bits were set again); for
static data the engine already skips it. Skipping it here would not skip the binding (C9),
which runs on every call.

vtable has SetStreamSource at method index 100 (= +0x190) and SetIndices at 104 (= +0x1A0),

**derived**: `[this+0x10]` is the D3D9 device, `chip+0x08` the vertex buffer, `record+0x20`
the per-stream strides, `record+0x30` the index buffer; the offset is always 0.

C10. **read** - The binding is unconditional once the record is non-null: no comparison with
the currently bound stream or index buffer, and SetIndices runs even when the stream count
is 0 or `record[+0x30]` is 0 (B7, 0x0077A3C9-0x0077A3D9). **derived**: one call to this
function issues `streamCount + 1` device calls; whatever redundancy filter exists sits in
the D3D runtime or DXVK (unverified).

C11. **read** - No clock and no global: data.json is empty and no instruction has an absolute

C12. **objdump** - Call sites: DrawSkinnedPrimitive 0x00767520 calls this slot at 0x007676B3

(C1) and renders the unreachable bounds arms B8/B9 as a `goto` into the loop.

## Open questions

- Who sets and advances `[this+0x34]` (C6): the shader's slot 18 (+0x48, "first pass") and
  slot 19 (+0x4C, "next pass") from 0x00767520's pass loop are the likely writers; their
  bodies would confirm the pass-index reading and whether every draw starts at 0.
- Which consistency nibble the skinned bodies' NiGeometryData carries per frame (0x8000 or
  mutable). A runtime log of `[[geometry+0xB4]+0x2E]` at this function settles it, and with it
  how much StreamReuse could save (C7, C8).
- Whether any shader class overrides slot 15 with its own body (only 32 vtables were found to
  hold 0x0077A310; a skinned shader with a different slot 15 would bypass this map).
- What the plain draw's third argument (ESI, loaded at 0x00767327) is, and whether it equals
  `[data+0x38]` (then the no-pack path F6/F7 returns the same record as the pack path).
- How many shader passes the skinned shaders (SkinShader, HairShader, ShadowLightShader) run
  per draw: with a volatile body each pass repacks (C8).
- Whether the D3D runtime / DXVK drops the redundant SetStreamSource/SetIndices calls (C10).

## Callees worth their own slice

- **0x00767B40** (whole-geometry pack, `thiscall`, five arguments, `RET 0x14`): the stamp test
  on `skin[+0x18]` that ORs dirty 0x3 into the mask is a per-frame repack trigger for unpartitioned
  skinned geometry; it also clears the dirty bits itself (C14).
- **0x00776E90** (0x00767B40's single-stream fallback; pseudocode only).
- Shader slots 18 (+0x48) and 19 (+0x4C) of NiD3DShader: the pass index at `+0x34` (C6).
- Already mapped or in this slice: 0x00763130 (scene-pass), 0x0076FE20 (declaration slot
  +0x6C, in progress in this slice).

## Layout requests

- `NiD3DShader`: +0x10 `d3dDevice` (IDirect3DDevice9*), +0x14 `renderer` (NiDX9Renderer*),
  +0x24 `shaderDeclaration` (NiDX9ShaderDeclaration*, nullable), +0x34 `currentPass` (u32;
  shared with 0x0077A1F0 and 0x007C9230).
- `NiGeometry`: +0xB4 `modelData` (NiGeometryData*), +0xB8 `skinInstance` (NiSkinInstance*)
  (shared with 0x00767520, 0x007693E0).
- `NiGeometryData`: +0x2E `consistencyAndDirty` (u16; 0x4000 static, 0x8000 volatile in the
  top nibble), +0x38 `bufferData` (NiGeometryBufferData*, whole-geometry record).
- `NiSkinPartition::Partition`: +0x28 `bufferData` (NiGeometryBufferData*).
- `NiGeometryBufferData` (the record): +0x1C `streamCount` (u32), +0x20 `streamStrides`
  (u32*), +0x24 `streamChips` (NiVBChip**), +0x30 `indexBuffer` (IDirect3DIndexBuffer9*)
  (shared with 0x00763130 and 0x00767520).
- `NiVBChip`: +0x08 `vertexBuffer` (IDirect3DVertexBuffer9*). The class name rests on the
  Gamebryo 2.2 file list `NiVBChip.h` (https://www.ymcn.org/22090.html, a file listing only)
  - unverified for this build.
