## Purpose

Answers one yes/no question for an actor and a target reference: "is `target` the first thing a
ray along my heading hits, and am I already facing the point I am heading for?" (derived, from the
steps below, all read):

1. Guards: actor, target and the actor's process (actor+0x58) non-null; the process's object from
   process vtable slot +0x410 non-null and its slot +0x0C answers false.
2. Gets a point from that object (0x0068B3F0), forms `delta = point - actor.pos` (actor+0x2C/+0x30/+0x34).
3. Range cap: FLT_MAX, or `|delta| * 0.1428767293691635` when 0x00683AA0 answers true.
4. Heading: actor vtable +0x1E0 (the heading virtual, 0x0065ABB0 for NPCs per OBVR's
   GameAddresses.h comment at lines 184-186), shifted by pi and wrapped when 0x005E0630(2) is true.
5. Facing check: `|angle(delta) - heading| < tolerance`, tolerance 0.01, or 0.1 when actor vtable
   +0x334(1) is true. Otherwise returns false without casting.
6. Builds a ray: direction = (0,1,0) turned by MakeZRotation(heading) (0x0070FDD0) and
   normalised; length = the y extent of a bound read from the actor's collision-side object
   (0x00680F30 result, +0x74/+0x84), plus 7.143836498260498 when 0x004D8B90 is false, capped by
   the range from step 3; origin = actor.pos with z raised by `0x005E0660(actor) * param_3`.
7. Casts it through an object reached from `[collisionObj+0x08]` via 0x00531DE0, vtable slot +0x88.
8. On a hit, resolves the hit (S+0x114) to a reference through 0x004806E0 then 0x004DC270 and
   returns true only when that equals `target`.

The function writes nothing outside its own stack frame and the thread's SEH chain FS:[0]
(read, see Claims). It does not read any clock or timer global (read: meta.json data_refs).
The global data it reads are the cookie 0x00B30AAC, constants in the 0x00A2xxxx-0x00A7xxxx
range, and the identity 3x3 at 0x00B26DC4, which lies in writable .data (derived) and is
constant only by assumption (see group d).
