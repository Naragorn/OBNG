## Purpose

The per-frame update of one actor in high process. In order: a short path that only ticks the actor's magic-target
effect list when a gate is closed; otherwise a time/day check on the process, an AI branch (combat/package start,
the high process's AI slot 3 or 4) for a living actor or a dead-actor branch (corpse timer, respawn check), the
actor's slot +0x368 (0x005FAAE0), a one-shot "3D just loaded" branch (Havok collision state set on the node tree or
an animation reset and skeleton update), then Actor::Update 0x00603CA0 (which holds movement, the character
controller and the animation step - not followed here), and last an exterior cell re-home check for a non-player
actor (D, from the control flow below).

**Recursion (answer to the slice question): 0x00605770 does not call itself.** asm.s holds no `CALL 0x00605770`,
meta.json's callee list does not contain it, and pseudo.c has no self call (R). None of its virtual calls go through
[vtbl+0x1C0] (R: the offsets are 0x1A0, 0x380, 0x388, 0x198 (twice), 0x19C, 0x20C, 0x368, 0x170 (twice), 0x278,
0x1C8, 0x1E0, 0x164 (three times), 0x174 on the actor). The "twice" in the seed most likely comes from the loop
0x00677EC0, which calls slot +0x1C0 at two sites (R, above); that this slot is 0x00605770 is U (see Callers). A callee calling back into slot +0x1C0 is not
excluded (U). The recursive callee here is 0x008AB440 (it calls itself on each child of an NiNode, R in
rea-all/0x8ab440.c, pseudocode only).

## Calling convention and parameters

- `__thiscall`: ECX = the actor, moved to ESI at 0x00605774 (R). Ghidra's `__fastcall(int*)` is wrong about the
  stack argument (R vs. asm).
- One stack argument, a float: `RET 0x4` at 0x0060583B and 0x00605DAF (R). Callee cleans the stack.
- The argument is the frame time handed down by the loop: the loop pushes `[ESP+0x38]` / `[ESP+0x20]` as float
  before the slot call (R, 0x00677FF4, 0x006782AA). It is read at [ESP+0x4C] (after three pushes) at 0x006059DC
  (AI slot choice and slot 3's argument) and 0x00605D27 (Actor::Update's argument) (R). pseudo.c names it
  `unaff_retaddr`, a misreading (R vs. asm).
- In the short path the argument's stack slot ([ESP+0x44] with one push) is **overwritten** with a computed delta at
  0x006057BB / 0x006057E7 / 0x00605809 and passed on to 0x006A2280 (R).
- Frame: `SUB ESP,0x3C`; saves ESI, then EBX, EDI only on the long path (R).

## Order of steps (slice question 2)

1. Day check / process time compare (L1-L6) - reads the game calendar, may set a flag through an extra's object.
2. 0x005F0410 when vt+0x1A0 and (vt+0x380 or vt+0x388) (L7-L8) - combat-side, not followed.
3. **AI** (A1-A12): combat package start 0x005F8000, 0x005F7CF0, then the high process's AI slot 3 or 4 with dt.
   Or the dead branch (D1-D10), or neither (D1 taken: vt+0x198(0) == 0 jumps straight to 0x00605B58).
4. Actor slot +0x368 = 0x005FAAE0 (P1), with the process manager's float [0x00B3BCF0], not dt.
5. One-shot 3D reset (R1-R9): Havok collision state of the node tree (0x008AB440) or **animation** reset and a
   skeleton update (0x00476D10, then 0x00471C00 + ApplyAnimData 0x00471F20 via 0x00474510).
6. **Actor::Update 0x00603CA0(dt)** (U1-U2), called at 0x00605D31: it calls 0x00471C00 at 0x00604257 and
   ApplyAnimData 0x00471F20 at 0x006043DC (R, 0x00603CA0/asm.s), so the per-frame skeleton update is reached from
   this function through this callee (D; under which condition inside 0x00603CA0 is that file's finding, pseudocode
   rea-all/0x603ca0.c:275-338 shows `if (uVar8 != 0)`). knowledge/render-thread-outside-the-pass.md:104-108 measured
   the chain 0x00471F20 <- 0x00603CA0 (read there). Movement and the character controller live inside it per the
   manifest and backlog (not followed here, U for this file).
7. Cell re-home (C1-C5).

So AI comes first, animation and the character controller come later inside Actor::Update (D from the order of the
calls at 0x00605A09/0x006059FD, 0x00605B7F, 0x00605D31). What the later steps read from the earlier ones is not
visible at this level: the steps hand nothing to each other through this function's registers or locals except dt
and the process pointer [this+0x58], re-read each time (R); any hand-over goes through the actor and process objects
inside the callees (U).
