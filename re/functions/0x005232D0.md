# 0x005232D0 - TESNPC::GetBaseActorValue (proposal)

Slice: actor-movement. Map only, not rebuilt.

## Identity

- Address: 0x005232D0 (body 0x005232D0-0x0052330E, 63 bytes, 17 instructions)
- Seed name: "Second caller of the controller's update (name unknown)"
- Proposed name: `TESNPC::GetBaseActorValue` (0x005232D0) - a proposal until refutation.

**The seed name is refuted.** The function calls neither 0x00896000 nor any
virtual function: its only call sites are `CALL 0x00565C50` at 0x005232E4 and
`CALL 0x00519D90` at 0x00523306 (read, asm.s). The measured return address
0x005232E9 is the instruction after the call to 0x00565C50 (read, asm.s).
0x005232E9 is not a live frame on a call chain into 0x00896000: it would be live
only for a sample taken inside 0x00565C50 itself, and such a sample could not lie
under the controller's update. **derived**, on the condition that 0x00565C50
makes no call in its instructions - so far only the rea-all pseudocode of
0x00565C50 shows that; its instructions (0x00565C50-0x00565C97) were not read,
and reading them would settle it (consistent with
knowledge/actor-frame-map.md:653 "the deeper words can be stale").

## Purpose

Returns one actor value of an NPC base form, by actor-value code:

- codes 12..32 (0x0C..0x20): the range is read (0x005232D7-0x005232DF,
  unsigned JA); the result is the zero-extended byte at
  `[this+0xEC+(signed char)0x00565C50(2, code)]` (read, 0x005232E1-0x005232EC).
  That `0x00565C50(2, code) = code - 12` is derived from pseudocode only
  (rea-all pseudocode of 0x00565C50: `case 2: return param_2 + -0xc;`); the asm
  of 0x00565C50 would make it read. In the
  engine's actor-value numbering 12..32 are the 21 skills (unverified: the
  numbering is from memory, not read here).
- codes 37..39 (0x25..0x27): returns 0.
- every other code: delegates to 0x00519D90 on the same `this`.

The body 0x005232D0-0x0052330E itself writes only its stack frame and reads
only `[this+0xEC+idx]` (read). On the default path it hands off to 0x00519D90,
whose rea-all pseudocode calls several functions and makes indirect calls via
`(this+0x24)->vtbl+0x48/+0x4C`; whether the whole call touches Havok state, the
clock, globals or memory is **unverified**.

## Calling convention and parameters

- `__thiscall`: `this` in ECX, moved to ESI at 0x005232D1 (read).
- One stack argument `[ESP+0x8]` after the PUSH ESI = the first stack argument,
  the actor-value code, loaded at 0x005232D3 (read).
- Callee cleans: `RET 0x4` at 0x005232F8 and at 0x0052330C (read).
- Return value in EAX: a zero-extended byte (0x005232EC MOVZX), 0 (0x005232DA
  XOR EAX,EAX, untouched on the 37..39 path), or whatever 0x00519D90 returns in
  EAX (tail of the call at 0x00523306) (read).
- ESI is saved and restored (0x005232D0 / 0x005232F7, 0x0052330B) (read).
- Callees: 0x00565C50 is cdecl - two pushes at 0x005232E1/0x005232E2, cleaned by
  the caller `ADD ESP,0x8` at 0x005232F4 (read). 0x00519D90 is thiscall with
  ECX=this (0x00523304) and one push (0x00523303), and the caller does not clean
  the stack after it, so it cleans its own 4 bytes (derived from 0x00523303 and
  the absence of an ADD ESP before 0x0052330C).

Note on pseudo.c: it agrees with the instructions; it hides that 0x00565C50 is

does not matter on any reachable path (derived from B1 and 0x00565C50's case 2).

## Claims

1. 0x005232D0 is the primary-vtable slot 74 (offset 0x128) of TESNPC: the only
   occurrence of the dword 0x005232D0 in the EXE's image is at 0x00A53EFC in
   .rdata, inside the vtable that starts at 0x00A53DD4, whose RTTI complete
   object locator 0x00ABE648 names `.?AVTESNPC@@` (offset 0). **unverified**:
   the export does not contain the vtable bytes, and xobse.csv names only
   `TESCreature_vtbl` 0x00A5324C and `RTTI_TESNPC` 0x00B02FB4, not the TESNPC
   vtable. Reading the dword at 0x00A53EFC and the COL before 0x00A53DD4 in the
   reference binary (md5 cdd2f0c5...) would settle it. The claim rests on a byte
   scan of
   `Oblivion - A Painted World/Stock Game/Oblivion.exe`, whose md5
   `66a6c2ef97ddea75f43d916aca8d164d` differs from the reference
   `cdd2f0c5eff198d4f26b7b5b54ce4930`; the function's 63 bytes in that copy are
   identical to bytes.bin (compared), so the layout is very likely the same, but
   the vtable was not read in the reference binary.
2. The same virtual on TESCreature (vtable 0x00A5324C, xOBSE `TESCreature_vtbl`)
   is slot 74 = 0x0051D540 - the "same call on another class's vtable" is
   0x0051D540, not 0x005232D0. **unverified** (same non-reference copy as claim
   1; 0x0051D540 not read). Reading the dword at 0x00A5324C+0x128 in the
   reference binary would settle it.
3. 0x005232D0 is not a caller of the character controller's update 0x00896000:
   no call to it and no indirect call in the body. **read** (asm.s, all 17
   instructions; meta.json callees = 0x00519D90, 0x00565C50 only).
4. 0x005232E9 is not a live frame on a call chain into 0x00896000. It would be
   live only for a sample taken inside 0x00565C50 itself, and such a sample
   could not lie under the controller's update. **derived** from claim 3, on the
   condition that 0x00565C50 makes no call in its instructions; so far only the
   rea-all pseudocode shows that. Reading the instructions of 0x00565C50
   (0x00565C50-0x00565C97) would settle it.
5. The range 12 <= code <= 32 is **read** (0x005232D7-0x005232DF, unsigned JA),
   and so is that the result is the zero-extended byte at
   `[this+0xEC+(signed char)0x00565C50(2,code)]` (0x005232E1-0x005232EC).
   `0x00565C50(2,code) = code-12` is **derived from pseudocode only** (rea-all
   case 2); the asm of 0x00565C50 is needed to make it read.
6. When 37 <= code <= 39 the result is 0. **read** (0x005232DA, 0x005232FB-0x00523301).
7. When code is outside both ranges the result is 0x00519D90's EAX. **read**
   (0x00523303-0x0052330C).
8. The body 0x005232D0-0x0052330E itself writes only its stack frame and reads
   only `[this+0xEC+idx]`. **read** (asm.s; data.json empty). On the default
   path it hands off to 0x00519D90, whose rea-all pseudocode calls several
   functions and makes indirect calls via `(this+0x24)->vtbl+0x48/+0x4C`; the
   transitive claim (no write, no global, no Havok, no clock) is **unverified**.
9. Codes 12..32 are the skills, 37..39 bounty/fame/infamy. **unverified** (the
   numbering is not read in this slice; xOBSE's `g_baseActorValueNames`
