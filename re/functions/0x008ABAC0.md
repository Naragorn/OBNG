## Purpose

Writes a new 16-byte position into the object at `this+0xA0..+0xAF` (= `this+0x70+0x30`, where `this+0x70` is
the transform argument passed to the shape; that +0xA0 is the transform's translation is unverified), then - only when `this+0x08` (the Havok world) is non-null - asks the object's shape at `this+0x14`
for a world AABB grown by `0.5 * [[world+0x74]+0x08] + extraTolerance`, and hands that AABB to 0x008DE950, the
world's broad-phase update for this object. It is the same position-then-AABB-then-broad-phase sequence that
0x008ECC60 runs before its cast (knowledge/actor-frame-map.md section on 0x008ECC60), without the cast.

The clock: no read or write of any clock or time global in the body (read: the only data reference is
0x00A3D65C, the 0.5f constant). Whether 0x008DE950 touches a clock is not answered here (unverified).

the two pushes is 16-aligned (derived from 0x008ABAC3, 0x008ABAC6, 0x008ABACF, 0x008ABAD7, 0x008ABAF2) - the
AABB output buffer (min, max as two 16-byte vectors; size derived from the frame, layout unverified).
Return value: the body sets no result in EAX (read); at RET EAX holds `[this+0x08]` = 0 on the no-world flow
(loaded at 0x008ABAD2) or 0x008DE950's return on the world flow (derived from the asm). That the function is `void` (no caller uses EAX) is **unverified**: it needs the four call sites' asm.

Both MOVAPS (0x008ABACC load, 0x008ABAD8 store) fault on a pointer not 16-aligned, so `position` and
`this+0xA0` must be 16-aligned (derived from the instruction semantics).

## Claims

1. When called, it stores the 16 bytes at `[position]` into `this+0xA0..+0xAF` after the TEST at 0x008ABAD5 but before the branch (JZ 0x008ABADF), so on both flows. **read** 0x008ABACC, 0x008ABAD5, 0x008ABAD8, 0x008ABADF.
2. When `[this+0x08] == 0`, it returns after that store without calling anything. **read** 0x008ABAD5, 0x008ABADF.
3. When `[this+0x08] != 0`, the tolerance passed to the shape is `[[[this+8]+0x74]+8] * 0.5f + extraTolerance`, computed in x87 registers (FLD/FMUL/FADD) at the precision set by the FPU control word, which this body does not set (which precision is in effect: **unverified**); only the FSTP at 0x008ABAFE rounds to 32-bit float. A class-A rebuild must reproduce the FPU precision and rounding in effect, not assume single-precision intermediates. **read** 0x008ABAE4, 0x008ABAEA, 0x008ABAF7, 0x008ABAFE; 0.5f from data.json for 0x00A3D65C.
4. The virtual call at 0x008ABB02 is made with ECX = `[this+0x14]` and stack args (this+0x70, tolerance, &local) in that order. **read** 0x008ABAE7, 0x008ABAF6, 0x008ABAFA/0x008ABAFE, 0x008ABB01. That it is a callee-clean thiscall is **unverified**: MOV ESP,EBP at 0x008ABB11 restores ESP, so the cleanup is not observable in this body.
5. 0x008DE950 is called with ECX = this and arg = EDI. **read** 0x008ABAF2, 0x008ABB05-0x008ABB0A. That EDI still points at the local buffer the virtual call received is **derived** from the MSVC callee-saved register convention (EDI preserved across calls), since the vt+0x0C target was not read.
6. `this+0xA0` is the translation of a transform at `this+0x70`. **unverified**. Read: 0x70+0x30 = 0xA0 and `this+0x70` is passed as arg1 of the shape virtual (0x008ABAFB). That the first 0x30 bytes are rotation rows and +0x30 the translation needs the hkTransform layout or the vt+0x0C target's reads of arg1; neither is in this export. Settled by reading one concrete shape's vt+0x0C (for example the capsule getAabb) and seeing it load the translation from arg1+0x30.
7. `this+0x08` is the Havok world. **derived** from 0x008DE950 using `[this+8]+0x88/+0x8C` as its lock counters with the same ECX (read 0x008DE956-0x008DE96A) and knowledge/actor-frame-map.md (0x008ECC60).
8. The receiver is a phantom (the character proxy's shape phantom), not the proxy. **derived** from caller pseudocode: 0x008AC080 and 0x008AC1E0 call it on an object reached via `proxy+0x30` with `extraTolerance = [proxy+0x5C] + [proxy+0x58]` (rea-all pseudocode, reading aid; call-site asm not read here -> the caller-side half is **unverified**).
9. The body reads and writes no clock or time global. **read** (only data ref 0x00A3D65C; no other absolute address in asm.s).
10. The body itself writes only `this+0xA0..+0xAF` and its stack (read 0x008ABAD8). Races between two actors running this concurrently can sit in: 0x008DE950 (world +0x88 incremented without LOCK, MOV/INC 0x008DE9A1/MOV at 0x008DE995-0x008DE9A2, read; broad phase, Up); the unfollowed shape virtual `[[this+0x14]]+0x0C` (0x008ABB02), whose writes are **unverified** (shared shape objects between phantoms are not excluded); the read of the world-shared tolerance `[[world+0x74]+8]` at 0x008ABAE4, which 0x008AD070 temporarily modifies (knowledge/actor-frame-map.md line 407, Up); and the +0xA0 write itself, which goes to an object other actors read (knowledge/actor-frame-map.md line 408). **derived** from claims 1, 3, 4 and the cited lines.

## Pseudocode vs instructions

- pseudo.c shows the position copy as four dword moves; the instructions use one aligned MOVAPS load and store
  (0x008ABACC, 0x008ABAD8). The instructions win: the copy needs 16-byte alignment of both pointers.
- pseudo.c drops the `this` (ECX) of both calls: the virtual call is a thiscall on the shape `[this+0x14]`
  (0x008ABAE7, 0x008ABB02), and 0x008DE950 is called with ECX = this (0x008ABB08). The instructions win.
- The rea-all decompile (`0x8abac0.c`) gives it as `FUN_008abac0(undefined4*, float)` without `this`; the asm
  shows ECX used (0x008ABAD0). The instructions win.
