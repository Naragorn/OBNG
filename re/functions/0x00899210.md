## Purpose

A thin wrapper around the pending-operation queue drain, bracketed by two profiler markers:

1. When the thread's profiler stream has room, writes a begin marker `{&"TtPendingOps", RDTSC low}`
   (R 0x00899224-0x00899251).
2. Clears the world's pending-operation counter `[this+0x84] = 0` (R 0x00899258).
3. Calls 0x008D8BF0 with ECX = `[this+0x80]` (proposed: the pending-operation queue object)
   (R 0x00899262-0x00899268).
4. When the stream has room, writes an end marker `{0x00A9610C, RDTSC low}` (R 0x0089926D-0x0089929C).

It does not touch the lock counters `[this+0x88]`, `[this+0x8C]` or the byte `[this+0x90]` (R: no
access to those offsets in asm.s). Its callers test them before calling (0x008DE950: R
0x008DEB15-0x008DEB2F; the other 34 callers: Up, see Control flow). The queue's operations
therefore run while `[this+0x88] == 0` and `[this+0x90] == 0` at entry (D from the caller's test at
0x008DEB15-0x008DEB2F; for other callers Up).

## Calling convention and parameters

- `this` in ECX (R: `[ECX+0x84]` and `[ECX+0x80]` at 0x00899258/0x00899262 with ECX never set in the
  body before them). pseudo.c types it `__fastcall`; with one register argument and no stack
  argument this is indistinguishable from `__thiscall` (D). The caller 0x008DE950 loads ECX with the
  world at 0x008DEB12 `MOV ECX,[ESI+0x8]` (R in its export).
- No stack arguments: plain `RET` at 0x008992A6 (R); nothing on the stack is read above the saved
  registers (R).
- Saves and restores EBX, ESI, EDI, EBP only inside the first marker branch (R 0x00899232/0x00899257).
  Reserves one dword of scratch via PUSH ECX (0x00899210) / POP ECX (0x008992A5); ECX is not
  preserved: the slot is overwritten with the RDTSC low word at 0x00899243 (`[ESP+0x10]`) and
  0x0089928E (`[ESP+0xC]`), so on return ECX holds the incoming `this` only when neither marker was
  written, otherwise a TSC value (R for the instructions; D for the return value of ECX).
- `this` is not preserved: ECX is overwritten with `[this+0x80]` at 0x00899262 and `this` is not
  read after the call (R).
- No return value: EAX holds whatever the TLS reload or RDTSC left (R 0x0089926D, 0x0089928C); no
  caller was checked for reading EAX (U), 0x008DE950 does not (R 0x008DEB36.. in its export is
  outside this map, U).
- Stack scratch: the PUSH ECX slot is reused as a spill slot for the RDTSC low word
  (`[ESP+0x10]` at 0x00899243 with EBP pushed, `[ESP+0xC]` at 0x0089928E without; D from the push
  count 5 resp. 4).

The two branches are independent (R: B2 re-reads the TLS block at 0x0089926D). Test flows for a
rebuild: room/room, room/full, full/room (the drain filled the stream), full/full. The drain at
0x00899268 is unconditional (R).

The preconditions live in the callers, not here (R for 0x008DE950 at 0x008DEB15-0x008DEB2F:

0x008CD4E0, 0x008A9D10.

## The drain 0x008D8BF0 as far as it answers the slice's questions (read in its export)

- Swap-out: the queue's array, count and capacity are swapped with a stack-local inline array of
  16 entries x 0x14 bytes, capacity word 0x80000010 (R 0x008D8C00-0x008D8C52). New pushes during the
  drain therefore land in that fresh array (D).
- `[world+0x98]` is incremented before the loop (R 0x008D8C56) and decremented after it (R
  0x008D8DCC).
- Order: the loop runs the swapped-out entries by ascending index 0 .. count-1 (R `INC EAX; CMP;
  JL` 0x008D8D94-0x008D8D9B), i.e. FIFO by push order (D from the push appending at index `count`,
  0x008D885A-0x008D8875). **Not strict FIFO overall:** after each entry, when the queue's count
  `[queue+4]` is non-zero (an entry pushed while the previous one ran), 0x008D8BF0 calls itself
  recursively (R 0x008D8D7E-0x008D8D87), so operations queued by entry i run before entry i+1 (D).
- Dispatch: type byte `[entry+0]`, `type-1` checked `<= 0x21` (R 0x008D8C7A-0x008D8C81), then the
  jump table 0x008D9458 (data.json of 0x008D8BF0, 32 listed entries).
- Type 0x11 (table index 0x10 -> 0x008D90E8, data.json): when `[[entry+4]+0x08] == [queue+0x0C]`
  (the object still belongs to this world, R 0x008D90E8-0x008D90F1) it calls 0x008DE950 with ECX =
  `[entry+4]` (the phantom) and the stack argument `[entry+8]` (the AABB copy) (R 0x008D90F3-0x008D90F7);
  then decrements the object's 16-bit reference count `[obj+6]` when `[obj+4] != 0` and calls its
  vtable slot 0 with 1 (proposed: deleting destructor) when it hits 0 (R 0x008D90FC-0x008D9115);
  then frees the 0x20-byte AABB copy through `[0x00BA7D98]` vtable +0x14 with (ptr, 0x20, 0x24)
  (R 0x008D9117-0x008D9127). 0x008DE950 queues type 0x11 itself when the world is locked
  (re/functions/0x008DE950.md, R there).

## Read and write list by group

- **(a) the object it is called on (the world, proposal):** R `[this+0x80]` 0x00899262; W
  `[this+0x84] = 0` 0x00899258. No other access in the body (R).
- **(b) other objects of the same kind:** none in the body (R).
- **(c) Havok world, bodies, phantoms, broad phase, pending queue:** the queue `[this+0x80]` is
  handed to 0x008D8BF0, which swaps out and empties it, writes `[world+0x98]` and runs every queued
  operation (bodies, phantoms, broad phase via 0x008DE950 for type 0x11, and 30-odd other types) -
  through the callee, not followed beyond what is listed above (U for the other types).
- **(d) globals, singletons, thread-local slots:** R `_tls_index` [0x00BA9DE4] at 0x00899212 (its file
  image value is 0, data.json; the runtime value is set by the loader, U); R `FS:[0x2C]` (TLS array)
  0x0089921A; R the TLS block pointer 0x00899221 and again 0x0089926D; R TLS +0x1A4 / +0x1A8 as in
  the table; W TLS +0x1A4 at 0x00899251 and 0x0089929C; W the stream entry's +0x00 at 0x0089923B /
  0x00899286 and +0x04 at 0x0089924B / 0x00899296. All per thread (D: indexed by the thread's own TLS
  array). The callee additionally reads `[0x00BA7D98]` (free) and TLS +0x19C / `[0x00BA7D9C]`
  (stack allocator) (R 0x008D8DDA-0x008D8DF4, 0x008D9117).
- **(e) heap and Havok's stack area 0x00B47900:** nothing in the body (R). Own stack frame: W the
  spill slot at 0x00899243 and 0x0089928E. Through the callee: frees via `[0x00BA7D98]` vt+0x14 and
  the stack allocator from TLS +0x19C or `[0x00BA7D9C]` (R in 0x008D8BF0; whether that reaches
  0x00B47900 is U).

## Clock

The function reads the time stamp counter twice, `RDTSC` at 0x00899241 and 0x0089928C (R), and
stores only EAX, the low 32 bits; EDX is discarded (R). It writes no game clock and reads no timer
global (R, whole asm.s). Both reads are inside B1/B2, so when the stream is full no clock is read (R).

## Claims

1. `this` arrives in ECX and the function takes no stack arguments (`RET` with no operand). (R 0x00899258, 0x00899262, 0x008992A6)
2. It writes `[this+0x84] = 0` before the drain. (R 0x00899258)
3. It calls 0x008D8BF0 with ECX = `[this+0x80]`, unconditionally. (R 0x00899262-0x00899268)
4. It does not read or write `[this+0x88]`, `[this+0x8C]` or `[this+0x90]`; the gate is in the callers. (R, whole asm.s)
5. When the TLS profiler stream has room, it writes a 12-byte record tagged 0x00A96B48 ("TtPendingOps", data.json) with the RDTSC low word before the drain, and one tagged 0x00A9610C after it. (R 0x0089922A-0x00899251, 0x00899276-0x0089929C)
6. The tag at 0x00A9610C is the 2-character string "Et" (bytes `45 74 00 00`, data.json; data.json gives no defined type). (D from the bytes)
7. Queued operations run in push order within one drain, but operations pushed while one runs are drained recursively before the next older one. (D from R 0x008D8D7E-0x008D8D9B and 0x008D885A-0x008D8875)
8. Type 0x11 re-runs 0x008DE950 on the phantom with its saved AABB when the phantom is still in this world, then, only when word `[obj+4] != 0` (0x008D90FF `CMP word [ECX+4],0` / 0x008D9104 `JZ 0x008D9117`), decrements word `[obj+6]` and calls vtable slot 0 with 1 when it reaches 0; when `[obj+4] == 0` it goes straight to freeing the 0x20-byte AABB copy, which happens in both cases. (R 0x008D90E8-0x008D9127)
9. The drain brackets its loop with `[world+0x98]` += 1 / -= 1. (R 0x008D8C56, 0x008D8DCC)
10. None of the world fields touched here or in the drain is written with a LOCK prefix. (R for 0x00899258, 0x008D8C56, 0x008D8DCC, 0x008D8869)
11. Two threads that each reach `[world+0x88] == 0` could both enter 0x00899210 and both drain the same queue object; nothing in this function prevents it. (D from claims 3, 4, 10; whether 0x008A7720 in the push guards the drain too is U)

- The meaning of `[world+0x98]` (drain depth?) and who reads it (U).

- What the stream entry's +0x08 holds (written by other markers?) and who consumes the TLS stream +0x1A4 (U).

- Whether any of the 35 callers runs off the main thread (U; needs a measured run or the thread map).
