## Purpose

For one ShadowSceneLight (`this`) and one scene object (the stack argument), test the
object against the light (`IsInRange(object, this->+0x100)`) and, when it is in range,
either descend into it (a node) or hand it to `AddGeometry` (a geometry). An object
that is out of range is not descended into: its whole subtree is skipped. Around the
test and the descent the light's plane mask `+0x1B0` is saved and written back, so the
narrowing `IsInRange` makes for one object holds for exactly that object's subtree.

In order, per call (read, asm.s):

1. Gate on the global dword 0x00B42F48: zero returns AL = 0 at once (no test, no write).
2. Save `this+0x1B0` into the stack slot reserved by `PUSH ECX`.
3. `IsInRange(object, this+0x100)` (thiscall on `this`, ECX unchanged since entry).
4. Out of range: restore the mask, return AL = 1.
5. In range, `object->vt[+0x08]()` non-null (a node, proposed `GetAsNiNode`):
   - exact RTTI `NiRTTI_NiSwitchNode`: only the active child (0x007C59E0), and only
     when it is non-null, 0x0049FFC0 returns true and its flags bit 0 is clear;
   - any other RTTI: every slot `0 .. count-1` of the children array (+0xB0 data,
     +0xB6 u16 count, re-read after every child), recursing into each child that is
     non-null, has `+0x2C != 0.0` (NaN counts as non-zero) and flags bit 0 clear
     (read, 0x007D5AA4-0x007D5AB8). The switch path has no inline `+0x2C` compare;
     its radius condition is whatever 0x0049FFC0 returns (unverified).
6. In range, not a node, `object->vt[+0x10]()` non-null (a geometry, proposed
   `GetAsGeometry`): `vt[+0x10]` is called a second time and its result goes to
   `this->AddGeometry(...)` 0x007D5790.
7. Restore the mask, return AL = 1.

Subsystems touched, in order: one global gate, the light's plane block (+0x1B0 save),
the range test 0x007D2EA0 (NiRTTI on the source light, NiBound/plane math or the CRT
square root, per its own file), virtual type queries on the object (+0x08, +0x04
GetRTTI on the node, +0x10), the scene graph's child arrays, the light's geometry
list through 0x007D5790 (which takes a critical section and touches the shader
property's light list, knowledge/shadow-light-list-remove.md), the plane block again
(+0x1B0 restore). This body reads or writes no clock, allocates nothing, takes no
lock itself.

Who walks: 0x007D6900 is the entry. Per the rea-all pseudocode (a reading aid, not
re-checked against its instructions here) 0x007D6900 takes an object, skips null,
calls `vt[+0x08]` on it and enters this walk with the node only when the node is
non-null, the object's flags bit 0 is clear and the node's `+0x2C != 0.0`; its own
callers are 0x004073D0 (per frame, per drawn actor-shadow light: on the scene root
[0x00B333CC], and on the light's caster +0x130 when [0x00B06F0C] != 0 -
re/functions/0x004073D0.md claim 12), 0x007C5F60 (rescan after the light moved, per
child of the ShadowSceneNode, knowledge/shadow-light-list-remove.md) and 0x007C5D00
(per light of the ShadowSceneNode's list +0xE8, on one subtree; rea-all pseudocode
only).

## Calling convention and parameters

- `__thiscall`: ECX = `this` (the ShadowSceneLight), moved to EBP at 0x007D59E9 and
  used only through EBP; ECX still holds it at the IsInRange call 0x007D5A0B (no
  instruction between 0x007D59E9 and 0x007D5A0B writes ECX) (read). The type is
  derived: 0x007D2EA0.md reads the same object as the ShadowSceneLight, and the
  callers' `this` are the shadow scene's lights (knowledge/shadow-light-list-remove.md).
- One stack argument, the object (an NiAVObject: node or geometry): at entry [ESP+4],
  read as `[ESP+0x10]` at 0x007D59FB after PUSH ECX/EBP/EDI, kept in EDI (read).
- Callee cleans: `RET 0x4` on all four exits (0x007D59F1, 0x007D5A89, 0x007D5AE0,
  0x007D5B11) (read).
- Return: AL. `XOR AL,AL` (0x007D59ED) on the gate exit, `MOV AL,1` (0x007D5A85,
  0x007D5ADC, 0x007D5B0D) on the three others (read). The upper 24 bits of EAX are
  not defined on the gate exit (EAX is never written before it) (read). The two
  recursive calls ignore the result: no TEST follows 0x007D5A74 or 0x007D5ABD (read).
  Derived from those four writes: AL means "the walk is enabled", not "the object was
  in range".
- Registers: EBP, EDI, ESI pushed and popped (ESI only on the path after IsInRange
  succeeded, PUSH at 0x007D5A1D, POPs at 0x007D5A7D, 0x007D5AD4, 0x007D5B01); EBX
  not used; ECX on return holds the saved mask (POP ECX at 0x007D5A88, 0x007D5ADF,
  0x007D5B10 pops the slot that holds it) or, on the gate exit, the caller's ECX
  (read).
- Stack frame, ESP0 = ESP at entry: ESP0-4 = the `PUSH ECX` slot, used as the local
  `savedMask` (written 0x007D59FF as `[ESP+0x8]` with ESP = ESP0-12; read 0x007D5A79
  and 0x007D5AD0 as `[ESP+0xC]` with ESP = ESP0-16, and 0x007D5B02 as `[ESP+0x8]`
  with ESP = ESP0-12) (read; offsets derived from the pushes). 16 bytes of frame plus
  4 bytes argument plus 4 bytes return address per recursion level, no SEH frame
  (derived from the pushes). The recursion depth is bounded only by the scene graph's
  depth (derived: there is no depth counter in the body).
- No x87 state is left behind: the only x87 work is `FLDZ` / `FCOMP` at
  0x007D5AA8/0x007D5AAA (one push, one pop) (read).

## Claims

C1. **read** - The only exit that does not return AL = 1 is the gate: [0x00B42F48] ==
0 gives `XOR AL,AL` / `RET 4` (0x007D59E1-0x007D59F1) before `this+0x1B0` is read and
before any call. Every other exit sets AL = 1 (0x007D5A85, 0x007D5ADC, 0x007D5B0D),
whatever IsInRange answered.

C2. **read** - The two recursive calls (0x007D5A74, 0x007D5ABD) and the AddGeometry
call (0x007D5AFC) are followed by no test of their result.

C3. **read** - The mask save happens once per call after the gate (0x007D59F4 read,
0x007D59FF store to the slot), before IsInRange (0x007D5A0B). Every exit after
0x007D5A0B passes through one of three stores `MOV [EBP+0x1B0],ECX` with ECX loaded
from the slot (0x007D5A79/0x007D5A7F, 0x007D5AD0/0x007D5AD6, 0x007D5B02/0x007D5B07),
and there are exactly four RET instructions in the body (0x007D59F1, 0x007D5A89,
0x007D5AE0, 0x007D5B11).
**derived** (from C3 and C1): no path out of this function leaves `+0x1B0` different
from its value at entry, as far as the writes of this body go; any write a callee
makes (IsInRange's bit clears, anything 0x007D5790 might do) is overwritten on the
way out. The gate exit does not need a restore because nothing has been called.

C4. **derived** (from C3 and the order 0x007D5A0B before 0x007D5A74/0x007D5ABD) - As
far as this body goes, the children of an in-range node start with the mask as
IsInRange left it for their parent (the parent's narrowing), each child's own
narrowing is undone when that child returns, so siblings do not see each other's
narrowing. The narrowing is per subtree, unlike 0x007C6100 (re/functions/0x007D2EA0.md
C8/C18). This rests on an **unverified** assumption: the virtual calls `vt[+0x08]` /
`vt[+0x04]` and the helpers 0x007C59E0 / 0x0049FFC0, which run between IsInRange
(0x007D5A0B) and the recursion, do not write the light's `+0x1B0`. They get ECX =
object / node / child rather than the light (read), but their bodies are not read;
reading them would settle it.

C5. **read** - IsInRange is called exactly once per call that passes the gate, at
0x007D5A0B, with ECX = `this`, arg1 = the object (EDI), arg2 = `[this+0x100]`; the
call site leaves 8 bytes for the callee to clean (no ADD ESP after).
**derived** (C5 and B2-B14): every object the walk visits costs exactly one IsInRange
call, so the return-site counter at 0x007D5A10 counts visited objects, both in range
and out of range. **measured** (artifacts/shadow/obng-scene-pass/20261030-101556/OBNG.log,
the steady Walker windows): ~2.0-2.4 M per 10 s at 0x007D5A10 (1 984 386, 2 108 163,
2 445 829, 2 412 800, 2 239 723, 2 395 030); knowledge/culling-and-draw-setup.md:199
gives it as about half of ~7 400 IsInRange calls per frame. The counter covers every
caller of 0x007D6900, not only 0x004073D0.

C6. **read** - An out-of-range object is not queried at all: B2 jumps straight to the
restore, before the first `MOV EDX,[EDI]` (0x007D5A18). Its subtree is skipped.

C7. A child is visited (IsInRange called on it) only when the parent node was in
range, and then, split by node kind:
- **read** (generic node, 0x007D5AA4-0x007D5AB8): every child slot that is non-null,
  whose `+0x2C` float does not compare equal to 0.0 (radius 0.0 and -0.0 are skipped,
  NaN counts as non-zero and is not) and whose byte `+0x18` bit 0 is clear.
- **read** for the tests, **unverified** for the radius meaning (exact NiSwitchNode,
  0x007D5A50-0x007D5A6B): only 0x007C59E0's result, when it is non-null, 0x0049FFC0
  (CALL at 0x007D5A5A) returns true, and its flags bit 0 is clear. There is no inline
  `+0x2C` compare on this path; whether 0x0049FFC0 is the `+0x2C != 0.0` test is
  unverified until its instructions are read.
The function never tests its own argument's `+0x18` or `+0x2C`; the caller does (for
the root: 0x007D6900, per the rea-all pseudocode, unverified at instruction level).

C8. **read** - The switch-node test is an exact compare of the GetRTTI result with
the address 0x00B3FD70 (0x007D5A35-0x007D5A45), not an IsKindOf walk.
**derived** (C8 and re/symbols/xobse.csv:1739, `NiRTTI_NiLODNode` at 0x00B3FD68, a
different object): a node whose RTTI is NiLODNode's - or any other class's than
exactly NiSwitchNode - is walked over all its children. Whether NiLODNode derives
from NiSwitchNode in this build (so that this differs from 0x007C7050, which the
rea-all pseudocode shows using 0x00560920 on the same RTTI) is **unverified**.

C9. **read** - On a switch node only the result of 0x007C59E0 (ECX = the node, at
0x007D5A47-0x007D5A49) is a candidate, and it is recursed into only when 0x0049FFC0
(ECX = that child) returns AL != 0 and its flags bit 0 is clear (0x007D5A4E-0x007D5A74).
What 0x007C59E0 and 0x0049FFC0 compute (active child by index +0xE0 bounded by
+0xB6; `+0x2C != 0.0`) is **unverified** - rea-all pseudocode only, not their
instructions. If 0x0049FFC0 is the radius test, the switch path applies the same two
child filters as the plain-node loop, in the same order (radius, then flags)
(derived, conditional on that).

C10. **read** - A geometry is recognised by `vt[+0x10]` returning non-null after
`vt[+0x08]` returned null; `vt[+0x10]` is then called a second time and the second
result is passed to 0x007D5790 (0x007D5AE3-0x007D5AFC). A node is never passed to
0x007D5790 here.
**unverified** (rests on knowledge/shadow-light-list-remove.md:24 and :63, not on this
export): 0x007D5790 = `ShadowSceneLight::AddGeometry(P)`, `ret 4`, AddHead into the
light's `NiTPointerList<NiPointer<NiTriBasedGeom>>` at +0xE4; so the walk would collect
the in-range geometries into that list, moving ones already present before the cursor
that 0x007D5ED0 set, and geometries not reached are later dropped by 0x007D6A40.
Reading 0x007D5790's instructions would settle it. Whether that list is the light's
shadow-caster set for the shadow map or the set of receivers it lights is also
**unverified**; the knowledge file describes it as "the lit geometry of this light",
which leans towards lit receivers and weighs mildly against the name
`CollectGeometryInRange`.

C11. **read** - The child loop re-reads the count `+0xB6` after every child
(0x007D5AC2) and reads the data pointer `+0xB0` per child (0x007D5A9B); it does not
cache either across iterations.

C12. **read** - The loop compares `EDI` (index) with the count unsigned (`JBE`, `JA`).
B9 (0x007D5A99) cannot be taken when reached (derived: B8 left for count == 0 and EDI
is 0).

C13. **read** - The body contains no access to any timer, clock or frame-time global:
its only data references are 0x00B42F48 and 0x00B3FD70 (meta.json `data_refs`), and
its callees are the five listed (meta.json). IsInRange reads no clock
(re/functions/0x007D2EA0.md Purpose). Whether 0x007D5790, 0x007C59E0 and 0x0049FFC0
read a clock is **unverified** at instruction level (their pseudocode shows none).

C14. **derived** (C5-C7, re/functions/0x004073D0.md claim 12, knowledge/actor-shadows.md)
- Cost shape: one walk per 0x007D6900 call; in 0x004073D0 that is one walk from the
scene root [0x00B333CC] per drawn actor-shadow light per frame, plus one from the
caster +0x130 when byte [0x00B06F0C] != 0 (name `bActorSelfShadowing` unverified, from
OBVR; re/functions/0x004073D0.md:133). The walk is bounded by, among others, (a) the
gate [0x00B42F48] != 0 (0x007D59E1), which turns it off entirely when zero, (b)
0x007D6900's root filters (rea-all pseudocode only), (c) IsInRange cutting whole
subtrees, (d) zero-radius and app-culled children of plain nodes (C7), (e) switch
nodes' inactive children. The 0x007D5A10 counter includes all callers of 0x007D6900,
not just 0x004073D0. When the source light is a directional light IsInRange returns true for
every object (re/functions/0x007D2EA0.md C2), so the walk then reaches every
non-culled, non-zero-radius object of the graph. Which source-light type the actor
shadow lights have is **unverified**.

C15. **unverified** - 0x00B42F48 is the shadow quality level. Read facts only: its
file-image value is 0 (data.json), this function requires it != 0, 0x004073D0
requires it >= 3 (OBVR GameAddresses.h:1061, `cmp dword ptr [0x00B42F48],3` at
0x004073D3).
