## Purpose

Called once per scene-graph object visited by a culling walk, with `this` = the culling
process and the stack argument = the object (an `NiAVObject`, proposal). It tests the
object's world bound (object+0x20: centre, radius +0x2C) against the process's active
frustum planes (six 16-byte planes at this+0x2C, active bits in the mask at this+0x8C),
in plane order 0..5, and

- when the bound lies wholly on the negative side of any active plane (WhichSide = 2),
  stops testing and does **not** call the object (culled);
- when the bound lies wholly on the positive side of a plane (WhichSide = 1), clears that
  plane's bit for the rest of this visit;
- when no plane returned 2 (or the mask was 0 on entry), calls the object's virtual
  slot +0x7C with the process as its argument (`OnVisible`, proposal), which for an
  `NiNode` (0x0070AB40) walks the children through 0x007073D0 back into this function
  with the reduced mask, and for an `NiGeometry` (0x007227A0) hands the object to
  0x0070E1A0, which appends it to the array at process+0x08 only when that pointer is
  non-null and byte process+0x04 is 0 (other paths in C11; OBVR measured +0x08 null in the
  render path, so the append is likely not what the main world render does - derived from
  OBVR's measurement, not re-measured here);
- afterwards puts the mask back to its value on entry (non-zero path only).

So the mask is the hierarchical plane-coherence of the walk: a child is tested only
against the planes its parent's bound straddled (derived, C10).

Subsystems touched, in order: the culling process's mask (read), the object's world
bound and the process's planes (through 0x0047DA70, per active plane), the object's
vtable (one virtual call), the process's mask (restore). No clock reads or writes, no
globals (C16).

## Calling convention and parameters

- `__thiscall`: ECX = `this`, the culling process, copied to EBP at 0x0070DFB2 (read).
  ECX itself is not used as `this` after that; it is reloaded with the argument.
- One stack argument, the object: [ESP+0xC] after the two entry pushes (0x0070DFC2,
  0x0070E023), [ESP+0x18] inside the three-register save (0x0070DFF1) - both resolve to
  the caller's [ESP+4] (derived from the pushes at 0x0070DFB0, 0x0070DFB1, 0x0070DFD3..D5).
- Callee cleans: `RET 0x4` on both exits, 0x0070DFD0 and 0x0070E03B (read).
- Saved and restored: EBP (0x0070DFB1 / 0x0070DFCE, 0x0070E039), EBX, ESI, EDI on the
  loop path (0x0070DFD3..D5 / 0x0070E01E..20) (read).
- Local: the slot pushed as ECX at 0x0070DFB0 becomes the saved mask ([ESP+4],
  written 0x0070DFBC, read 0x0070E02F). `POP ECX` at 0x0070DFCF / 0x0070E03A therefore
  leaves the entry mask in ECX on return (read; caller-volatile, no meaning).
- Return: no value is produced on purpose. EAX on exit is the saved mask on the
  non-zero path (0x0070E02F) and whatever the virtual call left on the zero path
  (read). 0x0049CBF0 does not read EAX after its call (0x0049CCCE..D2 POPs and RET 4,
  read (objdump)); 0x007073D0 tail-jumps here (C12), so its callers would see EAX - not
  checked (unverified). Proposed signature: `void __thiscall NiCullingProcess::Cull(NiAVObject* object)`.
- The virtual call is thiscall: ECX = the object, one pushed argument = `this` (the
  process) (0x0070DFC2..CC, 0x0070E023..2D; read). The entry path's stack balance
  requires that callee to pop its argument (RET 4); the four implementations read
  below all end in `RET 0x4` (read (objdump): 0x0068F970, 0x0070AB84, 0x007227AA; the
  0x004A0920 exit not read - unverified).

## Control flow

| # | at | instruction | condition | outcome |
|---|---|---|---|---|
| B1 | 0x0070DFC0 | `JNZ 0x0070DFD3` after `TEST EAX,EAX` (EAX = this+0x8C) | mask != 0 | taken: loop half. Not taken (mask == 0): virtual call `[[arg]+0x7C](this)` at 0x0070DFCC, then `POP EBP; POP ECX; RET 4` - no plane test, no mask write |
| B2 | 0x0070DFDB | `JMP 0x0070DFE0` | unconditional | skips the 3-byte filler `LEA ECX,[ECX+0x0]` at 0x0070DFDD (read (objdump)) |
| B3 | 0x0070DFEF | `JZ 0x0070E010` after `TEST [EBP+0x8C],ESI` (ESI = 1 << i) | bit i clear in the current mask | skip plane i |
| B4 | 0x0070E001 | `JZ 0x0070E01B` after `CMP EAX,0x2` | WhichSide(object+0x20, plane i) == 2 | leave the loop with EDI = i (< 6) |
| B5 | 0x0070E006 | `JNZ 0x0070E010` after `CMP EAX,0x1` | result != 1 (0, or any value other than 1 and 2) | keep bit i. Result 1: `NOT ESI; AND [EBP+0x8C],ESI` clears bit i (0x0070E008..0A) |
| B6 | 0x0070E019 | `JC 0x0070DFE0` after `CMP EDI,0x6` | i + 1 < 6 (unsigned) | next plane |
| B7 | 0x0070E021 | `JNZ 0x0070E02F` after `CMP EDI,0x6` at 0x0070E01B (the three POPs in between leave the flags alone) | EDI != 6, i.e. left through B4 | skip the virtual call. EDI == 6: virtual call `[[arg]+0x7C](this)` at 0x0070E02D |
| - | 0x0070E02F..3B | `MOV EAX,[ESP+4]; MOV [EBP+0x8C],EAX; POP EBP; POP ECX; RET 4` | both outcomes of B7 | mask restored to its entry value, return |

Test flows for a rebuild (each derived from B1-B7):

1. mask == 0 -> no WhichSide call; `OnVisible(this)` once; mask not written.
2. mask == 0x3F, all six results 0 -> six WhichSide calls with planes this+0x2C, +0x3C, ... +0x7C in that order; `OnVisible` sees mask 0x3F; mask 0x3F after.
3. mask == 0x3F, plane k returns 1, others 0 -> `OnVisible` sees 0x3F & ~(1<<k); mask 0x3F after.
4. mask == 0x3F, all results 1 -> `OnVisible` sees 0; mask 0x3F after.
5. mask == 0x3F, plane k returns 2 -> planes k+1..5 not tested; no `OnVisible`; bits cleared by planes < k returning 1 are restored (mask 0x3F after).
6. 2 at plane 5 -> EDI = 5 at B7 -> no `OnVisible` (the exit counter, not "all planes tested", decides).
7. sparse mask, e.g. 0x05 -> only planes 0 and 2 tested (plane 2 at this+0x4C); the counter still runs to 6.
8. mask with no bit in 0..5, e.g. 0x40 -> no WhichSide call, but the non-zero path runs: `OnVisible` sees 0x40, mask rewritten to 0x40.
9. `OnVisible` writes this+0x8C (e.g. a nested visit that fails to restore): non-zero path overwrites it with the entry value; zero path keeps whatever the callee left.

## Open questions

1. Gamebryo name of slot 1: OBVR's `NiCullingProcess::Cull` vs `NiCullingProcess::Process(NiAVObject*)` (C1). Settled by an xOBSE/OBVR header declaring `NiCullingProcess`'s vtable.
2. Name of the object's slot +0x7C (`OnVisible`, C11) - same kind of second source needed.
3. Does anything rely on EAX after 0x007073D0's tail jump into this function? (Return-value contract, Calling convention.)
4. `BSFadeNode`'s +0x7C override 0x004A0920 (distance fade, SEH frame, global 0x00B0727C) was not read; it decides what most game objects do once visible - candidate for its own slice.
5. Which planes are 0..5 (left/right/top/bottom/near/far order) - decided by 0x00717A40, not read past its entry.
6. `BSCullingProcess` (vt 0x00A68CF4) has its own slot 1 at 0x006FBB80: does it call 0x0070DFB0 as well? Not checked.

## Smaller callees worth their own slice

- 0x007073D0 `NiAVObject::Cull` (OBVR name) - four instructions, the dispatcher (C12); cheap.
- 0x0070AB40 `NiNode` slot +0x7C - the child walk (C11); cheap.
- 0x007227A0 / 0x0070E1A0 - geometry append to the visible array (C11); cheap, and it is where the draw list is filled.
- 0x004A0920 `BSFadeNode` slot +0x7C - large, unread (open question 4).
- 0x0070E040 / 0x00717A40 - plane setup from the camera (C13); the planes this function consumes.
- 0x0049CBF0 `TESWaterCullingProcess` slot 1 (C14).
