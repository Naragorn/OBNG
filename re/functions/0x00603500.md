The seed name is misleading: the function does not step the skeleton's animation. It
steps the head-tracking ("look at") state: picks a look target, turns the body towards it,
sets the look direction on the head-tracking object, refreshes three skeleton nodes' world
data, and runs the head-tracking object's solve and the spine twist (derived from the
callees and the strings below; agrees with `knowledge/actor-head-tracking.md`).

## Purpose

Per actor update, in this order (all read, addresses in Control flow):

1. Gates: the actor has a process (+0x58), the process's vfunc +0x08 returns 0, the process
   has a head-tracking object (vfunc +0xE8(actor)), the actor has a 3D (+0x3C).
2. Looks up the bones "Bip01 NonAccum", then "Bip01 Spine2" under it, then "Bip01 Head"
   under that (NiAVObject vfunc +0x58 GetObjectByName, strings 0x00A64228, 0x00A36ECC,
   0x00A3CAAC). Every frame, three name lookups (read 0x0060355B-0x00603584).
3. Gate on actor+0xC4 bits 0..2 all set; otherwise clears actor+0xE0 and the head-tracking
   object's +0x1D5 and returns.
4. First time: head-tracking +0x1D4 = 1 ("snap"), actor+0xE0 = 1.
5. Distance gate: the player's distance to this actor (TESObjectREFR::GetDistance
   0x004D7E90, name from `re/symbols/xobse.csv`) greater than the float at 0x00B36AB8 ->
   head-tracking +0x1D5 = 0 and return.
6. If the current look target answers vfunc +0x188 true and +0x154 zero, process vfunc
   +0x4B4 (meaning unverified; a clear of the target is a guess).
7. Clock: actor+0x100 and actor+0xDC each lose the frame seconds read from 0x00B33E9C.
8. When actor+0x100 <= 0: adds rand(0.2, 0.4) to it (`FADD [ESI+0x100]` at 0x006036D0,
   stored at 0x006036DC: an add, not a set), so the new value is in [0.2 + old, 0.4 + old]
   with old <= 0; the interval is closed because 0x0047E060 computes
   rand()*(b-a)/32767.0 + a, which reaches b at rand() = 32767 (read). Then, when process
   vfunc +0x4BC is true, picks a new look target (0x00601670, or the package target within
   100 units / 500 for the player), sets it through process vfunc +0x480 and sets
   actor+0xDC to rand in [4.0, 10.0], closed by the same formula (a set: `FSTP` at
   0x006037D7, no add; read).
9. Body turn: when 0x005F7900(0) is true, computes the heading from the actor to the look
   target and the signed difference to the actor's heading; past a threshold from the int
   globals 0x00B36C10 / 0x00B36C18 (degrees x 0.8) calls the turn 0x00685530, else
   0x005E05F0(0x30) (process movement flags).
10. Look speed: head-tracking vfunc +0xD0(speed, 0) with speed 50.0 or 0x005E0DD0(), or
    vfunc +0x78(0.0, 1, 0, 0, 0, 0), chosen by actor vfunc +0x334(1), the byte 0x00B1206C,
    process vfuncs +0x33C / +0x1DC and the player-to-target distance against the setting
    behind 0x00B36AE0.
11. Look direction: the normalized vector from the actor's vfunc +0x11C point to the
    target's vfunc +0x11C point (z zeroed in some cases), or the global vector
    0x00B3F9A8..0x00B3F9B0 when there is no target or a suppression flag is set; passed to
    head-tracking vfunc +0x84(x, y, z, 0).
12. Head-tracking +0x198 = (process vfunc +0x2C0 & 0xF) == 0 (0x005E05B0, 0x0054A0A0).
13. NiAVObject vfunc +0x74 (UpdateWorldData) on NonAccum's grandparent, parent, NonAccum.
14. Head-tracking solve 0x0054B010(dt, Head, NonAccum); when +0x1D5 is set and the byte
    0x00B148F4 is 0: 0x0054B3E0(dt, Head, &yaw, &out2) and the spine twist
    0x0047CAF0(yaw) on Spine2's parent.

## Claims

1. The function is head tracking, not the skeleton's animation step - **derived** from the
   bone-name strings (0x0060355B..), the head-tracking object (0x005E12B0) and
   `knowledge/actor-head-tracking.md`.
2. The stack argument (frame seconds) is never read; the clock is read from 0x00B33E9C at
   0x00603684, 0x00603696, 0x00603C27, 0x00603C5E - **read**.
3. Timers: actor+0x100 and +0xDC are decremented by the frame seconds every call that
   passes gates #1-#9 - **read** (0x0060367E-0x0060369C). The re-pick cadence of
   0.2-0.4 s is **derived** (from the re-arm at 0x006036D0 and the range constants
   0x00A3D9A4 / 0x00A47E6C) and assumes the timer never drifts below -0.2: the re-arm is
   additive, so one long frame can leave it <= 0 after the re-arm, and the pick then runs
   again on the next call.
4. The pick runs only when actor+0x100 <= 0; actor+0xDC is never a gate inside this
   function - **read** (#13, #15). The "hold 4-10 s" in the knowledge file therefore rests
   on some other reader of +0xDC - **unverified**.
5. Writes outside the actor and its own process/head-tracking object/skeleton: the CRT
   rand state through 0x0047E060 - **derived** from the pseudocode of 0x0047E060,
   `_rand` 0x009859DD and `srand` 0x009859D0. The first rand call (0x006036CB) runs
   whenever actor+0x100 <= 0 (gate #13 only), whether or not process vfunc +0x4BC allows a
   pick; only the second (0x006037D2) is pick-only. The rand state is per thread
   (`__getptd()->_holdrand`); the only process-global write is the seed-once byte
   0x00B069C3, written once. On several threads this is a determinism issue, not a data
   race: a worker draws from its own (unseeded) sequence, so a class B per-unit comparison
   against the main thread needs the rand state carried.
6. Every frame (when gates pass) the function does three GetObjectByName lookups by string
   - **read** (0x00603558-0x00603584); a cache is a cheap performance lever - **derived**.
7. NonAccum's grandparent, parent and NonAccum get UpdateWorldData every frame, top down,
   without null tests on the parents - **read** (0x00603BF8-0x00603C1A).
8. The spine twist 0x0047CAF0 is called with ECX = Spine2's parent ([base+0x34]+0x1C) -
   **read** (0x00603C85-0x00603C8A). The knowledge file's "starts at Spine2" was marked
   derived there; this reading starts one bone higher in the chain (at the parent).
   Which bones 0x0047CAF0 then writes is **unverified**. OBVR may want to pick this up.
9. 0x005E0550 and 0x006605A0 are called on the player, not on this actor - **read**
   (ECX loads at 0x00603AC5, 0x00603AD6).
10. Pseudocode disagreements, instructions win (**read**): (i) pseudo uses `unaff_EBX` for
    the node at 0x00603BF8; the instruction loads EDI = [ESP+0x2C] = NonAccum; (ii) the
    pseudo's `bVar1 = *pfVar7 < dist` is the negation of BL in the instructions (BL = 1 when
    setting >= dist), and the pseudo's branches are inverted to match, so the result is the
    same except for NaN; (iii) the pseudo hands the pushes for 0x004121A0 to the vfunc
    +0x174 / +0x11C calls; (iv) the pseudo puts the `PUSH 0` at 0x006038E7 on process
    vfunc +0x4CC; it is GetDistance's second argument; (v) the pseudo's signature lacks the
    RET 4 argument.
11. Within one call, the order is: gates, bone lookups, distance gate, clock, pick (rarely),
    turn, look speed, look direction, +0x198, UpdateWorldData x3, solve, twist - **read**.
