## Purpose

A thin wrapper (read, the whole body): it builds one point collector in its
own 16-byte aligned stack frame (0x1A0 bytes: a 0x20-byte header and an
in-place array of 8 entries of 0x30 bytes), calls the support check body
0x008AE100 on the same `this` with its two arguments and the collector, then
runs the collector's destructor inline: when the hit array's capacity word has
bit 31 clear after the call, it frees the array's buffer through the thread's
Havok memory (TLS block +0x19C, or the global [0x00BA7D9C] when that slot is
null).

It does **not** cast into the world itself (read: no world, phantom or shape
access in 0x008AE890-0x008AE921). Any world query happens in 0x008AE100 (see
the read-and-write map, group c).

It reads no clock and writes none (read: no RDTSC, no time global in the
body). The callee 0x008AE100 executes RDTSC at 0x008AE13D only when the TLS
monitor-stream cursor `[TLS+0x1A4]` is below its end `[TLS+0x1A8]`
(0x008AE127 CMP / 0x008AE12D JNC skips it otherwise), after writing the
string pointer 0x00A97CA0 ("TtcheckSupport") at 0x008AE137 (read, 0x008AE100
asm.s). It has a second conditional RDTSC at 0x008AE781, behind the JNC at
0x008AE773, with the string pointer 0x00A9610C written at 0x008AE77B (read,
0x008AE100 asm.s). Both are Havok monitor timers, not the game clock
(derived from the TLS monitor-stream writes).

## Calling convention and parameters

- **__thiscall**, `this` in ECX (read): ECX is not written between the entry
  and the call at 0x008AE8D0, so the caller's ECX reaches 0x008AE100, which
  takes it as its `this` (`MOV ESI,ECX` at 0x008AE115, read in 0x008AE100
  asm.s). ECX is first overwritten at 0x008AE8E4, after the call.
- The caller passes ECX = `[controller+0x8]` (0x008968AA `MOV EDI,[ESI+0x8]`,
  0x008968C7 `MOV ECX,EDI`, read in 0x00896000 asm.s); the caller skips the
  call when that pointer is null (0x008968AF JZ, read).
- Two stack arguments, callee-cleaned, `RET 0x8` at 0x008AE91F (read).

## Control flow

| # | Address | Instruction | Condition | Taken -> | Fall-through -> |
|---|---|---|---|---|---|
| B1 | 0x008AE8E2 | `JS 0x008AE91C` | `[S+0x18]` (capacityAndFlags after the callee) has bit 31 set (TEST EAX,EAX at 0x008AE8D9) | epilogue: nothing freed | free path (B2) |
| B2 | 0x008AE8FC | `JNZ 0x008AE904` | `[TLS block + 0x19C]` non-zero | ECX = that TLS allocator | ECX = `[0x00BA7D9C]` (0x008AE8FE) |

Test flows a rebuild would need (derived from B1 x B2):

1. Bit 31 set after the call (the inline buffer was kept): no free, no TLS read.
2. Bit 31 clear, TLS allocator set: `0x008A75D0(this = TLS allocator, ptr = [S+0x10], size = (cap & 0x3FFFFFFF) * 0x30, 0x14)`.
3. Bit 31 clear, TLS allocator null: the same call with `this = [0x00BA7D9C]`.

Note on B1 (read): the vtable reset at 0x008AE8DB is executed on both paths,
before the jump. It is a dead store in effect (the frame is dropped) but it is
in the instructions.

## Read-and-write map (the manifest's five groups)

**(a) Own object (`this` = the proxy at `[controller+0x8]`).** No read, no
write by 0x008AE890 itself (read: no memory operand through ECX). All access
to the proxy is in 0x008AE100 (in progress).

**(b) Other actors or references.** None by 0x008AE890 itself (read).

**(c) Havok world, bodies, phantoms.** None by 0x008AE890 itself (read). The
world query sits in 0x008AE100: it calls 0x008AD070 with the collector first
(0x008AE153-0x008AE159, read in 0x008AE100 asm.s). The rea-all pseudocode of
0x008AD070 (a reading aid, instructions not read here) shows it resetting the
collector, adding the proxy's floats `this[0x16] + this[0x17]` to a float at
`[[[this+0x30]+8]+0x74]+8`, calling `[this+0x30]`'s vtable +0x34 with the
collector, and restoring that float - a temporary write into an object
reachable from the phantom while the query runs: **unverified**, for
0x008AE100 / 0x008AD070's own files to confirm in the instructions. If it
holds, two proxies sharing that object could not run the support check at
the same time.

**(d) Globals, singletons, shared lists.**

| Address | Access | Where | Note |
|---|---|---|---|
| 0x00BA9DE4 (_tls_index) | read | 0x008AE8E4 | only on the free path |
| FS:[0x2C] | read | 0x008AE8EA | per thread |
| TLS block +0x19C | read | 0x008AE8F4 | per thread |
| 0x00BA7D9C | read | 0x008AE8FE | only when the TLS slot is null; a process-wide allocator then |
| 0x00A55DEC (vtable, .rdata) | address stored | 0x008AE8B0, 0x008AE8DB | constant; slot 0 = 0x00532B90, slot 1 = 0x008AF6D0 (data.json bytes) |

No global is written by the body itself (read). The allocator object chosen
in B2 is written by 0x008A75D0 (below).

**(e) Heap.** No allocation in the body (read). One call of `0x008A75D0`
on flows 2 and 3 with the constant 0x14 as its third argument (read,
0x008AE910); that it is a free and that 0x14 is a memory class is
**unverified** (0x008A75D0 is not exported in this slice). Where the buffer it
frees was allocated (a grow of the hit array past 8 entries inside the
callee chain) is **unverified**: only bit 31 of the capacity word is read
here, not who cleared it. The rea-all pseudocode of 0x008A75D0 (reading aid)
shows a size-class free list in the allocator object (`+0x34 + i*4` heads,
`+0x78 + i*4` counts, the freed block's first word overwritten) for sizes up
to 0x2000 while `+0x30` is non-zero, and a forward to `[this+0x10]`'s vtable
+0x14 / +0x1C otherwise: **unverified** at the instruction level. With the
TLS allocator that write stays per thread; with the fallback `[0x00BA7D9C]`
it would be a shared object (derived from B2; whether the fallback is ever
taken in game is **unverified**).

## Claims

1. 0x008AE890 is `__thiscall`, `this` passed unchanged to 0x008AE100, two stack arguments, RET 8. **read** (0x008AE890-0x008AE8D0 no ECX write; 0x008AE115; 0x008AE91F).
2. It builds a 0x1A0-byte stack object with vtable 0x00A55DEC, +0x04 = 0x7F7FFFFF, +0x10 = S+0x20, +0x14 = 0, +0x18 = 0x80000008. **read** (0x008AE89C-0x008AE8C8).
3. That object is a point collector with an in-place hit array of 8 entries of 0x30 bytes at +0x20. **derived** (claim 2, the 0x30 multiply at 0x008AE909/0x008AE912, 0x20 + 8 * 0x30 = 0x1A0); "collector" as a name: derived from 0x008AD070 passing it to a phantom virtual (pseudocode only), so **unverified** at the instruction level.
4. It does not cast into the world or read the phantom itself. **read** (no memory operand other than the stack frame, the TLS chain and 0x00BA7D9C in the body).
5. It reads no clock. **read** (body). The callee 0x008AE100 reads RDTSC at 0x008AE13D only when the TLS monitor-stream cursor `[TLS+0x1A4]` is below its end `[TLS+0x1A8]` (0x008AE127 CMP / 0x008AE12D JNC), and has a second conditional RDTSC at 0x008AE781 (string 0x00A9610C written at 0x008AE77B). **read** (0x008AE100 asm.s). Both are Havok monitor timers, not the game clock. **derived** (from the monitor-stream writes at 0x008AE137 and 0x008AE77B).
6. When `[S+0x18]` bit 31 is clear after the call, it calls 0x008A75D0 (`__thiscall`, ECX = `[TLS+0x19C]` or `[0x00BA7D9C]`) with the arguments (`[S+0x10]`, `([S+0x18] & 0x3FFFFFFF) * 0x30`, 0x14). **read** (0x008AE8D5-0x008AE917). That this call is a deallocation and that 0x14 is a memory class: **unverified** - 0x008A75D0 is not exported in this slice (only the rea-all pseudocode was seen); settled by reading 0x008A75D0's instructions.
7. The allocator for that free is `[TLS block + 0x19C]`, or `[0x00BA7D9C]` when the TLS slot is null. **read** (0x008AE8E4-0x008AE8FE).
8. The only writes of the body are to its own stack frame. **read** (every store in asm.s targets `[ESP+...]`).
9. The caller passes `[controller+0x8]` as `this`, a stack vector as direction, `controller+0x260` as the surface-info out-parameter, and reads `[controller+0x260] == 2` afterwards. **read** (0x00896000 asm.s 0x008968AA-0x008968DF).
10. Matches Havok's `hkpCharacterProxy::checkSupport` wrapper around `checkSupportWithCollector` with `hkpAllCdPointCollector`. **unverified** (structure only; no SDK source checked).
11. For threading: the body's own instructions write only its stack frame. **read** (claim 8). The call of 0x008A75D0 on flows 2 and 3 has only a pseudocode reading so far, so thread safety also depends on 0x008A75D0 writing only into the allocator object in ECX: **unverified**, settled by reading 0x008A75D0's instructions. The risk sites are therefore 0x008AE100, 0x008AD070, 0x008A75D0 and the shared fallback allocator 0x00BA7D9C. **derived** (claims 6, 7, 8); the callee side is **unverified** here.

## Disagreement between pseudo.c and the instructions

- pseudo.c declares `FUN_008ae890(param_1, param_2)` without `this` and calls
  `FUN_008ae100(param_1, param_2, &local_1b0)` without ECX. The instructions
  pass ECX through unchanged and 0x008AE100 uses it as `this`; the
  instructions win: it is `__thiscall` with three values in.
- pseudo.c drops the allocator in ECX for the call of 0x008A75D0 (the TLS
  chain at 0x008AE8E4-0x008AE8FE disappears). The instructions win.

## Open questions

1. What 0x008AE100 does to the collector and whether the hit array ever grows past 8 (flows 2 and 3 only occur then). Settled by 0x008AE100's file and a counter on the B1 branch in game.
2. Whether `[TLS block + 0x19C]` is ever null on the threads that run the actor update, so that the shared `[0x00BA7D9C]` is used. Settled by reading who writes TLS +0x19C (thread start code) or a probe on B2.
3. What `[controller+0x2B0]` is (the direction passed in is its negation, the mask 0x00A965C0 being four 0x80000000 words per 0x00896000 data.json). Settled by 0x00896000's file or a probe of +0x2B0.
4. Whether 0x008AD070's temporary write at `[[[proxy+0x30]+8]+0x74]+8` is in the instructions and what object it hits (a shape shared between actors would block running two support checks at once).
5. The proxy's class name and its vtable (not touched here).

## Layout requests

- `PointCollector` (vtable 0x00A55DEC), size 0x1A0, alignment 16:
  `+0x00 vtable`, `+0x04 float earlyOutDistance`, `+0x10 u32 hitsData` (a
  32-bit handle in a 64-bit clean header), `+0x14 i32 hitsSize`,
  `+0x18 u32 hitsCapacityAndFlags` (bit 31: storage not owned; low 30 bits:
  capacity), `+0x20 Hit inline[8]`, `sizeof(Hit) == 0x30`. Each offset as a
  `static_assert`ed constant.
- `SurfaceInfo` (the out-parameter at `controller+0x260`): `+0x00 i32 supportedState`
  (2 compared by the caller), `+0x10 Vector4`, `+0x20 Vector4` (written by
  0x008AE100) - from the caller and callee, not from this body.
- The TLS block offset +0x19C (Havok thread memory) and the fallback global
  0x00BA7D9C as named constants, shared with 0x008DE950's
  (knowledge/render-thread-outside-the-pass.md).
- CharacterController `+0x8` = the proxy pointer, `+0x260` = SurfaceInfo, `+0x2B0` = the vector the direction comes from.
