## Purpose

A drop-in for `MessageBoxA(NULL, text, caption, type)` with three arguments
(text, caption, type) that shows the box inside the game UI when it can:

1. If the byte at 0x00B06B38 is set, it answers at once without showing
   anything (5 for type 2, else 6).
2. Otherwise it brackets everything that follows with two thiscall methods
   on `g_timeInfo` (0x00B33E90): 0x0047D120 on entry (0x00494A18) and
   0x0047D0F0 on exit (0x00494E5E).
3. On the main thread, with the OS globals and input globals present and
   the reentrancy byte 0x00B06B16 set, it shows an in-game message menu
   through `ShowMessageBox` 0x00579C10 and runs its own modal loop (Win32
   message pump, input poll, menu/UI calls) until a choice is set by a key
   or by the return value of 0x00578D70, then turns the choice into a
   result code through a jump table at 0x00494E70. Which choice gives
   which result is **unverified**: the table bytes are not in the export
   (see "Control flow", #21).
4. Otherwise it either auto-answers (0x00B06C74 and 0x00B34FA8 both
   nonzero) or falls back to the real `MessageBoxA`.
5. A result of 4 is always turned into 5 before the return.

**Answer to the slice question** ("Which field does it read, and what does
it drive?"): it reads **no field** of `g_timeInfo`. Both Ghidra references
(0x00494A13, 0x00494E59) are `MOV ECX,0xB33E90` that pass the TimeInfo's
address as `this` to 0x0047D120 and 0x0047D0F0. Those two bodies are not in
the export, so which fields they touch is **unknown**. What the pair drives
is a bracket around a modal loop that can block the frame for an unbounded
time; the hypothesis that it suspends/resumes the frame clock so the wait is
not counted as frame time is **unverified**.
