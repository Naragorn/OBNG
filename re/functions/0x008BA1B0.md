## Purpose

Fills a ray-caster object (`this`) with the ray input, the collector and a
filter pointer, builds a broad-phase cast-ray input on its own stack (from
point, one cast, pointer to the to-point, stride 0x10, a cache pointer), and
calls slot +0x38 of the object passed as arg1 with
(&input, this, 0). Before and after, it writes one Havok monitor-stream record
each into the calling thread's TLS block ("TtRayCstCached" begin, label
0x00A9610C end) with the low dword of RDTSC. **read** (0x008BA1B0-0x008BA2BC).

In the cast wrapper arg1 is `[world+0x64]` (0x0088B9C1 / 0x0088BA5A, EDI =
result of a virtual call at 0x0088B974), which `knowledge/actor-frame-map.md`
(lines 363, 406) names the Havok broad phase. So the indirect call is the broad
phase's ray cast with `this` as its cast collector. **derived** (from the call
sites and that knowledge file; that EDI is the world is taken from the
knowledge file, not re-read here).

The cast wrapper calls this function directly only when a collector exists
(`[request+0x78] != 0`, JZ at 0x0088B99D, or else `[request+0x74] != 0`, JZ at
0x0088BA2B) and `[request+0x70] != 0` (JZ at 0x0088B9AA / 0x0088BA42); with
both collectors null it calls 0x00898ED0 at 0x0088BAA9 instead. **read**
(0x0088B850's asm.s). When `[request+0x70] == 0` it calls `hkWorld::castRay`
0x008987E0, which is itself a caller of this function (meta.json) and passes
arg4 = 0 (rea-all 0x8987e0.c line 18, pseudo only; its asm was not read).
So both paths run this body and write the "TtRayCstCached" label; 0x008987E0
is not an uncached alternative. **derived** (meta.json callers + that
pseudo). arg4 (`[request+0x70]` on the direct path, 0 from 0x008987E0) lands
in the broad-phase input at +0x1C; that it is the broad-phase AABB cache is
**derived** from the label only, and its meaning inside the broad phase is
**unverified**. "Cached" therefore names the routine (the broad-phase cast
path), not a guarantee that a cache is present: arg4 may be null.
