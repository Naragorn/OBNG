## Purpose

One tick of the loading screen:

1. Find the loading menu: the tile menu for menu type 0x3EF
   (kMenuType_Loading) through 0x00589B70 and its Menu through 0x005898F0.
   Leave if either is null.
2. Advance the menu's **own** TimeInfo (`[menu+0x54]`, not `g_timeInfo`
   0x00B33E90) with `GetTickCount` through TimeInfo::Update 0x0047D170, and
   take `now = clock->clockMs` (+0x10).
3. Advance the loading bar's target step (+0x64) by up to one on three
   millisecond thresholds (settings 0x00B14160/68/70, image values 2500,
   100, 10), and count the screen timer (+0x40, seconds) down by the
   milliseconds since the previous call, divided by 1000.0.
4. When the target step differs from the shown step, or the timer ran out,
   or the caller forces it, and the shown step is below 100: copy the step,
   push it to the tile as trait 0xFB1 (user3); if the new step is below
   99.9999 and the refresh flag is set, call 0x005AD780 and re-arm the timer
   from the setting at 0x00B14158 (image value 15.0); then, if the
   InterfaceManager exists, run the interface calls 0x00583F40, 0x00579260(0),
   0x005792B0 between two `g_ioManager` calls.
5. Record `now` as the previous call's time (+0x6C), and on the main thread
   tail-jump to 0x0060D0A0 on `g_osGlobals`.

## Calling convention and parameters

- **cdecl, one stack argument read as a byte, no defined return value**
  (derived from the reads below).
  - `RET` without immediate at 0x005ADB3E; the tail jump at 0x005ADB35 runs
    after `ADD ESP,8` restored the entry ESP: the caller cleans (read).
  - The only argument read is `CMP byte ptr [ESP+0x1C],0` at 0x005ADA3C.
    ESP there = entry - 0x18: `SUB ESP,8` 0x005AD980, `PUSH EBX` 0x005AD983,
    the 0x3EF push popped by `ADD ESP,4` 0x005AD990, `PUSH EBP/ESI/EDI`
    0x005AD9AA..AC; the `PUSH EAX` at 0x005AD9BF is popped by 0x0047D170
    (`ret 4`, TimeInfo.h `kTimeInfoUpdate`); Tile::UpdateFloat 0x0058CEB0
    pops its two arguments (C5). So `[ESP+0x1C]` = `[entry ESP+4]`, the
    first argument (derived).
  - ECX is written at 0x005AD99B before any read: not an input (read).
    meta.json says `Tick()`; pseudo.c says `Tick(char param_1)`; the
    instructions side with pseudo.c.
  - EAX at 0x005ADB3A is 0 after B1/B2 and the thread id after B18; after
    the tail jump it is whatever 0x0060D0A0 returns (read). Treated as void;
    whether a caller uses EAX is unverified (callers not exported).
- Parameter 0: `bool forceRefresh` (proposed). Nonzero forces the refresh
  flag (read, 0x005ADA3C..0x005ADA48).
- Callee-saved EBX, EBP, ESI, EDI pushed and popped (read).
- Locals: `[entry-4]` float scratch (the new timer at 0x005ADA26, then the
  step as float at 0x005ADA7E); `[entry-5]` byte `refresh` (read,
  0x005ADA41/0x005ADA48, read back at 0x005ADA57 and 0x005ADAA4).

Flow notes for the rebuild (each is a test flow):

- B3 increments with no cap; B5/B6b respect `slowStepCap` (read).
- B13 tests the **new** `shownStep` (FILD at 0x005ADA78 reads +0x60 after
  the store at 0x005ADA75), while B11 tested the **old** one (ECX loaded at
  0x005ADA50). So B13 is taken when B12 copied a `targetStep >= 100`
  (C22). Emulator run (scratch, not in Git): old 99 -> target 100 writes
  `shownStep = 0x64` at 0x005ADA75 before the compare.
- `stepChangedMs` at B12 is the clock re-read at 0x005ADA6F, not EBP; both
  hold the same value because nothing between 0x005AD9CA and 0x005ADA6F
  writes the clock (derived; no call between them).
- `lastTickMs` is written on every path that passed B2 (read).
- PC 24 changes B8's outcome for some inputs (C20): those inputs are flows.

## Countdown at PC 24

Instructions (read, 0x005ADA09..0x005ADA2E):

```
TEST ECX,ECX                 ; sinceLast sign
FLD  float [ESI+0x40]        ; ST0 = timer (exact)
MOV  [ESP+0x14],ECX
FILD dword [ESP+0x14]        ; ST0 = sinceLast as int32 (exact), ST1 = timer
JGE  +6
FADD float [0x00A2FC78]      ; ST0 = sinceLast + 2^32            -> rounded to PC
FDIV double [0x00A2FC70]     ; ST0 = ST0 / 1000.0                -> rounded to PC
FSUBP                        ; DE E9 = FSUBP ST(1),ST(0): timer - ST0 -> rounded to PC, pop
FSTP float [ESP+0x14]        ; round to float format
FLD  float [ESP+0x14]
FST  float [ESI+0x40]
```

At PC 24, RC nearest (the game's word, measured: `_control87` 0x000A001F,
`knowledge/frame-clock.md`):

| Op | Address | Rounds at PC 24? | Why |
|---|---|---|---|
| FLD float | 0x005ADA0B | no | a float load is exact |
| FILD dword | 0x005ADA12 | no | an int32 fits the 64-bit register significand; precision control applies to the arithmetic results, not to loads (derived; see C17) |
| FADD float 2^32 | 0x005ADA18 | **yes** (only when `sinceLast < 0`) | `sinceLast + 2^32` lies in [2^31, 2^32); at 24 bits its ulp is 256 |
| FDIV double 1000.0 | 0x005ADA1E | **yes** | the double operand is used at full value, the quotient is rounded to 24 bits |
| FSUBP | 0x005ADA24 | **yes** | |
| FSTP float | 0x005ADA26 | no change for reachable inputs | the value already has a 24-bit significand; it would only change on float overflow or a subnormal result, and neither is reachable (C19) |
| FLD / FST float | 0x005ADA2A / 0x005ADA2E | no | exact |

So the original computes, with `r24` = round to a 24-bit significand,
nearest-even:

```
x     = sinceLast >= 0 ? sinceLast            (exact, up to 31 bits)
                       : r24(sinceLast + 2^32)
q     = r24(x / 1000)
timer = r24(timer - q)
```

What the rebuild has to do (C18): keep `sinceLast` exact into the division
and round **each of the three arithmetic results** to float. In C++ with
IEEE double and float arithmetic:

```
const double x = sinceLast >= 0
    ? static_cast<double>(sinceLast)
    : static_cast<double>(static_cast<float>(static_cast<double>(sinceLast) + 4294967296.0));
const float q = static_cast<float>(x / 1000.0);
timer = timer - q;   // float - float, one rounding
```

Two traps this rules out: (a) converting `sinceLast` to float before the
division (`(float)sinceLast / 1000.0f`) rounds it first. It can differ only
when `|sinceLast| > 2^24`, because `float(sinceLast)` is exact for
`|sinceLast| <= 2^24` (derived), and then only for some inputs, not for
every one: (1.0, 16777217) gives 0xC683106F under both forms, while
(5.0, -1121445008) gives 0xCA41B235 at PC 24 and 0xCA41B236 float-first
(reproduced in the refutation round; table below). In the refutation
round's 200000-case sweep, 0 of the 15448 differences had
`|sinceLast| <= 2^24` (that sweep is not in Git). (b) Keeping the quotient
in double (the 53-bit reading the review rejected) differs, the review's
input among them (table below). The counts given earlier (trap (a) in 207
of 3004 cases, trap (b) in 820 of 3004) are **unverified**: they come from
the emulator sweep with seed 20261027, which is not in Git and was not
rerun; re-running `tools/difftest/emulate.py` on that sweep would settle
them.
