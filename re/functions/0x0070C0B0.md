## Purpose

Draws one scene graph from one camera through one culling process:

1. returns at once when the renderer global, the camera (arg 1) or the scene (arg 2) is null;
2. picks the visible array: arg 4, or - when arg 4 is null - the culling process's own
   pointer at process+0x08;
3. hands the camera to the renderer (0x00701970, thiscall on the renderer: the camera's
   world frame, frustum and port go to renderer vtable +0x140 when the renderer's mode
   fields allow it - read from that callee's export, not this body);
4. when the visible array is non-null: sets its count (+0x04) to 0, runs the cull walk
   `process->Process(camera, scene, array)` (vtable +0x08), then
   `0x0070C000(camera, array)`, which brackets 0x0070BF30 between the renderer's
   accumulator slots +0x4C(camera) and +0x50 - 0x0070BF30 gives the array to the
   accumulator's +0x54, or with no accumulator calls each geometry's slot +0x84 (slot 33)
   with the renderer;
5. when the visible array is null: runs `process->Process(camera, scene, 0)` only, and
   0x0070C000 is skipped (0x0070C0E7, read). A geometry that reaches 0x0070E1A0 while
   process+0x08 is null is handed to [renderer+0x08]+0x58, or to geometry +0x84(renderer)
   when there is no accumulator or +0x58 returns AL == 0 (read (objdump)
   0x0070E1DF..0x0070E20D; re/functions/0x0070DFB0.md C11). That every visible geometry
   reaches 0x0070E1A0 is unverified (C11).

All nine direct call sites pass arg 4 = 0, and the image holds no other reference to
0x0070C0B0 (C10), so in this build the array is always process+0x08, and which of 4. or 5.
runs is decided by that field alone (derived). OBVR measured it null for the world scene
graph's culling process on every frame (C11, not re-measured here), so per that
measurement the world pass takes 5. and does not take 4.

No D3D draw call is issued in this body or in 0x0070C000 / 0x0070BF30 directly; they hand
geometries to the accumulator's slots or to the geometry's slot +0x84 (C13, read). Where
the accumulator draws is open question 1.

Subsystems touched, in order: renderer global (read), culling process (+0x08 read when
arg 4 is null), renderer camera setup (0x00701970), visible array (count write), culling
walk (process vtable +0x08), accumulator draw bracket (0x0070C000). No clock read or
write: the only data reference is 0x00B3F928 (meta.json, data.json), and neither callee
in the slice references a clock (C14).

## Calling convention and parameters

- `__cdecl`, four stack arguments, plain `RET` at 0x0070C108 and 0x0070C118 (read); the
  caller cleans: `ADD ESP,0x10` right after both calls in 0x0040C830 (0x0040CCD8,
  0x0040CE4D, read (objdump)); other callers fold the cleanup into a larger `ADD ESP`
  (0x00483184, 0x004D0410: `ADD ESP,0x18`, read (objdump)).
- ECX on entry is not read: it is overwritten at 0x0070C0B0 with the renderer pointer
  (read). That renderer value stays in ECX until 0x0070C0DE (no instruction in between
  writes ECX, read), so 0x00701970 is called with ECX = renderer.
- Saved and restored: EBX, EBP, ESI, EDI, pushed as the guards pass (0x0070C0BA,
  0x0070C0C3, 0x0070C0CC, 0x0070C0D3) and popped in reverse on each exit (read).
- Return value: none produced on purpose (no write to EAX meant as a result) (read). On
  the paths that make calls (exit 0x0070C108, and 0x0070C118 reached from 0x0070C114) EAX
  holds whatever the last callee left; on the guard exits B1-B3 EAX keeps the value it had
  on entry (read).

Test flows for a rebuild (each derived from B1-B5):

1. renderer global null -> no call, no write (camera, scene, process may be anything).
2. renderer set, camera null -> no call, no write.
3. renderer set, camera set, scene null -> no call, no write.
4. all set, arg 4 = A (non-null) -> [process+0x08] not read; calls in order:
   0x00701970(this = renderer, camera), A.count = 0 (before Process runs),
   process->Process(camera, scene, A), 0x0070C000(camera, A).
5. all set, arg 4 = 0, [process+0x08] = B (non-null) -> as flow 4 with B.
6. all set, arg 4 = 0, [process+0x08] = 0 -> 0x00701970(renderer, camera),
   process->Process(camera, scene, 0); nothing else; no write.
7. Order check for 4/5: the count write precedes the Process call (0x0070C0EA before
   0x0070C0F8), and 0x00701970 precedes both (0x0070C0DE).

Precondition, not a flow: with renderer, camera and scene non-null, a null culling process
faults (no guard; dereferenced at 0x0070C0DA when arg 4 is 0, always at 0x0070C0F1 or
0x0070C109) (read).
