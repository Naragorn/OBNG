## Purpose

For every entry of the phantom's overlap list (array at this+0x120, count at this+0x124, walked from the last
entry to the first) it asks both shapes for their type (shape vtable +0x08), looks up a function index in the
collision dispatcher's pair table (byte at dispatcher+0x190 + ownType*32 + otherType) and calls the function at
dispatcher+0x998 + index*0x14 with (&this->collidable, other collidable, collision input, collector). The
dispatcher is not world+0x7C here but the first dword of the world's collision input [[this+8]+0x74]+0x00
(read, 0x008ECDD3-0x008ECDDA). The function does not read the tolerance [input+0x08] itself; it passes the
input pointer on. The widened tolerance written by the caller 0x008AD070 at 0x008AD0AC reaches the dispatcher
functions through that pointer only under two conditions (derived, conditional): (1) the caller's phantom vcall
vt+0x34 at 0x008AD0B4 resolves to 0x008ECDD0 (the vtable slot was located in a non-reference local copy, not the
reference binary; unverified, see Identity), and (2) that phantom's [[+8]+0x74] is the same input the caller
widened (unverified). Whether the dispatcher functions read +0x08 is unverified (not followed).

The slot offset +0x998 sits 4 bytes below the slot +0x99C that 0x008ECC60 uses ((index+0x7B)*0x14,
0x008ECC60.md C7) and 4 bytes above +0x994 used by 0x008ECE60 (0x008ECE60.md C7), all at stride 0x14 with the
pair table at +0x190: the same offsets and stride in the object at [[world+0x74]+0] (derived). That this is the
same table as 0x008ECC60's depends on [[world+0x74]+0] == [world+0x7C] (C3, unverified). A per-pair function
table of five dwords starting at +0x990 is unverified: only the stride 0x14 and the three consecutive dword
offsets +0x994/+0x998/+0x99C are read; the entry start +0x990 and the slot ordinal come from a recalled Havok
layout (`Agent2FuncTable`, from memory), and the first dword of an entry is unread. That +0x998 means "closest
points" (rather than penetrations) and +0x99C "linear cast" is unverified.

| F2 | count-1 >= 0 as signed (count 1..0x80000000): loop with EDI = count-1 down to 0 | 0x008ECDEE-0x008ECE4C | per entry: two type vcalls, one dispatcher call |
| F3 | loop back while EDI after `DEC` is not negative (`JNS`) | 0x008ECE4B / 0x008ECE4C | back to 0x008ECDF5 (reloads this into ECX); otherwise falls through to 0x008ECE4E |

Edge: the count is read once (0x008ECDDD), the data pointer every iteration (0x008ECE00); the slot address ESI is
computed before the two type vcalls (0x008ECE09) and dereferenced after them (0x008ECE39). When a callee changed
the list during the loop, this function would use the old count and the old slot address (derived; no callee
here is known to do so, unverified). Test flows: empty list (F1), one entry (F2 once), several entries in
reverse order (F2+F3), pair-table index selecting different slots.

## Could two threads run this at once for two different phantoms?

The function's own instructions write only their stack and read the phantom, the world's collision input, the
dispatcher's tables and the other collidables (read). On that evidence alone, two calls for two different
phantoms do not conflict (derived from C9, C10). What stands against it:
1. The input it passes is the world's single shared collision input; the caller 0x008AD070 writes its tolerance
   at 0x008AD0AC and restores it at 0x008AD0BB around this call. Two threads in that pair would race on
   [input+0x08]: one thread's restore can shrink the other's widened tolerance while its dispatcher function
   runs (derived from 0x008AD070.md; that the dispatcher functions read +0x08 is unverified).
2. The overlap list +0x120/+0x124: neither 0x008D8370 nor 0x008D83E0 writes it in its own body (read,
   0x008D8370.md claim 10, 0x008D83E0.md). If written on this path, the writes are inside their pair listeners'
   vcalls (vt+0x08 at 0x008D83C9, vt+0x0C at 0x008D8409; derived). Candidate direct writers are 0x008ECF30
   (remove) and 0x008ED2B0 (free) (pseudocode leads, unverified); no appender has been found. The blocker is
   whatever the broad phase's pair listeners call to change +0x120/+0x124; it must not run during the walk.
3. The dispatcher functions, the shape type vcalls and any collector growth are unfollowed; their writes
   (heap, Havok's stack area at 0x00B47900, statics) are unknown.
A parallel version would need a per-thread copy of the collision input with its own tolerance instead of the
shared write-and-restore (derived; not built, map only).
