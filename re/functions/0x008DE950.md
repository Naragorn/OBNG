# 0x008DE950 - phantom broad-phase update (proposal)

Slice: actor-movement. Map only, not rebuilt. Evidence: `re/export/actor-movement/0x008DE950/`
(meta.json, asm.s, data.json, pseudo.c). Callee bodies were read only as pseudocode from
`re/export/rea-all/functions/0x<address>.c`; those claims carry the mark "unverified (pseudocode)" (Up).

Marks: **R** read in the instructions (address given), **D** derived (from which R facts),
**U** unverified, **Up** unverified, seen in pseudocode only.

## Purpose

Moves one object (proposed: a phantom) inside the Havok world's broad phase to a new AABB that
the caller passes by pointer, and applies the overlap pairs that this move adds and removes:

1. When the world pointer `[this+0x08]` is null: does nothing (R 0x008DE95D).
2. When the world is locked (`[world+0x88] + [world+0x8C] != 0`): builds a 3-field record
   `{type byte 0x11, this, aabb pointer}` on its stack and hands it to 0x00898820 (proposed: queue a
   pending world operation), then returns (R 0x008DE963-0x008DE992).
3. Otherwise: increments `[world+0x88]`, takes two scratch arrays of 8-byte entries (capacity
   `[world+0x2A8]` each) from the thread's stack allocator, calls the broad phase's vfunc +0x18 on
   `[world+0x64]` with this object's handle `this+0x28`, the AABB, count 1 and the two arrays
   (proposed: added pairs, removed pairs). When either array is non-empty it removes duplicates
   (0x008D84F0), removes the "removed" pairs (0x008D83E0) and adds the "added" pairs (0x008D8370)
   through the dispatcher `[world+0x68]`, then compacts the array at `this+0x50` (0x008DE4E0).
   Around the broad-phase call it brackets with `[world+0x08]` vfuncs +0x24/+0x28. Then it
   decrements `[world+0x88]` and, when it reaches 0 with pending work (`[world+0x84] != 0`) and
   byte `[world+0x90] == 0`, calls 0x00899210 (proposed: execute pending operations). Finally it
   returns both scratch blocks to the stack allocator (LIFO) and frees any array that a callee grew
   onto the heap (R, sites below).

It reads no clock itself: the body has no RDTSC, no timer import and no time global (R, whole
asm.s). 0x00899210 writes RDTSC profiling markers into TLS +0x1A4 ("TtPendingOps") (Up).

## Calling convention and parameters

- `__thiscall`: `this` in ECX, copied to ESI at 0x008DE954 (R). ESI is never reloaded, so `this`
  stays live for the whole call (R).
- One stack argument: `[ESP+4]` at entry, a pointer to the AABB (R as a 4-byte value read at
  0x008DE972 and 0x008DEA94 and pushed as a pointer; that it is an AABB is D from the caller
  0x008ECC60, which passes `LEA EDX,[ESP+0x30]` after writing two 16-byte vectors with MOVAPS at
  0x008ECCDC/0x008ECCE1, and from 0x008D8830's case 0x11 copying 0x20 bytes from it (Up)).
- Callee cleans: both exits are `RET 0x4` (R 0x008DE992, 0x008DEBDA).
- Frame: `SUB ESP,0x30`; pushes ESI, EDI, EBX, EBP (EBP popped early at 0x008DEAA9). Returns no
  value (EAX is not set on purpose before either RET; R).
- Clobbers: EAX, ECX, EDX; restores ESI, EDI, EBX, EBP (R).

## Read-and-write list by group

**(a) The object it is called on (`this`, proposed phantom)**
- R `[this+0x08]` (sites in the table). No direct write to `this` in the body (R: no store with base ESI).
- `this+0x28` handed to the broad phase as the object's handle; whatever the broad phase writes into
  it is U (vt+0x18 not followed).
- `this+0x50` array compacted by 0x008DE4E0: its size and elements written (Up).
- Locked path: 0x008D8830 increments a 16-bit count at `this+6` when `this+4` is non-zero (proposal:
  a reference count) (Up).

**(b) Other actors or references**
- None touched directly (R). The pair callbacks reached through the dispatcher (0x008D83E0 vt+0x0C,
  0x008D8370 vt+0x08 on agents chosen by the two collidables' type bytes at +4) operate on the other
  collidable of each pair (Up); which objects those belong to is U.

**(c) The Havok world, its bodies, phantoms and broad phase**
- W `[world+0x88]` at 0x008DE9A2 (+1) and 0x008DEB15 (-1): balanced on the main path (R); not
  touched on F1/F2 (R). Not atomic: the check (0x008DE963-0x008DE970) and the increment
  (0x008DE995-0x008DE9A2) are separate plain instructions, and the DEC has no LOCK prefix (R).
- R `[world+0x8C]`, `[world+0x84]`, byte `[world+0x90]`, `[world+0x2A8]`, `[world+0x78]` (R).
- `[world+0x08]` vt+0x24 then vt+0x28: called once each on the main path, a balanced bracket (R
  that both are called once; what they do U).
- Broad phase `[world+0x64]` vt+0x18 (0x008DEAA0): lasting change of the broad phase's state for
  this object's AABB (U, not followed) and fills A and B (D from the sizes being tested afterwards).
- Dispatcher `[world+0x68]`: removes and adds collision pairs - lasting (Up).
- 0x00899210 (when F9-F11 allow): writes `[world+0x84] = 0` and runs 0x008D8BF0, which drains the
  world's pending operations (Up); 0x008D8BF0 is itself listed as a caller of 0x008DE950 (meta.json),
  so a drained queued operation can re-enter this function (D from meta.json; that the type-0x11
  record is what leads back here is U).
- Locked path: the record is appended to a queue at `[world+0x80]` under a critical section, the
  AABB is copied into a 0x20-byte heap block, `[world+0x84]` is incremented (Up; 0x00898820's
  `MOV ECX,[ECX+0x80]` was seen only in an Oblivion.exe copy whose md5 is not the target's, so U).

**(d) The engine's globals, singletons and shared lists**
- R `[0x00BA9DE4]` `_tls_index` (0x008DE99B; also xOBSE `kTlsIndex`, re/symbols/xobse.csv), R
  FS:[0x2C] (0x008DE9B1), R TLS +0x19C (sites above).
- R `[0x00BA7D9C]` at 0x008DE9D6, 0x008DEA36, 0x008DEB44, 0x008DEB6A, 0x008DEB93, 0x008DEBB9, only
  when TLS +0x19C is null (R). data.json gives its file value as 0 (R); no write to it is in this
  export. It must be non-null at run time only if that fallback is ever taken: a thread with a
  null TLS +0x19C reaching 0x008DE9D6/0x008DEA36 would otherwise fault on `[ECX+0x20]`. Whether it
  is ever set, and whether the fallback is ever taken, is U (settled by a write xref to 0x00BA7D9C
  or a run-time read of it and of TLS +0x19C on the calling threads); what it points to is U.
- W `[mem+0x20]` at 0x008DE9F2, 0x008DEA51, 0x008DEB4D, 0x008DEB9C: per thread when TLS +0x19C is
  set; the shared object `[0x00BA7D9C]` otherwise (R). Balanced in the call: each scratch block is
  given back, LIFO (B restored before A) (R).

**(e) The heap**
- Scratch from the stack allocator (R); overflow through `mem->vt+0x0C` (R call, meaning U).
- 0x008A75D0 frees A/B data with memory class 0x14 (the pushed 0x14 at 0x008DEB75, 0x008DEBC4; R)

## Can two calls on different phantoms overlap in time?

Not safely, on the instructions read here. Every shared structure the call mutates:

| Shared structure | Instruction | Why it conflicts |
|---|---|---|
| `[world+0x88]` | 0x008DE995-0x008DE9A2 (load, INC, store), 0x008DEB15 (DEC mem, no LOCK) | non-atomic read-modify-write; two threads can lose an update (R for the instructions, D for the race) |
| gate `[world+0x88]+[world+0x8C] == 0` | 0x008DE963-0x008DE970 then 0x008DE9A2 | test and set are separate; two threads can both pass and update the broad phase at once (D) |
| broad phase `[world+0x64]` | 0x008DEAA0 | shared per world; its internal writes are U (not followed) |
| dispatcher / agents `[world+0x68]` | 0x008DEAD6, 0x008DEAFA | creates/destroys pair agents in shared tables (Up) |
| pending ops `[world+0x84]`, queue | 0x008DEB31 -> 0x00899210 | drain writes `[world+0x84]` and runs queued operations (Up) |
| `[0x00BA7D9C]+0x20` | 0x008DE9F2, 0x008DEA51, 0x008DEB4D, 0x008DEB9C | only when the thread's TLS +0x19C is null; a plain bump/restore, no lock (R) |

Whether `[world+0x08]` vt+0x24/+0x28 is a mutual-exclusion lock that would serialize the middle
part is U; even if it is, the counter update at 0x008DE9A2 and the gate at 0x008DE963 lie outside
the bracket (R: the bracket starts at 0x008DEA7F, after both).

## Claims

1. `this` is in ECX/ESI, one stack argument (an AABB pointer), `RET 0x4` on both exits - R 0x008DE954, 0x008DE992, 0x008DEBDA; AABB meaning D (caller 0x008ECC60).
2. When `[this+0x08] == 0`, the call returns with no write - R 0x008DE95D.
3. When `[world+0x88] + [world+0x8C] != 0`, nothing in the world is changed by this body; a record {0x11, this, aabb} goes to 0x00898820 - R 0x008DE963-0x008DE992.
4. On the main path `[world+0x88]` is incremented once and decremented once (balanced), without LOCK - R 0x008DE9A2, 0x008DEB15.
5. The two scratch arrays come from the thread's stack allocator TLS +0x19C, or the global `[0x00BA7D9C]` when that slot is null, and are given back LIFO before return - R.
6. The scratch capacity is `[world+0x2A8]` entries of 8 bytes each, byte size `(n*8+0x10) AND ~0xF` - R 0x008DE9AB, 0x008DE9DF-0x008DE9E6.
7. The broad phase `[world+0x64]` vt+0x18 is called with (handle list (stack slot E-0x30 = {this+0x28}), aabb, 1, &A, &B) - R 0x008DEA8A-0x008DEAA0; the first argument is the address of E-0x30 (built at 0x008DEA9B), which holds `this+0x28` (stored at 0x008DEA76), i.e. a pointer to a one-element list of handle pointers, not `&(this+0x28)` (R); the Havok meaning (updateAabbs, added/removed) is U.
8. Pair handling runs only when at least one array is non-empty after that call - R 0x008DEAA3-0x008DEAB2.
9. The world's filter is passed as `[world+0x78] + 8`, or 0 when null - R 0x008DEADE-0x008DEAEA.
10. Pending operations run from inside this call when the lock count returns to 0, `[world+0x84] != 0` and byte `[world+0x90] == 0` - R 0x008DEB15-0x008DEB31; that 0x00899210 runs them is Up.
11. Two calls on different phantoms of the same world are not safe to overlap: the lock counter and its gate are plain non-atomic memory operations - D from claims 3 and 4; the broad phase and dispatcher conflicts are U/Up.
12. The body reads no clock - R (no RDTSC, no timer call in asm.s).
13. Scratch arrays are freed through 0x008A75D0 with class 0x14 only when their capacity's bit 31 is clear - R 0x008DEB58-0x008DEB80, 0x008DEBA7-0x008DEBCF; that a callee clears it by growing the array is U.

## Open questions

- What `[world+0x08]` vt+0x24/+0x28 do: a lock, a multithread check, or a simulation hook? Decides whether the middle part serializes.
- The broad phase's vt+0x18: which function, what it writes in the shared broad-phase structures, and whether it can grow A/B (clearing bit 31).
- What `[world+0x2A8]` holds (capacity of the pair arrays) and whether it changes at run time.
- Whether worker threads have TLS +0x19C set; if not, `[0x00BA7D9C]+0x20` is a shared, unlocked bump pointer.
- The exact semantics of `mem` vt+0x0C/+0x10 and `[mem+0x28]` (the restore path at F13).
- Which queued operation type reaches back into 0x008DE950 through 0x008D8BF0 (the caller list says it does).
- The md5 of the local Oblivion.exe copies (66a6c2ef...) differs from the target build; raw bytes from them were not used as evidence.
